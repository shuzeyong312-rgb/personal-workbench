# 1688 经营指标增量 POC

## 1. 目的与边界

日期：2026-10-09。

后续实测记录见 §9。§2–8 保留此前研究和当时未访问的历史状态，不覆盖历史事实；本次实测修订了“尚无本地浏览器会话就不能启动 POC”的判断。

本轮只评估月成交、上架时间、平台标签三个字段能否进入后续正式 Spec。复用 [1688 销量数据源验证](1688-sales-source-validation.md) 的 5 个 active 商品及其失败证据；不访问平台、不改数据库、Collector、API、Frontend 或正式测试，也不保存或提交凭据、Cookie、Token、headers 或原始响应。

`Go` 表示字段来源、粒度、口径、稳定性和访问条件已有足够证据，可以进入字段级正式 Spec；`Partial` 表示有真实观察但仍缺关键合同证据；`No-Go` 表示目前没有足够依据进入正式 Spec。`No-Go` 不代表平台没有该字段。

## 2. 本轮核查与环境门槛

- 已阅读协作方式、竞争情报重构计划、竞品分析基准、既有销量来源验证和根目录 `poc_sales_validation.py`。
- 既有 POC 使用本机 Chrome、项目 `.browser-profile` 和已安装扩展，最多从本地 SQLite 只读取 5 个 active 商品，以真实页面响应监听 `mtop.1688.pc.plugin.od.data.query`；脚本只在内存解析响应，不保存完整响应。
- 当前 `.browser-profile` 和扩展目录存在；本机有 Chrome 进程，但没有 9222 CDP 监听会话。无法确认这些进程是否使用 POC 档案，也无法确认登录态。扩展来源/授权条件未在仓库证据中确认。

## 5. 来源与脚本审查结论

1. 既有销量值来自扩展相关的网络响应，而非已验证的 1688 官方公开交易数据源。扩展响应只证明当时捕获到这些原始值；不证明它是权威成交账本、完整覆盖或口径准确。
2. `poc_sales_validation.py` 用页面 URL 选择商品并监听目标响应，但没有校验响应载荷中的 Offer ID 与当前 URL 一致；跨商品归属仍缺直接证据。脚本还会将商品 URL 和 Offer ID 写入终端 JSON 输出。本轮没有运行脚本，因此没有产生这类输出或新响应。
3. 既有报告表明 `totalSales`、`totalOrder` 的语义不同或至少不稳定；`saleQuantityList` 记录稀疏且日期缺口多，不能替代月成交口径，也不能推导每日销量。
4. 竞品基准中的 SaaS 页面列标题（如“月销件数”“上架时间”）是功能展示参考，页面示例数据不是本项目字段来源、接口许可、准确率或覆盖率证据。
5. 本轮没有尝试第三方 SaaS、未授权接口、验证码绕过或登录态读取；不把插件数据直接称为可信交易数据。

## 6. 是否进入正式 Spec

**暂不建议启动经营指标正式 Spec。** 月成交为 Partial，上架时间和平台标签为 No-Go；三者都缺少可复核的当前来源/访问授权与重复观察。该结论只阻塞新经营指标产品化，不影响已有价格、MOQ、SKU 等事实位置工作。

后续若重新开展 POC，先满足以下门槛，再用原有 5 个商品重复采集并覆盖原来 2 个未触发样本：

1. 确认使用的浏览器扩展和数据源有合法授权，且用户提供/确认可用的本机登录会话；不得读取、导出或提交凭据。
2. 对每个响应核验 offerId 与目标页面一致；对未触发、登录、验证、扩展不可用分别记录原因；失败值保持未采集。
3. 对同一商品做至少两次独立观察并覆盖不同时间点；记录原始值、响应时间、重复一致性和字段可见性。重复值只能说明相同观察，不代表成交增长或交易真值。
4. 月成交需有来源定义说明商品/店铺粒度、件数/订单数/代销含义、窗口边界、刷新频率及档位边界；档位在业务允许前始终保留原文，若定义仍不清则不得精确排名。
5. 上架时间需确认其对应的商品事件（首次发布或当前链接发布）和日期精度；标签需取得原始名称、归属粒度、状态有效时间，并证明采集失败不会被解释为标签取消。

上述门槛通过后再逐字段重判 Go/Partial/No-Go；不要求三个字段捆绑通过，也不为未通过字段先建数据库、API 或 UI。

### 12.3 Chrome 技术边界与许可

依据当日核对的 Chrome 官方文档：[activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

- 用户点击扩展 action 可授予当前标签页临时权限；同源后续导航可能继续保有权限，跨源导航/关闭标签页会撤销。因此“有权限”不等于允许后台采集，POC 必须自身只在明确点击时读取一次。
- Manifest V3 仅申请 `activeTab`、`scripting`，通过 action popup 中的采集按钮向当前 tab 的 **main frame** 单次 `executeScript` 注入，使用默认 `ISOLATED` world。默认隔离环境与页面共享 DOM，可读取普通页面 DOM；不能因此读取采购助手的后台变量/其他扩展私有上下文。
- 不声明 `host_permissions`、`content_scripts`、后台 worker、`tabs`、`cookies`、`webRequest`、`debugger`、`storage` 或 `<all_urls>`，不设后台事件/轮询。临时授权足以取得当前 tab 必要信息；只用它获取当前 tab，不枚举其他标签页。
- POC 先支持 main frame 的普通可见 DOM。若助手区域位于 open Shadow DOM，先记录结构限制，本期不添加递归穿透；closed Shadow DOM、跨源 iframe、canvas/图片文字、扩展自有 UI 或 Chrome 限制页面均不得强行读取。`activeTab` 不是全 frame/跨 origin 授权；不扩大权限或切换 MAIN world 绕过限制。区域无法直接读取，返回 source_unavailable 与具体已知原因；结构未知时只记 region_not_resolved。
- “可见”需有布局尺寸、display/visibility 非隐藏、非透明，并处于当前视口；不自动滚动、展开、悬停或点击页面。不读取完整 body/HTML、隐藏字段、Cookies、localStorage/sessionStorage 或账号信息。数据由 allowlist 字段节点返回，来源证据只保留字段标签和值，不返回父级完整文本。
- 读取动作不导航、不刷新、不 fetch/XHR、不监听或重放采购助手请求、不重试。页面与采购助手自身可能继续正常发请求；POC 不能保证浏览器整体零请求，只能保证读取工具不主动触发额外商品/数据请求。

许可核查：本轮仅检索公开索引，未访问商品页面。官方 [1688网站法律声明](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_b2b/suit_bu1_b2b201802011532_36855.html) 的检索摘要包含对未经许可通过自动化程序等获取/使用站内内容的限制；该限制不能因为“用户点击”“只读 DOM”“本地保存”自动视为豁免。官方 [采购助手个人信息处理规则](https://terms.alicdn.com/legal-agreement/terms/privacy_policy_simple/20241022163836165/20241022163836165.html) 是个人信息处理说明，不是本 POC 的数据再利用授权。

**当前许可结论：未取得适用于本账号、当前采购助手版本、本地 DOM 提取/保存用途的明确许可证据；暂不放行真实注入。** 需核对适用的完整服务条款及平台/数据提供方允许的访问与保存范围；用户对实验的确认与平台数据使用许可是两个条件。以上是许可证据缺口记录，不是完整法律适用结论。可继续本地离线设计与 Fixture 测试，不能把浏览器技术可行性写成已获平台授权。

### 12.4 最小 POC 设计与状态合同

拟定文件范围：`experiments/1688-current-page-poc/` 下 Manifest、popup HTML/JS、单次 DOM reader 和解析核心及 Fixture/test；不新增依赖、服务、数据库、业务接口、正式 Frontend 接入、批量/定时能力。**本轮实际只新增离线 `parser.mjs`、`fixtures.json`、`parser.test.mjs`；其余扩展文件待方案/许可确认后实现。**

用户流程：用户正常打开已经可见的商品 → 点击扩展 → popup 显示当前 Offer → 用户点击采集 → 一次 DOM 读取 → popup 显示逐字段原文、状态、来源、采集时间和缺口。POC 最小版本只在当前 popup 内存展示，不自动保存/覆盖历史文件，不写 Chrome storage，不接本地工具 API。用户可手动复制 allowlist JSON；自动导出、跨会话保存与业务导入不属于本期。

身份：从精确 `https://detail.1688.com/offer/<digits>.html` URL 提取 Offer；拒绝外站、相似域名、路径尾部混入、非 HTTPS 与 userinfo。点击时的 Offer 作为 expected ID；注入执行前后再次核对当前 URL，结果返回后还核对原 tab 的 Offer。任一变化返回 read_failed/offer_identity_mismatch，不归给原 Offer。不导出 query/hash，只输出 canonical URL。DOM 字段绑定到该页面 Offer 的上下文，不凭 URL 宣称字段业务粒度/销量窗口已确认。

时间：DOM 快照读取时一次生成带时区的 `observed_at`，同一次所有字段共享该时间；记录来源是本机浏览器时钟。输出 UI 用 Asia/Shanghai，原始 ISO 时间保留 offset。popup 点击时间不能替代 DOM 采集时间；离线重放保留历史样本时间，不伪装为新采集。

| 状态 | 判定 | 有效值处理 |
|---|---|---|
| observed | 身份/来源通过，已显示的非占位原文读出；`0` 也是原文，不推导销量精确性 | 仅更新同 Offer、同字段、同来源，且时间不早于原值的 popup 内存有效值 |
| placeholder | 正确来源明确显示 `-`/`—`/`--`/暂无等 | 保留此次占位证据；不清空上次有效值 |
| verification_required | 可见验证文案/验证框等正面证据 | 不解析底层可能陈旧的业务值；全部字段标验证，停止、不代操作；保留上次有效值 |
| source_unavailable | 区域/标签当前不可见、未解析到、结构不可访问、加载中 | raw_value=null，记录已知限制；不推断无数据/无标签；保留上次有效值 |
| read_failed | 来源可识别但邻接值无法读取、注入抛错、身份变化、采集时间不合法 | raw_value=null 或空字段失败结果；保留上次有效值 |

每个字段保留 `offer_id/status/raw_value/source/observed_at/reason`；标签另附归属尚未核验标记。结果含 partial 标志；summary observed 只表示至少一个字段成功，不代表全部经营字段就绪。popup 区分“本次观察”与“此前有效值”并保留各自时间，避免把旧值呈现为本次成功。多个顶部候选、混入分销代发或来源歧义时停止该来源，不选第一个凑数。验证检测只看已显示元素，隐藏/历史验证文本不触发；无验证命中也不能证明不存在尚不可见的验证。

### 12.6 确认后真实实验的最小验收标准

2. **真实 DOM 正样本**：用户将屏幕八项助手字段逐一与输出对照；收藏与标签分别校对来源。不存在的标签标不可用。只保存 allowlist 原文/状态/时间与脱敏局部证据，不记录账号、完整 HTML/URL 参数/网络响应。
3. **权限与结构**：仅 activeTab+scripting；普通 DOM 读不到采购助手时记录 source_unavailable 和结构原因，实验到此结束，不增权限/读取私有数据。真实样本通过后再收入 Fixture，保留来源与人工确认时间，不补造未显示值。
4. **请求边界**：静态检查无导航、刷新、fetch/XHR、控件触发、定时器和请求重放；用户观察一次点击前后的当前页面是否发生由工具触发的导航/刷新/数据请求。自然后台请求单列，不能用“浏览器有请求”证明工具违规或用代码检查替代真实验证。不导出 HAR 或请求凭据。
5. **失败保留**：验证/占位/源不可用/读失败由离线 Fixture覆盖，不主动制造平台验证。真实页自然出现验证则返回 verification_required 并停止；人工处理由用户决定，工具不参与。失败不能替换当前 popup 内存中的有效值，也无能力覆盖正式数据库。

本期通过标准是**当前页面原值、身份、来源、时间与错误保留行为**，不是经营指标准确率、窗口语义、覆盖率或无人值守监控。无需再次证明如何触发安全验证。主要剩余风险：适用许可未核验、恢复后的真实 DOM/数值样本未取得、页面结构变化/不可访问、标签商品归属未确认，以及原页面自身可能继续请求。当前方案技术可行但真实 Gate 尚未完成。
