# 竞品组分析动态优先工作区 V1

> 状态：草稿，待独立 Spec Review；未冻结，不授权实施。
> 日期：2026-10-22。
> 依据：用户于 2026-10-21 至 2026-10-22 参与需求探索并确认本方向。

## Problem Statement

竞品监控大屏和竞品组分析已有关注等级、商品横向比较、动态事件及证据入口，但主界面仍展示较多身份文字；一般变化与重要变化混在同一组列表；组分析先展示长商品对比表，重要动态在页面下方。用户需要滚动到表格之后，才能查看近期变化。动态中一个商品同类的多个 SKU 变化又逐条占行，增加重复感。

用户希望先看最近值得关注的组和竞品动作，并能在同一组分析工作区里切换动态与商品对比；仍可使用我方定位、商品搜索、重要变化筛选和单条事件证据。

## Product Goal

减少找到重要组变化和核对变化证据所需的阅读与滚动，同时保留完整商品对比和原始变化事实。

页面职责继续为：

- **竞品监控大屏**：从今日有变化的组中先识别优先查看对象。
- **竞品组分析**：先查看近期重要动作，必要时切换到商品对比核验。
- **单品详情 / 变化证据**：查看单个商品事实和每条原始事件的证据。

## User Scenarios

1. 用户打开大屏，在前五个重点关注或建议查看组中找到目标组；一般变化不占用主列表首屏。
2. 用户进入组分析，默认查看今日重点动态；同一商品同一轮采集中多个 SKU 的同类变化显示为一条摘要，展开核对每个 SKU 和对应证据。
3. 用户切换到商品对比，搜索商品或店铺、只看有重点变化的 Offer，或定位我方商品；这些操作仍只作用于对比视图。

## Product Contract

### 0. 继承合同与局部覆盖

本 Spec 经 Review / Freeze 后，仅在以下范围覆盖既有 Spec；未列出的事实、API、错误、时间和导航规则继续继承：

- 覆盖 `group-first-dashboard-v1.md` 中组项必须展示 own product 简要身份的展示要求：不再在组名下显示商品名和店铺名。Attention 规则、Reason、KPI、资格及排序不变。
- 覆盖 `group-competitive-position-v1.md` 的比较区与动态区上下排列，以及“视觉分组不能合并 ChangeEvent”的展示限制：允许本 Spec 定义的无损摘要分组；所有原始 ChangeEvent 与证据仍逐条保留。
- 覆盖 `group-detail-v1.md` 中按纵向区块依次呈现比较与动态的页面结构。比较事实、筛选语义、事件分类、时间范围、游标、错误处理和单品证据合同不变。

### 1. 大屏关注列表

- 继续消费现有 Backend Group Attention read model；Dashboard KPI、采集状态、趋势和组导航保持原语义。
- 主区只展示“重点关注”和“建议查看”组。最多默认展示按 Backend 既有顺序排列的前 5 组；沿用现有展开 / 收起交互查看其余重点及建议组。
- “一般变化”组放在独立的折叠区，默认收起；展开后保留 Backend 返回顺序，不与重点 / 建议组混排。
- 显示数量需区分重点 / 建议组与一般变化组，不能让用户误以为折叠区组已从数据中移除。无重点 / 建议组但存在一般变化时，主区应清楚说明，并可展开一般变化。
- 组名下方不再展示我方商品名称或店铺名称。组项其余现有的等级、变化竞品数、Reason、最近变化时间和“进入组分析”保留。
- Frontend 只按 `attention_level` 分区并保留组内 Backend 顺序；不得计算或重排 Attention、改变等级或新增阈值。

### 2. 组分析工作区

- 在现有组分析主工作区提供两个同级视图：“竞品动态”和“商品对比”。默认选中“竞品动态”，用户无需先滚过完整商品比较表才能看到动态。
- 两个视图占用同一主内容位置，不把完整商品对比表和完整动态列表上下堆叠。页面仍使用现有自然滚动，不新增嵌套纵向滚动容器。
- “商品对比”保留当前竞争总览、经营表现、口碑履约子视图及其现有列、排序、摘要和商品速览语义。
- “定位我方”、店铺 / 商品 / Offer 搜索、“仅看重要变化”只出现在并只作用于“商品对比”视图；其现有筛选组合和“我方被筛选隐藏时提示清除筛选并定位”的行为继续有效。
- “竞品动态”保留当前全组范围、今日 / 近 7 天 / 近 30 天和重点 / 全部筛选；默认今日、重点。范围切换、加载失败、重试、游标继续加载和证据打开沿用现有语义。
- “重点”继续采用当前事件类型定义：商品或 SKU 价格调整、MOQ 调整、SKU 新增或移除；价格幅度不另设门槛。库存、上下架、标题、主图等事件仍可通过“全部”查看。
- 标签可用键盘操作，并以可访问名称和选中状态暴露当前视图；折叠的一般变化区也须能通过键盘展开和收起。沿用 `docs/ui-system.md` 的现有视觉基线。

### 3. 动态摘要与原始事件

- 同一竞品 Offer、同一轮采集、同一变化类型的多个事件，在动态主列表中合并为一条摘要。商品级与 SKU 级事件若属于同一组，摘要应说明商品级变化以及涉及的 SKU 数；只含 SKU 级事件时可显示如“4 个 SKU 降价”。
- 同一组内的 SKU 数按不同 `entity_key` 计数，不按事件行数或重复事件数冒充 SKU 数。方向由现有 `change_type` 决定。
- 不同变化类型分别展示，例如降价和 SKU 新增不合成一个无明确含义的动作。
- 摘要不得把不同 SKU 的前值、后值或幅度拼成单一价格；有差异的原值逐项保留在展开内容。
- 展开摘要后，可查看组内每条原始变化的商品 / SKU 名称、原始前值与后值、检测时间及独立“变化证据”入口。证据内容继续关联原事件 ID、Snapshot ID 与 Collection Run ID。
- 只在现有事件字段能证明同一采集关系时合并（例如共享非空 `collection_run_id` 或对应同一 Snapshot）；关联不明确的事件保持分开，不按时间接近或文案相似推断为同一次动作。
- 合并仅是只读展示摘要，不合并、删除、改写或去重 `ChangeEvent`；不改变 Attention、事件分类、价格变化方向或完整事件总数。
- 分页继续加载时，新事件追加到已显示的同一摘要并更新数量，不另建重复摘要；加载过程中显示的数量按当前已加载事件逐步更新，全部加载完成后才代表当前窗口完整数量。实现沿用当前有界读取与重试语义，不新增持久化表或历史摘要事实。若现有游标无法可靠支持该行为，应在实施前提出最小契约调整并复核 Spec，不可静默近似合并。

## Business Rules and Boundaries

- Group Attention 继续由 Backend 生成并排序；本 Spec 只改变大屏的展示分区与默认折叠。
- 关注排序仍按现有稳定顺序：等级、内部优先级、强事件等级、变化竞品数、最近变化时间及稳定兜底。最近时间不改成首要排序规则。
- Group Detail 的比较、排名、资格、快照时间、当前成员范围、未知值、错误状态和详情导航继续继承 `group-competitive-position-v1.md` 与其仍有效的 `group-detail-v1.md` 条款；本 Spec 只覆盖本文件明确列出的页面展示行为。
- “仅看重要变化”与动态区的“重点”使用既有事件类型定义；搜索只筛商品对比结果，不改变动态范围或组内排名。
- 不推断销量、增长、风险或竞争力；不新增阈值、评分、提醒、保存查询或用户偏好。
- 不新增数据库表 / 字段 / Migration、采集行为、持久化摘要、依赖或导航框架。是否需要最小只读 Backend 响应扩展仅用于可靠分页摘要，须在实施时以证据决定。

## Loading, Empty, and Error States

- Attention 加载、失败和空结果继续区分；动态与商品对比视图互不覆盖对方的已加载状态。
- 无重点 / 建议组时，不显示虚假的关注组；若一般变化存在，显示折叠入口及数量。
- 动态重点为空时提示可切换“全部”；全部为空显示当前窗口无变化。
- 事件摘要详情加载或证据打开失败时，保留已显示摘要和原始页面状态，提供现有重试 / 重新加载路径；不得把读取失败当作无变化。
- 切换组、窗口或动态筛选时，沿用现有过期响应保护、窗口上下文和游标校验；旧响应不得混入当前摘要。

## Acceptance Criteria

### Dashboard

- 组名下方不再重复显示 own product 名称或店铺名。
- 默认最多展示按 Backend 顺序排列的前 5 个“重点关注 / 建议查看”组；其余可展开查看。
- “一般变化”在独立折叠区内，默认收起；组数清楚且顺序稳定。
- 前端分区没有改变等级、理由、KPI、组资格或 Backend 原始顺序。

### Group Detail

- 初次进入默认选择“竞品动态”，首屏不再要求滚过整个商品对比表才能看到重要变化。
- 可切换“商品对比”而不丢失现有搜索、重要变化筛选、Offer 排序、定位我方、隐藏我方提示及商品详情入口。
- 动态默认显示今日重点事件；切换近 7 天 / 近 30 天 / 全部仍使用现有读取和排序语义。
- 同 Offer、同采集、同类型的多 SKU 变化显示为一条摘要；展开显示所有对应原始变化及独立证据入口。
- 不同类型变化分开；不同 SKU 的价格或库存原值不被压成一个虚构值；无可靠关联的事件不合并。
- 继续加载后，新子事件并入已有摘要并更新数量；加载完成前数量只代表已加载事件，加载完成后代表当前窗口完整数量；证据仍指向原始事件。
- 键盘用户能选择两个视图及展开一般变化；选中、折叠状态有清楚的无障碍语义。
- Loading、空、部分数据、失败、重试、范围切换等现有状态与证据边界继续有效。

## Testing Decisions

实现阶段复用现有 Dashboard 的 Vitest / Playwright 覆盖与 `frontend/e2e/group-position.spec.ts` API mock seam，不访问正式数据库或真实 1688 页面。

- Dashboard 覆盖关注 / 建议与一般变化分区、前 5 个及展开顺序、计数、空分区、组名下方身份文字移除。
- Group Detail 覆盖默认动态视图、标签切换、保留现有对比交互和筛选范围、键盘 / aria 状态。
- 动态摘要覆盖 Offer 级与 SKU 级事件、多个 SKU 同类型变化、不同类型拆分、不同值保留、缺失关联不误合并、展开后逐条证据。
- 分页覆盖新子事件并入已有摘要、数量逐步更新及窗口加载完成后的完整数量、继续加载和重试、失败保留原数据、旧响应隔离。
- 不在 Spec 阶段新增或运行测试；本节仅为未来实施验收合同。

## Out of Scope

- 重定义 Group Attention 算法、Reason、等级阈值或组排序。
- 重定义“重点”事件类型、价格幅度门槛、事件检测或历史事实。
- 搜索动态事件、跨视图全局搜索或高级事件筛选。
- 修改商品比较指标、排名、经营数据、商品身份或组成员关系。
- 新增通知、自动决策、销量推断、持久化用户偏好、数据库历史摘要或新页面路由。
- 全局 UI 改版、Figma 设计系统或与本工作区无关的视觉重构。
