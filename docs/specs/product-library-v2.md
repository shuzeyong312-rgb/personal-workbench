## 1. 问题与目标

用户收到的报价资料格式各异，常见内容包括产品型号/名称、技术参数、卖点、颜色、容量/功能版本、出厂价/批发价/代发价/平台控价、MOQ、税费与运费口径、包装物流、配件、认证/专利、售后条款、产品图片及原始资料页码。

以下六款为用户提供的代表性图文资料示例，用于检验常见字段类别与边界，不是完整需求清单、强制逐字段验收集，也不构成后续所有厂家或品类的上限。没有获得原始 PDF/PPT/Excel 文件，故不声称完成原件逐字段核验；正式导入质量仍以真实数据验收为准（见第 14 节）：
- GS008 磁吸暖手宝：出货价与两档零售控价、认证、包装配件。
- DM-82 挂脖风扇：出厂价、阿里控价、C 端控价、售后与运费条件。
- GS-01 手持风扇：风速档位、颜色、尺寸、装箱和重量信息。
- S17 迷你风扇：有图文及技术规格，但没有报价。
- W01 喷雾风扇：不同工作模式下的功率、续航、噪声和风速。
- H8 石墨烯暖手袋：5000mAh/10000mAh 两种容量，各有批发价与代发价、起批及运费条件。

目标：
1. 继续由外部 Codex 将厂家原始资料整理为统一 Excel；工作台不内置 AI/OCR/网页解析。
2. 产品基础资料、技术参数、规格款式、价格条件和来源分别组织，避免把不同价格混成一个“批发价”。
3. 尽量保留厂家原文；缺失值保持未知，冲突值明确提示，不由系统或 Codex 猜测。
4. 兼容现有产品、旧六列表格、产品搜索、客户报价和导入回执。
5. 以小型、可维护的关系模型解决一对多数据，不建设完整 ERP/PIM、供应商 CRM 或 SKU 组合引擎。

## 3. 产品语义与边界

### 3.1 产品与规格

- 产品是一款厂家产品资料主体。
- 颜色、容量、功能或配置不同，但属于同一产品系列时，可关联规格款式；不能仅因为不同颜色就强制建立多个主产品。
- 产品身份按型号 + 名称精确匹配，不因报价来源公司不同而拆成多个主产品。相同型号但名称不同、相同名称但型号不同，均视为不同产品。
- 规格只有在存在明确差异时建立；没有规格信息时不生成虚构规格。
- 参数可保留完整原文，同时可选地整理为参数明细。结构化参数不能替代原文。

### 3.2 厂家与报价来源必须区分

- 保留数据库字段 manufacturer_name，避免破坏旧数据和旧 API；身份索引会通过新迁移调整。界面将其标为“首录资料公司（兼容字段）”，不据此宣称该公司一定是实际生产工厂。
- V2 导入流程允许填写资料归属公司；报价来源公司在来源资料/价格记录中单独记录。
- 如果原件未说明实际生产厂家，不推断或补写。
- 不新增完整供应商档案、联系人、账期或采购订单功能。

### 3.3 身份规则与迁移要求（高风险）

目标身份规则已确定为“型号 + 名称”，不包含厂家/资料归属公司。当前 GitHub 主分支的模型、服务层、迁移 20261020_17 和身份 Spec 仍使用“厂家名称 + 型号 + 名称”，因此 V2 必须纠正实现与文档之间的差异，不能把旧索引当成目标规则。

目标唯一性：
- model 非空：精确唯一键为 (model, name)，不论厂家/资料来源公司是否相同。
- model 为空：同一 name 仍视为相同身份，不论厂家/资料来源公司是否相同。
- 型号、名称按规范化后的原文精确比较；大小写、全半角、标点及参数规格不做自动归并。
- 规格、颜色、价格类型、报价来源均不是主产品身份的一部分。

迁移必须先检查现有数据中跨厂家相同型号+名称的记录，以及无型号同名记录。存在多个历史产品 ID 时，迁移只输出冲突报告（ID、原厂家字段、型号、名称和必要差异）并整体拒绝升级；不得自动合并、删除或挑选一条作为主记录。人工完成数据归并方案并重新备份后，才允许继续迁移。

厂家/资料归属公司字段保留用于兼容旧记录，但不再参与身份匹配。每个报价来源必须进入独立来源记录。价格类型与渠道分开保存，例如 price_type=平台控价、price_channel=阿里平台，避免同一公司同时提供阿里控价与 C 端控价时发生混淆。相同产品从另一家公司导入时，默认新增来源/价格，不覆盖首录公司的主字段或主产品资料。V1 模板仍可上传，但其批次“厂家名称”在来源处理上作为报价/资料来源公司；如果命中已有产品，应通过预览明确选择追加来源、更新主资料或跳过。

### 3.4 价格类型不能混用

价格类型至少支持：
- 出厂价
- 批发价
- 一件代发价
- 定制价
- 平台控价
- 建议零售价
- 零售价
- 其他（必须保留原文说明）

价格记录还应保留币种、适用规格、起订量及单位、税费口径、运费口径、运费金额、定制条件、报价日期、来源及原文摘录。控价不得自动用作采购成本或客户报价输入。

未知价格必须为空，不得变成 0。明确零价才允许金额为 0。不得从自由文本备注中自动推算结构化价格。

## 4. 目标数据模型

采用现有主表加规格、来源、价格三张关联表；不引入通用动态字段平台。

### 4.1 library_products（保留现有主表）

保留现有字段和原始值（运行期镜像规则见 4.5）：
- id、manufacturer_name、model、name
- manufacturer_name 在 V2 作为历史/首录资料归属字段兼容保留，不参与身份匹配，也不自动代表经核实的实际生产厂家。新产品沿用批次来源公司填充该兼容字段；后续追加其他来源时不覆盖。实际厂家仅记录在来源资料中明确标注的字段。
- parameters、selling_points
- wholesale_price_cents、price_note
- created_at、updated_at、version

新增：
- category：可空的产品分类文本，不强制建立复杂分类树。
- structured_attributes：可空 JSON，用于灵活参数明细；每项至少包含 group、name、value、unit、condition、source_id、source_excerpt、review_status（confirmed/needs_review）。原始参数文本仍保存于 parameters。建议分组包括“基本规格、供电/电池、性能/模式、材质、包装物流、配件清单、认证/专利、售后政策、交易条件、其他”。这些是数据分组，不为每个品类建立独立数据库列。

目标身份键为型号 + 名称。当前数据库索引尚未符合目标，必须通过新迁移改为型号/名称精确唯一性，并同步手动新增/编辑、V1/V2 导入、重复预览和并发检查。厂家字段保留但不参与身份匹配。

### 4.2 library_product_variants（规格款式）

最少字段：
- id、product_id（外键）
- variant_code（可空的厂家规格/SKU 编码）
- variant_name（必填，如 5000mAh、10000mAh、冰川蓝）
- color（可空）
- structured_attributes（可空 JSON，结构同主产品，保存规格独有参数；不另设含义重叠的 attributes_json）
- notes、created_at、updated_at、version

规格记录必须属于一个产品。没有明确规格的产品不要求创建空规格。规格编码只在同产品内匹配，不得把厂家未提供的 SKU 编码编造出来。

### 4.3 library_product_sources（资料来源）

最少字段：
- id、product_id（外键）
- source_company（可空；报价/资料提供方）
- claimed_manufacturer_name（可空；原件明确标注的生产厂家）
- source_file_name（可空；原始文件名）
- source_page（可空；页码、工作表或区域）
- source_date（可空；原件明确给出的报价/资料日期）
- source_type（quote/catalog/specification/other）
- source_excerpt（可空；支持追溯的原文摘录）
- notes、created_at、updated_at、version

导入时间与原件报价日期必须分开。原件没有日期时 source_date 留空，不得将导入当天伪装成报价日期。V2 初始阶段保存来源元数据和摘录；原始文件二进制及图片附件纳入后续附件阶段，不声称只存文件名就等于保存了原件。

### 4.4 library_product_prices（价格明细）

最少字段：
- id、product_id（外键）、variant_id（可空外键）
- source_id（必填外键，含 legacy 回填来源）
- price_type、price_channel（可空，如阿里平台/C端平台）、amount_text（规范化十进制文本）、currency_code
- price_unit（计价单位，可空）、min_order_quantity、min_order_unit
- tax_mode（unknown/included/excluded）
- freight_mode（unknown/included/excluded/extra/negotiable）
- freight_amount_cents（可空；仅用于人民币运费，其他币种运费保留在 terms_text）
- customization_terms、terms_text、notes、source_excerpt
- quote_date（可空）、is_default_wholesale
- created_at、updated_at、version

价格金额以规范化十进制文本保存，避免将不同币种都假设为“两位小数的分”。V2 结构化记录可保存 ISO 4217 币种代码；CNY 金额最多两位小数，其他币种按原文精度保存。当前人民币客户报价计算只允许 CNY 价格，其他币种不得直接参与计算，也不自动换汇。

每条价格可作用于整个产品（variant_id 为空）或某一规格。起订量与单位必须分开保存；“20 个/箱起批”等完整条件还要保留原文，避免只存一个数字丢失语义。

### 4.5 旧批发价兼容规则

wholesale_price_cents 暂时保留为兼容字段，不再作为所有价格的唯一数据源。

- 迁移时，对旧产品中非空的批发价回填一条产品级、币种 CNY、类型“批发价”、来源标记为 legacy_backfill、默认标记为真的价格记录；不从 price_note 推断其他价格。
- V2 中只有存在唯一且明确的产品级 CNY 默认批发价，金额非空且满足旧字段范围时，才镜像到 wholesale_price_cents。默认标记只允许 price_type=批发价、price_unit=件；出厂价和代发价可显式用于一次报价，但不能冒充默认批发价。
- 如果产品存在多个规格价或多个候选批发价且没有唯一默认项，镜像字段保持 NULL，列表显示“多价格”或“需选择规格”，不得挑最低价/第一条价格。
- 价格明细是唯一权威数据源，wholesale_price_cents 仅单向投影。服务层在同一事务中先执行明确的价格命令，再重算镜像；禁止把读取到的旧镜像反写价格明细。旧入口转换规则见 4.6。
- 产品列表排序/筛选的旧“批发价”语义定义为“默认批发价”，不表示任意一种价格。默认价要求计价单位为“件”；其他单位不折算、不设默认。多规格价产品不能因为没有默认价就被误认为完全没有报价。

### 4.6 旧价格入口与默认价的唯一写入方向

- 新建产品的旧 wholesale_price 或 V2 产品表“默认批发价”非空时，转换成来源明确、price_unit=件的产品级 CNY 批发价，并明确设为默认；没有价格明细时可创建一条，不能只写镜像。若同时提供默认明细，金额、来源、计价单位与条件相同则复用该条，不同则待处理。已有产品不能靠此快捷字段隐含切换默认，必须显式确认价格行 set_default。
- V1 导入命中已有产品时，六列中的批发价先生成本来源的候选价格；append_source 不更换已有默认项，也不将本来源的价格备注写入主产品 price_note。默认项未存在时也必须显式确认设默认，不能以“追加”之名改变旧报价基准。
- 旧 PUT /products/{id} 的 wholesale_price 若与当前镜像相同，视为无价格命令。不同的非空金额只有在唯一产品级 CNY 默认价、且没有规格默认时才可转换成对该价格的显式更新；显示旧/新金额并校验产品 version。多个候选、无默认或规格默认存在时返回 409 default_price_selection_required，要求进入价格明细操作，不猜目标。
- 旧 PUT 的显式 null 只取消产品级默认标记并置空镜像，不删除价格事实；Excel 空价不发出清空/取消默认命令，沿用“空值保留”。产品 price_note 仍是主字段，仅显式 update_main 更新，和每条价格 notes 无自动双向同步。
- 更换默认必须显式提交目标 price_id 和当前产品 version；在同一事务取消旧默认、设置新默认、校验资格及重算镜像。删除默认价格后镜像为 NULL，不能自动选替代项。规格默认存在时所有旧单价格写操作拒绝，需进入详情明确切换默认模式。

### 4.7 数据库完整性和版本合同

- 产品身份沿用 V1 文本规范化（型号/名称 trim、统一换行，空型号变 NULL），采用 BINARY 精确比较；空型号同名只匹配空型号产品，不与有型号同名产品合并。非规范化旧记录拒绝迁移，不静默改名。
- 规格编码非空唯一 (product_id, variant_code)；无编码规格唯一 (product_id, variant_name, COALESCE(color,''))。来源、价格按 6.4 的完整键建立可空值等价的唯一性保护，不能依赖 SQLite 普通 UNIQUE 对 NULL 去重；可用表达式索引，须以隔离 SQLite 测试验证。价格重复键中空值和规范化十进制必须一致比较。
- 价格须有 source_id（legacy 回填也建立来源）；复合外键/等价数据库约束确保 variant_id、source_id 均属于同一 product_id。参数 JSON 的来源及归属由服务层在写事务校验，不允许跨产品引用。
- 每产品最多一个产品级默认，或每规格最多一个规格默认；部分唯一索引保护数量，同一事务服务层防止两种模式共存。CHECK 保护枚举、正 version、非负价格/运费及默认资格；金额精度、长度和有限值由服务层统一校验，不能只信前端。手动 API 修改来源键/规格键后同样重新校验唯一性及所有引用，不能绕过导入约束。
- 任一关联记录新增/修改/删除、参数 JSON 变化或默认变更，均在同一短写事务令所属产品 version 递增一次并更新 updated_at；同事务多行仅递增一次，无变化不递增。关联表 version 初值 1，实际更新才递增；参数以所属产品/规格 version 控制。
- 删除产品时事务内删除其关联资料，历史 committed 回执保持原样；删除规格/来源若仍被价格或参数引用则返回 409 related_record_in_use，不级联丢失价格或参数。先明确改引用/删除依赖再操作。

## 5. V2 Excel 模板契约

保留 V1 模板并继续接受。V2 模板采用独立、严格版本的工作簿；通过产品数据表头和固定工作表组合识别，不依赖文件名猜测版本。混合、未知或不完整结构明确报错。

### 5.1 产品数据（必需）

列顺序固定：
1. 产品临时ID（工作簿内唯一，如 P001）
2. 产品型号
3. 产品名称
4. 产品分类
5. 产品参数原文
6. 产品卖点
7. 默认批发价
8. 价格备注

产品临时ID仅用于关联同一工作簿中的其他表，不作为数据库 ID。同一工作簿内相同型号+名称只允许一条产品数据行；多个来源、规格和价格必须关联到同一个产品临时ID。若产品数据重复，必须在预览中阻止该身份组提交，Codex/用户合并主产品行并重新预览，不能静默跳过第二行及其来源。报价/资料来源公司在上传步骤填写一次，作为本批来源记录的默认值，不在每行重复；资料索引中的来源公司可覆盖该默认值。新产品入库必须至少有一个可追溯的资料来源；如果公司确实未知，保留为待处理行，不得伪造公司名。现有 manufacturer_name 字段保留为兼容的首录厂家/资料归属字段，不参与身份匹配；命中已有产品时不得因为来源公司不同而覆盖该字段。

默认批发价是兼容快捷字段；完整多价格必须进入价格明细。若默认批发价与价格明细中标记的默认批发价冲突，该产品标记为待处理，不自动择一。

### 5.2 参数明细（工作表必需，数据可空）

列顺序固定：
- 产品临时ID
- 规格临时ID（可空，空表示产品级参数）
- 资料临时ID（可空，解析规则同价格明细）
- 参数分组
- 参数名称
- 参数值
- 单位
- 适用条件
- 原文摘录

参数名称、值和来源摘录应尽量保留原件含义。不能确认的数值/单位不要标准化成猜测结果。复杂的模式参数（如 W01 不同模式的功率和续航）应按适用条件分别记录。包装尺寸、装箱数、配件、认证/专利、保修与退换货、税费和运费政策均可使用分组参数记录，不需要为每类产品增加专属列。参数明细最终合并进产品或规格的 structured_attributes JSON；参数值为空但有摘录时保留未知事实（needs_review），名称/归属缺失为行错误。不单独建立参数数据库表；参数原文仍保留在产品 parameters 字段。

### 5.3 规格款式（工作表必需，数据可空）

列顺序固定：
- 规格临时ID（工作簿内唯一）
- 产品临时ID
- 规格名称
- 规格编码
- 颜色/款式
- 规格备注

不把相同参数、相同价格的每个颜色强制拆成独立价格记录；产品级价格可以适用于所有规格。规格独有参数通过参数明细引用规格临时ID。

### 5.4 价格明细（工作表必需，数据可空）

列顺序固定：
- 价格临时ID（工作簿内唯一）
- 产品临时ID
- 规格临时ID（可空）
- 价格类型
- 价格渠道（可空，如阿里平台/C端网络平台）
- 金额
- 币种
- 计价单位
- 起订量
- 起订单位
- 税费口径
- 运费口径
- 运费金额
- 定制条件
- 报价日期
- 资料临时ID（可空）
- 是否默认批发价
- 价格备注
- 原文摘录

价格备注映射 terms_text，原文摘录映射 source_excerpt，定制条件映射 customization_terms；notes 为详情人工补充，导入不自动重写。金额使用明确十进制文本，币种使用 ISO 4217 代码并与金额分开。CNY 金额最多两位小数；其他币种保留原文精度但不参与人民币自动报价。未知金额留空，不得填 0。“面议”“定制另算”等信息放入价格备注/原文摘录，不能伪造成数字。

### 5.5 资料索引（工作表必需，数据可空）

列顺序固定：
- 资料临时ID（工作簿内唯一）
- 产品临时ID
- 报价来源公司
- 原件中标注的生产厂家（可空）
- 原始文件名
- 页码/工作表/区域
- 原件日期
- 资料类型
- 原文摘录
- 备注

一个产品可以有多条来源资料；价格记录通过资料临时ID关联来源。来源公司与资料归属公司不默认相同。来源引用为空时：该产品仅有一条资料索引则关联它；没有资料索引则生成默认来源；存在多条则为待处理，必须修正文件指定引用，禁止自动取第一条。无来源行时，V2 主表原文也完整进入默认来源摘录；命中已有产品选择 use_existing 不覆盖主字段时仍保留输入。默认来源使用上传时的来源公司，source_file_name 留空（原件未知），notes 记录上传的整理工作簿名；不得将整理 Excel 文件名冒充厂家原件名。来源索引另增加“原件中标注的生产厂家”（可空）字段，仅记录原件明确说明的厂家，不据来源公司推断实际生产厂家。原始文件名和页码只表示来源元数据，不能冒充已保存原始文件。

### 5.6 格式识别与字段值域

- V2 必须具有且仅具有“产品数据、参数明细、规格款式、价格明细、资料索引”五张业务表，另可有“填写说明”；关联表即使无数据也保留完整表头。任意缺表、未知业务表、超列、表头不完全相等均拒绝。V1 仍按原六列表头解析并保留原来的忽略非业务表行为；若出现任一 V2 关联表而主表为六列，按混合版本拒绝，不静默丢弃关联数据。V2 内部 template_version 固定 2，身份规则版本固定 4，分别记录在预览/回执。
- 临时 ID 均为文本，trim 后 1～100 字符、同类型内全簿唯一，不能使用数据库 ID；文本字段拒绝数字/布尔/日期自动转文本。公司/型号/名称继承 V1 200 字符上限；分类/规格名/编码/颜色/分组/参数名/单位/条件/渠道/计价单位各最多 200；文件名/页码最多 500；单个 value/excerpt/notes/terms 最多 10000（V1/V2 合成主行来源摘录例外，最多 30000，见 5.5/6.1）；单个产品或规格参数 JSON 序列化 UTF-8 最多 100 KiB；不截断。
- 价格类型固定使用 3.4 的八个中文值；税费固定 unknown/included/excluded，运费固定 unknown/included/excluded/extra/negotiable，资料类型固定 quote/catalog/specification/other，默认标记固定文本 true/false（空为 false）。空税运费为 unknown；币种未知保留 NULL 并标记待核对，不推断 CNY；非空币种为大写 ISO 4217 代码，非空金额且币种未知不得设默认或参与计算。
- 金额可空，非空为非负普通十进制文本（禁止指数/符号/范围/NaN/Infinity），规范化去无意义前导和小数尾零。CNY 范围继承 0～999999999.99、最多两位小数；其他币种最多 30 位有效数字、12 位小数，仅保存不换汇。未知金额记录可保留类型、条件及摘录，不能设默认。运费金额只在币种为 CNY 时解析为整数分，未知币种/非人民币运费必须留在价格备注/摘录，非空结构化运费金额报错。
- 计价单位未知留空并提示，禁止从起订单位推断计价单位。V1 六列和旧手动价格明确继承既有“人民币元/件”兼容合同，V2 必须按原件填写；不把价格 20 元/箱当成 20 元/件。MOQ 可空；非空为正十进制文本，最多 12 位整数、6 位小数，单位必须非空。单位未知时两者留空、完整原文存价格备注，不推断“件”。报价/原件日期使用有效 YYYY-MM-DD 文本，未知留空，不用上传日期替代。
- 空白 Excel 值在增量更新时保留旧值，不用于删除；明确清空只在详情中操作。单元格长度/金额错误是行错误；重复临时 ID、孤儿引用及混合模板为文件结构错误，整文件拒绝，避免不确定地选择引用目标。

### 5.7 填写说明

模板含填写说明，列明字段含义、允许值、缺失/冲突处理和样例。说明表的样例不得被当作真实产品行导入。

## 6. 导入、校验与合并规则

### 6.1 兼容和安全

- V1 六列表头继续可上传，但产品身份匹配必须采用 V2 目标规则（型号 + 名称），不能保留旧的厂家分区去重逻辑。
- V1 文件的厂家名称作为该批次的来源公司；对于新产品，可继续写入旧 manufacturer_name 兼容字段。若型号+名称已存在且本批来源尚未记录，默认提供“追加来源/价格”操作；该操作只追加或更新来源/价格，不覆盖已有主资料。若来源及价格均已精确存在，则默认跳过。
- V1 每条有效产品行的六列原文（含不同的新参数/卖点/备注）以带字段名的来源摘录完整保存，即使 append_source 不更新主资料也不丢输入；最多 30000 字符的合成来源摘录用于容纳合法主产品行，其他普通摘录上限仍见 5.6。重复上传同样六列精确 reuse；同来源材料发生变化保留新来源，不覆盖旧摘录。V1 未说明原件文件名/日期时保持未知。
- V2 使用独立解析分支；不得静默把 V2 多价格数据塞进 V1 的 price_note。
- 延续现有 .xlsx、文件大小、OOXML/ZIP 安全、公式拒绝、隐藏行列/合并单元格检查。所有业务表的公式单元格均拒绝，不能使用缓存公式结果。
- 延续 1000 个产品主记录的现有限额；关联表增加明确的总行数上限，参数、规格、价格和来源四表合计最多 5000 个物理数据行（第 2 行起累计，中间空行占额度，纯样式尾部不占），仍受现有 5 MiB 上传与 50 MiB 解压限制。
- 拒绝未知工作表、未知列、重复临时 ID、孤儿引用、跨产品错误规格引用、价格引用不存在的来源，以及无法识别的模板版本。
- 预览阶段不得写入产品、规格、价格或来源数据；只允许写入导入凭据。

### 6.2 产品身份

主产品身份固定为 (model, name)，厂家字段不参与匹配。非空型号使用唯一索引 (model, name) WHERE model IS NOT NULL；无型号使用唯一索引 (name) WHERE model IS NULL。服务层、手动 CRUD、V1/V2 导入、文件内重复、并发检查和回执基线必须采用相同规则；不允许只改索引而保留旧的按厂家筛选身份逻辑。禁止模糊匹配。

### 6.3 关联数据校验

- 每条参数、规格、价格和资料索引必须引用存在的产品临时ID。
- 规格临时ID必须唯一；价格引用的规格必须属于同一个产品。
- 价格类型、币种、税费/运费口径使用允许值；其他类型必须明确选择“其他”并保留原文。
- 规格、价格和来源的格式错误必须显示工作表名、Excel 行号、字段和原因。结构性引用错误按 5.6 整文件拒绝；其余字段错误保留在行预览中。
- 关联数据有错误时不得静默丢弃。预览中逐项标记；用户可跳过错误关联行或修正文件重新预览。所有跳过项必须出现在最终回执中。
- skip_product 表示放弃整个产品组，其关联行一并跳过；use_existing 表示复用主产品、不改主字段，关联行仍可独立决策。append_source 是 use_existing 下仅写来源/价格的受限计划，不等于 skip_product（详见 6.6）。
- 参数语义键为归属产品/规格 + 分组 + 名称 + 适用条件 + 单位；事实记录键再加 source_id。不同来源的值并存，同键同来源不同值保留为 needs_review 候选（事实去重键另含规范化 value 与 source_excerpt，重复导入同一冲突值不再次追加），不覆盖旧值；冲突未确认前不作为单一权威值展示。预览保留全部值、摘录和行号；缺少参数行不删除旧参数。
- 缺少某个工作表的业务数据不代表删除已有记录；导入是增量合并，不做“缺席即删除”。

### 6.4 关联记录匹配

- 规格有编码时以 (product_id, variant_code) 精确匹配；无编码时以 (product_id, variant_name, color) 精确匹配，NULL 颜色以空值参与。可变参数不得进入身份键，否则修改容量说明会误新增规格。有编码/无编码两类不自动互相匹配或补编码；显示候选，用户在详情核对后操作。相同键内容不同必须 update 并展示差异，不可按行顺序覆盖。
- 来源记录精确键为 (product_id, source_company, source_file_name, source_page, source_date, source_type, source_excerpt)，可空项按空值相等；普通文本仅 trim/统一换行，公司折叠空白，均区分大小写。完整摘录参与比较（摘要只供索引，命中后比原文），不同摘录并存。键不同视为新来源，不自动改旧来源身份；完全相同且备注/标注厂家无变化则 reuse（无依赖时也可 skip）。
- 价格候选按产品、规格、价格类型、价格渠道、币种、计价单位、来源、报价日期、起订数量/单位和定制条件匹配。若价格行未填报价日期但来源资料有明确日期，可继承来源日期；两处日期均有值但不一致时该价格为待处理，只能跳过或修正重预览，不静默覆盖。税费/运费口径与金额属于可比较字段，变化时展示差异并由用户决定更新；不同来源或不同报价日期的记录可以并存。
- 默认批发价规则：可以有一条产品级默认批发价（适用于所有规格），或为各规格分别指定默认批发价；两种方式不能同时使用。每个规格最多一条默认批发价。出现多个/冲突默认候选必须在预览中解决，不能自动择一。
- 不根据最低价、最新导入时间或 Excel 行顺序自动覆盖价格。
- 没有足够信息唯一识别已有规格/价格/来源时，默认跳过并要求人工确认；不做模糊匹配或 AI 合并。
- 不因一次导入缺少旧关联行而删除已有规格、价格、来源。删除只能在产品详情中明确操作并二次确认。

### 6.5 事务与回执

复用当前 LibraryImport 的服务端凭据、30 分钟 ready 期限、幂等回执和原子写事务。append_source 不改主业务字段，但仍按 4.7 递增主产品 version/更新时间，使旧报价快照失效。当前 identity_rule_version 为 3；V2 必须递增身份/解析规则版本，不能复用旧 ready 预览。基线摘要必须包含按型号+名称命中的产品及其规格、价格、来源的稳定排序快照，不能按厂家隔离，也不能只检查主产品表。

- 提交前再次校验基线、版本和全部决策。
- 产品、规格、价格、来源及 committed 回执在同一事务写入。
- 任意数据库写入失败必须整体回滚，不能只保存主产品而丢失关联价格。
- 网络不确定时先查询原 import_id；不得自动重复上传。
- V2 发布后，旧 ready 预览因解析/身份规则版本不一致而要求重新预览；旧 committed 回执仍可查询/幂等重放。
- 同一产品不能被同一批次的多个关联行重复更新成相互冲突的结果。
- V2 决策标识必须使用“工作表名 + 原始 Excel 行号 + 记录类型/临时ID”，不能只用行号，因为不同工作表会重复行号。产品主记录与每条参数明细、规格、价格、来源记录均展示独立的新增/更新/追加来源/跳过/错误状态；更新必须携带目标数据库 ID 与 version。参数明细最终合并进产品/规格 JSON，但审核仍保留原始工作表行号。仅 skip_product 强制关联记录一并跳过；use_existing 不触发级联跳过。对已有产品，append_source 只能增加或更新明确来源下的来源/价格记录，不得改写产品主字段。

### 6.6 决策、依赖和重复的确定规则

- 产品计划明确区分 insert（新产品）、update_main（明确更新主字段）、use_existing（保留主字段但处理关联数据）、append_source（use_existing 的来源/价格受限模式）、skip_product（整组跳过）。已有产品默认 use_existing；新增来源/价格默认生成追加候选但需确认，主字段不同只展示差异，绝不隐含更新。纯重复且无新增关联内容默认 skip_product。
- append_source 只允许来源及其价格 insert/update/skip；如价格需要不存在的规格，提示改用 use_existing 并逐条确认新增规格，不能偷偷创建规格或写参数。update_main 继承非空替换、空值保留，不修改身份或首录公司；改身份通过手动编辑并检查全局唯一性。
- 每条关联行允许 insert/update/reuse/skip（reuse 只用于精确存在且内容无变化的记录，不写数据库）；invalid 只能 skip。use_existing、append_source 和 update_main 必须携带主产品目标 ID/version；关联 update/reuse 携带所属目标 ID/version，参数使用所属 JSON 容器版本及预览键。客户端不得注入预览以外的目标或字段。
- 同一工作簿完整键相同且内容相同的关联行，第一条作为候选，其余显示 duplicate 并仅允许 skip；同键内容冲突则全部列出冲突、禁止写该键，必须修正文件重预览或全部跳过。参数冲突例外：可显式 insert 为 needs_review 事实，原文和值一并保留，不设权威值。同批不允许两行 update 同一个数据库记录。
- 先验证完整计划和依赖图，再按产品→来源/规格→参数/价格顺序在同一事务执行。某来源/规格行 skip 后，引用它的新增行只能 skip；如果该行已精确匹配现有记录，可改为 reuse 该目标，仍校验 ID/version。不能将“跳过未写入的临时 ID”当作可引用记录。主产品重复组不能通过选择一行绕过，须全部跳过或修正文件。
- 基线在同一读取事务包含本批所有身份的存在/不存在及其完整关联快照；确认 BEGIN IMMEDIATE 后先重算，新增竞争产品（含无型号）、关联新增/删除、默认/来源变化均使整批 409 preview_stale。对规范化、日期继承、默认解析、跳过依赖后的最终计划做稳定排序摘要；请求字段完整、每行恰有一个决策，少项/多项/重复/非法目标 422 invalid_decisions。set_default 仅价格行可用、布尔值，省略表示不改变既有默认；已有产品的新增默认必须显式 true，纳入摘要。产品级和规格级切换须显式确认全部受影响默认项，不由单行隐式取消其他规格默认。
- committed 回执保留 template_version、identity_rule_version、各表/产品组计数、每行稳定标识、目标 ID、outcome、reason_code、错误/冲突和全部跳过项；合成的默认来源/兼容价格使用服务端稳定派生标识并注明来源产品行。计数区分产品和关联行，不把四条价格误算成四款产品。
- 历史 committed 先按其原规则版本解析原决策和摘要再幂等返回，不能先套 V2 决策解析器拒绝旧请求；缺版本及版本 2/3 均有兼容分支。历史 ready GET/confirm 均 409 preview_rule_changed。同凭据同决策并发只提交一次；不同决策 409 idempotency_conflict，SQLite busy 503 database_busy，写/commit 失败 rollback 后原 ready 可重试。

## 7. 产品详情与客户报价

### 7.1 产品详情

在现有产品库页面中扩展详情区，不另建导航或通用状态系统。建议分区：
- 基础信息
- 技术参数与卖点
- 规格款式
- 价格明细
- 包装/配件/认证/售后（以参数分组和原文保存，不建立每个品类专属字段）
- 资料来源
- 附件（后续阶段）

列表显示型号/名称、来源公司摘要、默认批发价状态和更新时间。公司筛选应按关联来源记录查询，旧 manufacturer_name 仅作为没有来源记录时的兼容回退。价格状态区分“有默认批发价”“多价格/需选规格”“无报价”，不能把控价算作已有采购价。

### 7.2 客户报价兼容

- 现有只有一个批发价的产品迁移后应继续可报价，原有金额与客户导出白名单不变。
- 只有一个明确的 CNY 默认批发价时可沿用旧流程。
- 多规格或多价格产品必须在报价预览中明确选择规格与基准价格记录；不自动取最低价。
- 默认自动报价来源只允许唯一、明确的产品级 CNY 默认批发价。出厂价/批发价/代发价只有用户明确选中具体 price_id 后，才可作为本次计算基准；平台控价、建议零售价、零售价、其他及定制价均禁止作为自动计算基准，即使伪造 price_id 也由服务端拒绝。所有自动计算基准必须 price_unit=件；按箱/套等单位未经过明确换算不能参与每件报价，人工最终价仍可用。定制价格先保留原文，条件经确认后须另建明确采购类型记录或人工报最终价，不隐式放开。
- 缺少明确采购价时显示待报价并阻止自动计算；用户可以按现有机制人工填写本次客户报价，但不得修改厂家原始价格。
- 客户 Excel 只导出原有白名单字段和本次确认的客户报价；来源公司、原始报价、平台控价、价格备注、税费/运费内部条件、内部 ID 和来源摘录均不得自动导出。
- 选定规格时，只允许产品级价格或同规格价格；无规格的产品级默认可沿用旧流程，有规格则必须显式选规格。只保留每产品一行客户报价（不扩展为多规格报价单）；型号/名称/参数客户文本必须明确显示所选规格名称及颜色，经预览确认后导出，不让客户收到无规格价格。内部规格 ID、属性 JSON 和来源摘录不拼入客户文本。
- 采购 MOQ 与现有客户统一 MOQ 是两件事，不互相写回。对已选价格的采购 MOQ、单位、定制条件、税运费显示内部核对提示：客户 MOQ 低于采购 MOQ、MOQ 未知/起订单位不明或非件、税运费 unknown 或条件未确认时禁止直接自动计算，需逐产品确认条件（conditions_confirmed_ids）或人工填写最终价。确认不代表系统做单位换算、按箱折价或按 MOQ 推算运费；这类计算不在范围内。
- 客户税费/运费规则保持现有人工设置，不从供应商条件自动改写；含税价不能再静默加税、已含运费不能再静默加运费，显示潜在重复计费并要求确认。人工最终价不改采购记录，缺可靠基准继续提示无法核对成本。
- 报价 digest 加入 contract_version=2、有序产品/version、选定规格和价格 ID/version、来源 ID/version、完整条件快照及条件确认、客户规格文本、rules/overrides/moq/note。预览与导出各自使用一致读取事务，导出重新查库校验全部归属/资格/版本和条件并重算；不相信客户端传来的金额。选择、条件、规则或文本改变即清空所有确认并重新预览。
- 旧报价结果是已下载的文件而非数据库历史表，原文件不改写；V2 发布前已生成但未下载的旧 digest 必须 409 quotation_preview_mismatch 后重预览，不承诺跨版本继续导出。迁移副本上以同样旧单价/规则新生成的客户金额及原七列白名单保持一致。
- 延续文本风险检查、用户确认、金额 Decimal 计算和安全测试。客户文件仍仅一个可见工作表、七列“产品型号、产品名称、完整参数、卖点、最终报价、MOQ、报价说明”；全新构造，不复制内部表、批注、隐藏内容、文档属性或文件名。客户参数/卖点可能含厂家名称和成本，即使关键词未命中也必须全文确认；来源公司名同时纳入风险提示，不承诺自动清洗安全。客户复制功能同样执行白名单和核查，不输出关联 JSON。

## 8. 图片与原始文件

V2 第一阶段必须提供来源公司、原始文件名、页码/区域、日期和原文摘录的保存位置；真实缺失字段保持 NULL 并提示待核对，不能为满足必填编造原件信息；这属于资料追溯元数据，不等于保存文件本体。

实际产品图片、证书/检测报告及原始报价文件的二进制存储安排在独立附件阶段：
- 附件必须通过受控上传保存到工作台管理的目录，不允许把任意本机绝对路径写进数据库后当作可用附件。
- 附件关联产品或规格，并记录文件名、类型、来源页、大小、哈希和上传时间。
- 文件路径不得允许目录穿越；限制类型、大小和数量；删除产品时按明确规则处理附件，不误删共享来源。
- 不在当前阶段将图片 OCR、AI 识别、自动背景处理或外部云存储引入产品库。
- 当前导入明确提示“未保存图片及原始文件，请自行保留原件”，回执记录 attachments_not_imported；预览返回 attachment_warning，confirm 顶层 confirmed_attachments_not_imported=true 才可提交有此警告的文件，确认位纳入决策摘要。输入 Excel 内图片/绘图/超链接均不导入；存在时预览提示并要求确认，不把它们算作已保存资料。只有图片而无可用文字的内容留为待处理，不宣称转换完成；不得删除/移动用户原件，外部整理输出与原件由用户保留到附件阶段。
- 附件导入方案需在实施附件阶段另做短 Spec，比较单独上传与 ZIP 资料包的操作成本后再定，不在本 Spec 中擅自增加 ZIP 上传契约。

## 9. 迁移和兼容

- 新增 Alembic revision，父版本必须取实现时实际脚本 head；禁止修改历史 revision。
- 新迁移将当前 uq_library_products_manufacturer_model_name 索引替换为目标身份索引：uq_library_products_model_name（model, name，WHERE model IS NOT NULL），以及 uq_library_products_null_model_name（name，WHERE model IS NULL）。不得只改索引而遗漏服务层、schema gate、手动 CRUD、V1/V2 导入与并发校验。
- 同一实现 PR 必须同步更新 docs/specs/product-library-identity-v2.md 中与目标身份冲突的描述，避免仓库继续存在两套相反的有效规则。
- 新表使用外键和必要索引；启用/验证 SQLite 外键约束。
- 回填旧 wholesale_price_cents 为价格明细时，逐条验证旧金额与新记录一致；旧产品 ID、version、厂家、型号、名称、参数、卖点、价格备注、创建/更新时间和导入回执必须保留。
- 迁移前必须检查不同厂家之间的同型号同名称冲突，以及无型号同名冲突；不得自动合并。每个冲突须提供产品 ID 和字段差异供人工决策，冲突未解决前禁止迁移。
- 回填来源记录时，将旧 manufacturer_name 作为历史资料归属/来源标签保存，不把它自动认定为真实生产厂家。已有产品的主字段、ID、version 和导入回执保持不变。来源记录可保存 claimed_manufacturer_name；只有原件明确标注时才填写。
- 不自动解析旧 price_note，不把备注中的“控价/代发/运费/面议”转换成结构化金额。
- 数据迁移在隔离 SQLite 副本执行；迁移前后比较产品行、价格、身份索引、版本、导入回执、报价结果和外键完整性。任何不符合预期都阻止升级。
- 正式工作库不作为开发/验收数据库；不启动可能自动迁移正式库的服务来做试验。
- 停止所有写入后，在 BEGIN IMMEDIATE 的真实 SQLite 事务内执行完整预检、建表、回填、建目标索引、删旧索引、更新 alembic_version；预检含 integrity_check、foreign_key_check、规范化及全部 (model,name) 分组（包括 model IS NULL）。索引/回填/stamp 任一步失败均回滚 DDL、数据和 revision；不能使用会自动提交的中间操作。
- schema gate 必须验证两条目标身份索引的 unique/列顺序/BINARY/WHERE、旧身份索引不存在及关联表/约束就绪；不只看索引名字。未就绪所有 V2 身份/关联写入返回 503 identity_schema_required；只读和历史 committed 回执仍可用。
- legacy 来源每旧产品一条，source_type=other、notes 标记 legacy_backfill、公司取旧字段，原件文件名/页码/日期为空；非空旧价精确回填且关联该来源，按既有报价“元/件”合同标记 price_unit=件（历史合同语义，不伪称原件证实）。回填不调用会递增 version/updated_at 的运行期服务。再次 upgrade 由 revision 防重，失败重试不留半套表或重复回填。
- 降级与失败回滚分开：升级失败必须原地事务回滚；V2 已产生新资料后禁止通过 drop 新表降级。恢复须停写、导出备份后的全部产品/关联资料及回执，恢复验证过的一致性旧备份并人工处理增量，不声称无损自动降级。本阶段不授权正式库迁移、冲突归并或恢复执行。
- 测试中的 Alembic env 当前覆盖 sqlalchemy.url 为 DATABASE_URL；隔离演练必须显式替换应用 DATABASE_URL/engine 后再加载迁移环境，断言最终路径为临时副本，不能只传 -x 或改 ini 后假定隔离。不得启动正式服务验证迁移。
- 旧产品查询、编辑、删除、搜索、批量导入、报价预览/导出必须回归验证。

## 10. 分阶段实施

### Phase A — 独立 Spec Review（当前阶段）
审查目标身份键从旧索引迁移到 (model, name) 的碰撞预检、V1 来源追加行为、字段/价格镜像、Excel 表头、合并规则、迁移和报价兼容；审查通过前不实现。

### Phase B — 数据与导入核心
增加规格、价格、来源表和必要字段；实现 V2 模板/解析/预览/关联校验/事务保存；旧模板保持可用。图片/原始文件二进制暂不纳入。

B/C 为开发顺序，不是可分别上线的兼容边界；关联版本、镜像适配和旧报价门禁完整后才允许启用 V2 写入。

### Phase C — 详情与报价适配
展示和编辑参数、规格、来源、价格；报价支持明确选择价格记录/规格；保留现有客户导出安全合同。

### Phase D — 附件
单独评审并实现产品图片、证书、报告、原始报价文件的受控保存和展示。

暂不实现：内置 AI/OCR、供应商 CRM、库存/订单、复杂 SKU 组合器、全量报价历史分析看板、自动换汇、自动推断厂家/认证/报价。
