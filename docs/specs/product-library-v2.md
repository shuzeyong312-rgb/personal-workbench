## 1. 当前基线与设计取舍

`product_library_service.py` 的旧模板为六列：产品型号、产品名称、产品参数、产品卖点、批发价、价格备注；供应商在上传时填写。旧主表有文本参数、卖点、数值批发价和价格备注；当前 PR #7 未发布实现额外引入分类、参数 JSON、规格、来源、带类型的价格，以及 `20261029_20`/`21` 迁移。`ProductLibraryDetails` 暴露参数明细和关联表编辑；`product_library_quotations` 读取价格与快照并导出客户文件。生产库状态未在本轮核验；Issue 提供的前提是五表 V2 未发布、未迁移正式库。

继续使用已有产品主记录；新增或保留最少的来源记录与报价记录：来源关联产品，保存供应商、文件名、导入时间、行号/可知页码及该行八列原文；报价关联产品与来源，保存规格标签、原价文本、明确可用的金额/币种/单位及版本。规格只作为报价的文本标签，不需要独立规格实体；参数只保存完整文本。实际表/列与迁移以实现时最小 diff 为准，不为兼容五表保留通用价格类型、参数字典、结构化税运费/MOQ、规格管理界面。历史数据及回执保留优先于删列，不能为简化而删除唯一副本。

## 2. 输入合同

标准模板一个工作表，名称“产品清单”，严格按顺序固定八列：

| 列 | 规则 |
|---|---|
| 分类 | 普通文本，可空 |
| 产品型号 | 文本，可空；保留前导零 |
| 产品名称 | 文本，必填 |
| 产品参数 | 普通文本，可空；保留换行与厂家原文 |
| 批发价 | 唯一语义为出厂批发价；不同规格在同一单元格分行，例如 `5000mAh：26元/个` 换行 `10000mAh：32元/个`；可空 |
| 控价 | 独立普通文本，可空，保留渠道原文；绝不进入采购成本或客户报价计算 |
| 卖点 | 普通文本，可空 |
| 备注 | 普通文本，可空；MOQ、税费、运费、包装、售后等原文放这里 |

一行一产品，不要求 ID、额外工作表或图片。供应商名称在上传时填写/确认一次，空值阻止提交；从原件识别只可建议，须用户确认。单文件多供应商且行归属不可靠时阻止受影响行，提示拆分或明确归属后重新预览，不猜测。系统记录实际上传文件名、时间、行号；只有来源明确提供页码时才记录，不凭 Excel 行号伪造原件页码。外部整理厂家 PDF/Excel 等可批量生成此模板，一份文件可含数十至上百款；仅依据原文，无法确认的规格、金额或价格类型保留原文并标记待核对，不把出货价、代发价、零售价或控价猜成出厂批发价。原件需要用户自行保留；不宣称图片或文件已入库。

空值是未知，不是 0；非空文本保留内部换行，统一换行符并去除首尾空白。上传只接受明确识别的八列表头或旧六列表头，缺列、额外列/工作表、错序、公式、不可读取文件、超限等须明确定位并拒绝，不部分写入；旧六列继续按其既有格式及校验处理，不因新模板限制无故改变其兼容合同。Excel 中的图片/附件不导入，预览告知并由用户确认。实施时沿用现有安全限制，不静默截断。

## 3. 身份、预览和提交

身份为规范化后的型号 + 名称精确匹配，供应商不参与；空型号按空型号和名称匹配，空型号与有型号不同。同文件同身份多行无法确定合并时整组阻止并指出行号，不悄悄丢弃。分类、参数、卖点、控价、备注按字段展示现值和新值：已有主资料默认保留；明确选择后才更新选定字段，空输入不清空。来源原文无论选择保留或更新均留存；跳过整行则不写该行。

同产品不同供应商追加来源与报价，不覆盖其他来源。相同供应商、产品、规格按规范化文本精确匹配（空规格为单独键，不作模糊合并）；同值重复导入不创建重复报价，变化时展示旧/新值并要求明确选择更新或保留。变更要保留旧报价历史及来源；不同来源原文即使价格相同也须可追溯，重复同文件同内容重试不重复写入。单元格中的规格不可可靠拆分、同规格多种含糊金额或来源归属不明时保留整格原文、标待核对，不创建可计算报价；用户可跳过该行或在源文件修正后重新上传，不能静默猜测。

预览逐行展示八列、异常和冲突；确认须完成所有受影响行决策。确认重新校验产品/来源/报价版本及预览摘要，变更或过期则要求重新预览；产品、来源、报价、决策及回执在同一事务提交，失败全部回滚。相同确认请求重放已提交回执，不重复写入；未提交旧规则预览失效并提示重新上传，已提交历史回执可读取和幂等重放。不同文件来源指纹及报价去重应分别判定，不能因金额相同丢失新来源。

## 4. 详情和客户报价

详情以八字段为主，批发价按供应商/规格列出，来源及历史报价为次级展开信息；不呈现参数明细表或多价格类型管理。保留当前手动产品编辑、搜索和删除的既有安全语义；调整其输入/展示以适配文本字段，不让旧编辑入口意外覆盖来源或报价。资料原文和来源可查看，但不等同原件已保存。

客户报价必须明确选择该产品的供应商和规格的有效出厂批发价；不自动选择最低价，也不因只有一条就暗中替用户选择。无可用报价显示“无报价”，不得变成零。只有原文明示出厂批发价、金额与规格确定、人民币和每件计价明确且数值符合旧报价范围时才可计算；其他单位、币种、含糊金额仅展示并待核对，不换算。旧六列的数值批发价沿用原有人民币/件合同，作为历史批发价保留其来源与历史语义，不从价格备注推断别的价格。任何控价、其他类型历史价、来源、内部 ID、成本和备注不得输出到客户文件；沿用客户资料敏感词复核及导出白名单。报价预览到导出必须绑定所选报价、产品版本及规则快照，变化时失效重算，伪造跨产品或无资格选择拒绝。税费/运费条件不猜测，保留现有客户报价规则及确认流程。

## 5. 兼容、收敛与恢复

- 旧六列仍可导入：原表头、上传供应商和旧预览/决策行为保持兼容，六列分别映射型号、名称、参数、卖点、历史批发价、价格备注；新增分类和控价为空，价格备注原文保留。主资料冲突不静默覆盖。旧模板可继续下载或被识别；新标准模板只有八列单表。
- 正式旧库保留产品 ID、版本、字段、创建/更新时间、历史批发价、价格备注、来源及已提交回执；不能从备注或旧多类型价自动推导出厂批发价。跨厂家相同型号+名称或空型号同名碰撞须在锁内预检并输出 ID/差异，人工解决前拒绝迁移，不自动合并。真实旧库可能存在碰撞，本轮未查询。
- `20261029_20` 与 `21` 是 PR #7 未发布迁移：实现应以实际生产 Alembic head 为准，在未发布分支内移除/替换其五表实现与迁移，形成一条针对真实旧库的简化迁移链；不得修改已发布历史 revision。若任何环境已应用 20/21，先盘点并备份其中数据/回执，单独提供可验证的前向转换或重建隔离库方案，不能假定可丢弃，也不能直接降级删除数据。旧五表文件不承诺永久导入；明确提示已废弃，保留原件，需重新整理为八列。历史 committed 回执继续可读重放。
- 迁移在隔离旧库副本演练：停写、取得并验证一致性备份；事务内预检、建结构、回填、索引及版本更新，失败全部回滚。逐项比较旧数据、价格、来源、回执、外键及报价结果。已产生新写入后不通过删除新表降级；恢复须停写、导出增量、恢复已验证备份并人工处理增量。正式操作需另行授权。

## 6. 实现验收与门禁

1. 单表八列严格验证；百款合成资料、换行规格、空值、前导零、无图片、错误文件/公式及混合供应商均有明确结果。
2. 同身份跨供应商追加、相同报价重试、变价确认与历史追溯、主字段冲突、并发失效、确认失败回滚和回执重放均可验证；未知价格不能参与计算。
3. 旧六列、旧产品手动 CRUD/搜索、历史价格/备注和回执、身份碰撞、隔离迁移失败恢复均回归；不同来源不覆盖，输出文件全内容检查无内部成本/控价/来源/ID 泄漏。
4. 产品详情、上传预览冲突及报价选择进行桌面与窄屏人工验收；后端相关 pytest、前端相关 Vitest/typecheck/build 在实现阶段运行。样例和原型不证明真实厂家资料或生产行为。
5. 本轮只有设计与原型，固定 SHA 后等待 ChatGPT 独立 Spec Review；通过前不进入实现，不合并 PR #7、不部署或操作正式库。
