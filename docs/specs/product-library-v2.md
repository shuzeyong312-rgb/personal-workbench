- 目的：将不同厂家/供应商提供的报价资料统一整理入产品库，尽可能保留原始信息，同时建立可检索、可报价、可追溯的数据结构。

## 1. 问题与目标

用户收到的报价资料格式各异，常见内容包括产品型号/名称、技术参数、卖点、颜色、容量/功能版本、出厂价/批发价/代发价/平台控价、MOQ、税费与运费口径、包装物流、配件、认证/专利、售后条款、产品图片及原始资料页码。

已审阅的样本覆盖：
- GS008 磁吸暖手宝：出货价与两档零售控价、认证、包装配件。
- DM-82 挂脖风扇：出厂价、阿里控价、C 端控价、售后与运费条件。
- GS-01 手持风扇：风速档位、颜色、尺寸、装箱和重量信息。
- S17 迷你风扇：有图文及技术规格，但没有报价。
- W01 喷雾风扇：不同工作模式下的功率、续航、噪声和风速。
- H8 石墨烯暖手袋：5000mAh/10000mAh 两种容量，各有批发价与代发价、起批及运费条件。

目标：
1. 继续由外部 Codex 将厂家原始资料整理为统一 Excel；工作台不内置 AI/OCR/网页解析。
2. 产品基础资料、技术参数、规格款式、价格条件和来源分别组织，避免把不同价格混成一个“批发价”。
3. 尽量保留厂家原文；缺失值保持未知，冲突值明确提示，不由系统或 Codex 猜测。
4. 兼容现有产品、旧六列表格、产品搜索、客户报价和导入回执。
5. 以小型、可维护的关系模型解决一对多数据，不建设完整 ERP/PIM、供应商 CRM 或 SKU 组合引擎。

## 3. 产品语义与边界

### 3.1 产品与规格

- 产品是一款厂家产品资料主体。
- 颜色、容量、功能或配置不同，但属于同一产品系列时，可关联规格款式；不能仅因为不同颜色就强制建立多个主产品。
- 产品身份按型号 + 名称精确匹配，不因报价来源公司不同而拆成多个主产品。相同型号但名称不同、相同名称但型号不同，均视为不同产品。
- 规格只有在存在明确差异时建立；没有规格信息时不生成虚构规格。
- 参数可保留完整原文，同时可选地整理为参数明细。结构化参数不能替代原文。

### 3.2 厂家与报价来源必须区分

- 保留数据库字段 manufacturer_name，避免破坏旧数据、API 和身份索引；界面显示名调整为“厂家/资料归属公司”，不据此宣称该公司一定是实际生产工厂。
- V2 导入流程允许填写资料归属公司；报价来源公司在来源资料/价格记录中单独记录。
- 如果原件未说明实际生产厂家，不推断或补写。
- 不新增完整供应商档案、联系人、账期或采购订单功能。

### 3.3 价格类型不能混用

### 3.4 身份规则与迁移要求（P0）

目标身份规则已确定为“型号 + 名称”，不包含厂家/资料归属公司。当前 GitHub 主分支的模型、服务层、迁移 20261020_17 和身份 Spec 仍使用“厂家名称 + 型号 + 名称”，因此 V2 必须纠正实现与文档之间的差异，不能把旧索引当成目标规则。

目标唯一性：
- model 非空：精确唯一键为 (model, name)，不论厂家/资料来源公司是否相同。
- model 为空：同一 name 仍视为相同身份，不论厂家/资料来源公司是否相同。
- 型号、名称按规范化后的原文精确比较；大小写、全半角、标点及参数规格不做自动归并。
- 规格、颜色、价格类型、报价来源均不是主产品身份的一部分。

迁移必须先检查现有数据中跨厂家相同型号+名称的记录，以及无型号同名记录。存在多个历史产品 ID 时，迁移只输出冲突报告（ID、原厂家字段、型号、名称和必要差异）并整体拒绝升级；不得自动合并、删除或挑选一条作为主记录。人工完成数据归并方案并重新备份后，才允许继续迁移。

厂家/资料归属公司字段保留用于兼容旧记录，但不再参与身份匹配。每个报价来源必须进入独立来源记录。价格类型与渠道分开保存，例如 price_type=平台控价、price_channel=阿里平台，避免同一公司同时提供阿里控价与 C 端控价时发生混淆。相同产品从另一家公司导入时，默认新增来源/价格，不覆盖首录公司的主字段或主产品资料。V1 模板仍可上传，但其批次“厂家名称”在来源处理上作为报价/资料来源公司；如果命中已有产品，应通过预览明确选择追加来源、更新主资料或跳过。

### 3.3 价格类型不能混用

价格类型至少支持：
- 出厂价
- 批发价
- 一件代发价
- 定制价
- 平台控价
- 建议零售价
- 零售价
- 其他（必须保留原文说明）

价格记录还应保留币种、适用规格、起订量及单位、税费口径、运费口径、运费金额、定制条件、报价日期、来源及原文摘录。控价不得自动用作采购成本或客户报价输入。

未知价格必须为空，不得变成 0。明确零价才允许金额为 0。不得从自由文本备注中自动推算结构化价格。

## 4. 目标数据模型

采用现有主表加三类关联数据；不引入通用动态字段平台。

### 4.1 library_products（保留现有主表）

保留现有字段和原始值：
- id、manufacturer_name、model、name
- manufacturer_name 在 V2 作为历史/首录资料归属字段兼容保留，不参与身份匹配，也不自动代表经核实的实际生产厂家。新产品沿用批次来源公司填充该兼容字段；后续追加其他来源时不覆盖。实际厂家仅记录在来源资料中明确标注的字段。
- parameters、selling_points
- wholesale_price_cents、price_note
- created_at、updated_at、version

新增：
- category：可空的产品分类文本，不强制建立复杂分类树。
- structured_attributes：可空 JSON，用于灵活参数明细；每项至少包含 group、name、value、unit、condition、source_excerpt。原始参数文本仍保存于 parameters。建议分组包括“基本规格、供电/电池、性能/模式、材质、包装物流、配件清单、认证/专利、售后政策、交易条件、其他”。这些是数据分组，不为每个品类建立独立数据库列。

目标身份键为型号 + 名称。当前数据库索引尚未符合目标，必须通过新迁移改为型号/名称精确唯一性，并同步手动新增/编辑、V1/V2 导入、重复预览和并发检查。厂家字段保留但不参与身份匹配。

### 4.2 library_product_variants（规格款式）

最少字段：
- id、product_id（外键）
- variant_code（可空的厂家规格/SKU 编码）
- variant_name（必填，如 5000mAh、10000mAh、冰川蓝）
- color（可空）
- attributes_json（可空，保存规格独有参数）
- notes、created_at、updated_at、version

规格记录必须属于一个产品。没有明确规格的产品不要求创建空规格。规格编码只在同产品内匹配，不得把厂家未提供的 SKU 编码编造出来。

### 4.3 library_product_sources（资料来源）

最少字段：
- id、product_id（外键）
- source_company（可空；报价/资料提供方）
- claimed_manufacturer_name（可空；原件明确标注的生产厂家）
- source_file_name（可空；原始文件名）
- source_page（可空；页码、工作表或区域）
- source_date（可空；原件明确给出的报价/资料日期）
- source_type（quote/catalog/specification/other）
- source_excerpt（可空；支持追溯的原文摘录）
- notes、created_at

导入时间与原件报价日期必须分开。原件没有日期时 source_date 留空，不得将导入当天伪装成报价日期。V2 初始阶段保存来源元数据和摘录；原始文件二进制及图片附件纳入后续附件阶段，不声称只存文件名就等于保存了原件。

### 4.4 library_product_prices（价格明细）

最少字段：
- id、product_id（外键）、variant_id（可空外键）
- source_id（可空外键）
- price_type、price_channel（可空，如阿里平台/C端平台）、amount_text（规范化十进制文本）、currency_code
- min_order_quantity、min_order_unit
- tax_mode（unknown/included/excluded）
- freight_mode（unknown/included/excluded/extra/negotiable）
- freight_amount_cents（可空；仅用于人民币运费，其他币种运费保留在 terms_text）
- customization_terms、terms_text、notes
- quote_date（可空）、is_default_wholesale
- created_at、updated_at、version

价格金额以规范化十进制文本保存，避免将不同币种都假设为“两位小数的分”。V2 结构化记录可保存 ISO 4217 币种代码；CNY 金额最多两位小数，其他币种按原文精度保存。当前人民币客户报价计算只允许 CNY 价格，其他币种不得直接参与计算，也不自动换汇。

每条价格可作用于整个产品（variant_id 为空）或某一规格。起订量与单位必须分开保存；“20 个/箱起批”等完整条件还要保留原文，避免只存一个数字丢失语义。

### 4.5 旧批发价兼容规则

wholesale_price_cents 暂时保留为兼容字段，不再作为所有价格的唯一数据源。

- 迁移时，对旧产品中非空的批发价回填一条产品级、币种 CNY、类型“批发价”、来源标记为 legacy_backfill、默认标记为真的价格记录；不从 price_note 推断其他价格。
- V2 中只有存在唯一且明确的产品级默认批发价时，才将金额镜像到 wholesale_price_cents。
- 如果产品存在多个规格价或多个候选批发价且没有唯一默认项，镜像字段保持 NULL，列表显示“多价格”或“需选择规格”，不得挑最低价/第一条价格。
- 新旧字段的同步必须由服务层在同一事务中执行；不得允许两个来源互相覆盖。
- 产品列表排序/筛选的旧“批发价”语义定义为“默认批发价”，不表示任意一种价格。多规格价产品不能因为没有默认价就被误认为完全没有报价。

## 5. V2 Excel 模板契约

保留 V1 模板并继续接受。V2 模板采用独立、严格版本的工作簿；通过产品数据表头和所需工作表组合识别，不依赖文件名猜测版本。混合、未知或不完整结构明确报错。

### 5.1 产品数据（必需）

列顺序固定：
1. 产品临时ID（工作簿内唯一，如 P001）
2. 产品型号
3. 产品名称
4. 产品分类
5. 产品参数原文
6. 产品卖点
7. 默认批发价
8. 价格备注

产品临时ID仅用于关联同一工作簿中的其他表，不作为数据库 ID。报价/资料来源公司在上传步骤必填一次，作为本批来源记录的默认值，不在每行重复；资料索引中的来源公司可覆盖该默认值。若来源公司确实未知，必须在预览中显式标记未提供，不能伪造公司名。现有 manufacturer_name 字段保留为兼容的首录厂家/资料归属字段，不参与身份匹配；命中已有产品时不得因为来源公司不同而覆盖该字段。

默认批发价是兼容快捷字段；完整多价格必须进入价格明细。若默认批发价与价格明细中标记的默认批发价冲突，该产品标记为待处理，不自动择一。

### 5.2 参数明细（可空）

列顺序固定：
- 产品临时ID
- 规格临时ID（可空，空表示产品级参数）
- 参数分组
- 参数名称
- 参数值
- 单位
- 适用条件
- 原文摘录

参数名称、值和来源摘录应尽量保留原件含义。不能确认的数值/单位不要标准化成猜测结果。复杂的模式参数（如 W01 不同模式的功率和续航）应按适用条件分别记录。包装尺寸、装箱数、配件、认证/专利、保修与退换货、税费和运费政策均可使用分组参数记录，不需要为每类产品增加专属列。参数明细最终合并进产品或规格的 structured_attributes JSON，不单独建立参数数据库表；参数原文仍保留在产品 parameters 字段。

### 5.3 规格款式（可空）

列顺序固定：
- 规格临时ID（工作簿内唯一）
- 产品临时ID
- 规格名称
- 规格编码
- 颜色/款式
- 规格备注

不把相同参数、相同价格的每个颜色强制拆成独立价格记录；产品级价格可以适用于所有规格。规格独有参数通过参数明细引用规格临时ID。

### 5.4 价格明细（可空）

列顺序固定：
- 价格临时ID（工作簿内唯一）
- 产品临时ID
- 规格临时ID（可空）
- 价格类型
- 价格渠道（可空，如阿里平台/C端网络平台）
- 金额
- 币种
- 起订量
- 起订单位
- 税费口径
- 运费口径
- 运费金额
- 定制条件
- 报价日期
- 资料临时ID（可空）
- 是否默认批发价
- 价格备注
- 原文摘录

金额使用明确十进制文本，币种使用 ISO 4217 代码并与金额分开。CNY 金额最多两位小数；其他币种保留原文精度但不参与人民币自动报价。未知金额留空，不得填 0。“面议”“定制另算”等信息放入价格备注/原文摘录，不能伪造成数字。

### 5.5 资料索引（可空）

列顺序固定：
- 资料临时ID（工作簿内唯一）
- 产品临时ID
- 报价来源公司
- 原件中标注的生产厂家（可空）
- 原始文件名
- 页码/工作表/区域
- 原件日期
- 资料类型
- 原文摘录
- 备注

一个产品可以有多条来源资料；价格记录通过资料临时ID关联来源。来源公司与资料归属公司不默认相同。若本批未提供资料索引行，系统仍须为每个被导入产品建立一条默认来源记录，使用上传时填写的来源公司和原始文件名；价格行未指定资料临时ID时关联该默认来源，避免来源信息丢失。来源索引另增加“原件中标注的生产厂家”（可空）字段，仅记录原件明确说明的厂家，不据来源公司推断实际生产厂家。原始文件名和页码只表示来源元数据，不能冒充已保存原始文件。

### 5.6 填写说明

模板含填写说明，列明字段含义、允许值、缺失/冲突处理和样例。说明表的样例不得被当作真实产品行导入。

## 6. 导入、校验与合并规则

### 6.1 兼容和安全

- V1 六列表头继续可上传，但产品身份匹配必须采用 V2 目标规则（型号 + 名称），不能保留旧的厂家分区去重逻辑。
- V1 文件的厂家名称作为该批次的来源公司；对于新产品，可继续写入旧 manufacturer_name 兼容字段。若型号+名称已存在且本批来源尚未记录，默认提供“追加来源/价格”操作；该操作只追加或更新来源/价格，不覆盖已有主资料。若来源及价格均已精确存在，则默认跳过。
- V2 使用独立解析分支；不得静默把 V2 多价格数据塞进 V1 的 price_note。
- 延续现有 .xlsx、文件大小、OOXML/ZIP 安全、公式拒绝、隐藏行列/合并单元格检查。所有业务表的公式单元格均拒绝，不能使用缓存公式结果。
- 延续 1000 个产品主记录的现有限额；关联表增加明确的总行数上限，建议合计最多 5000 条参数、规格、价格和来源记录，仍受现有 5 MiB 上传与 50 MiB 解压限制。
- 拒绝未知工作表、未知列、重复临时 ID、孤儿引用、跨产品错误规格引用、价格引用不存在的来源，以及无法识别的模板版本。
- 预览阶段不得写入产品、规格、价格或来源数据；只允许写入导入凭据。

### 6.2 产品身份

主产品身份固定为 (model, name)，厂家字段不参与匹配。非空型号使用唯一索引 (model, name) WHERE model IS NOT NULL；无型号使用唯一索引 (name) WHERE model IS NULL。服务层、手动 CRUD、V1/V2 导入、文件内重复、并发检查和回执基线必须采用相同规则；不允许只改索引而保留旧的按厂家筛选身份逻辑。禁止模糊匹配。

### 6.3 关联数据校验

- 每条参数、规格、价格和资料索引必须引用存在的产品临时ID。
- 规格临时ID必须唯一；价格引用的规格必须属于同一个产品。
- 价格类型、币种、税费/运费口径使用允许值；其他类型必须明确选择“其他”并保留原文。
- 规格、价格和来源的格式错误必须显示工作表名、Excel 行号、字段和原因。
- 关联数据有错误时不得静默丢弃。预览中逐项标记；用户可跳过错误关联行或修正文件重新预览。所有跳过项必须出现在最终回执中。
- 如果产品主记录被跳过，其关联的规格/价格/来源行默认一并跳过，并在结果中明确说明。
- 参数明细按归属产品/规格 + 参数分组 + 参数名称 + 适用条件精确匹配；同一身份在同一工作簿出现互相冲突的值时标记冲突。更新现有参数时显示旧值、新值和来源摘录；缺少参数行不删除旧参数。
- 缺少某个工作表的业务数据不代表删除已有记录；导入是增量合并，不做“缺席即删除”。

### 6.4 关联记录匹配

- 规格优先使用产品内的规格编码精确匹配；无规格编码时使用规格名称、颜色及规范化属性精确匹配。存在多个候选时禁止自动选第一个。
- 来源资料按产品、来源公司、文件名、页码、原件日期及来源类型识别候选；同一页允许不同来源摘录，必要时将规范化摘录摘要纳入候选判定；内容变化展示差异。
- 价格候选按产品、规格、价格类型、价格渠道、币种、来源、报价日期、起订数量/单位和定制条件匹配。税费/运费口径与金额属于可比较字段，变化时展示差异并由用户决定更新；不同来源或不同报价日期的记录可以并存。
- 默认批发价规则：可以有一条产品级默认批发价（适用于所有规格），或为各规格分别指定默认批发价；两种方式不能同时使用。每个规格最多一条默认批发价。出现多个/冲突默认候选必须在预览中解决，不能自动择一。
- 不根据最低价、最新导入时间或 Excel 行顺序自动覆盖价格。
- 没有足够信息唯一识别已有规格/价格/来源时，默认跳过并要求人工确认；不做模糊匹配或 AI 合并。
- 不因一次导入缺少旧关联行而删除已有规格、价格、来源。删除只能在产品详情中明确操作并二次确认。

### 6.5 事务与回执

复用当前 LibraryImport 的服务端凭据、30 分钟 ready 期限、幂等回执和原子写事务。当前 identity_rule_version 为 3；V2 必须递增身份/解析规则版本，不能复用旧 ready 预览。基线摘要必须包含按型号+名称命中的产品及其规格、价格、来源的稳定排序快照，不能按厂家隔离，也不能只检查主产品表。

- 提交前再次校验基线、版本和全部决策。
- 产品、规格、价格、来源及 committed 回执在同一事务写入。
- 任意数据库写入失败必须整体回滚，不能只保存主产品而丢失关联价格。
- 网络不确定时先查询原 import_id；不得自动重复上传。
- V2 发布后，旧 ready 预览因解析/身份规则版本不一致而要求重新预览；旧 committed 回执仍可查询/幂等重放。
- 同一产品不能被同一批次的多个关联行重复更新成相互冲突的结果。
- V2 决策标识必须使用“工作表名 + 原始 Excel 行号 + 记录类型/临时ID”，不能只用行号，因为不同工作表会重复行号。产品主记录与每条参数明细、规格、价格、来源记录均展示独立的新增/更新/追加来源/跳过/错误状态；更新必须携带目标数据库 ID 与 version。参数明细最终合并进产品/规格 JSON，但审核仍保留原始工作表行号。产品被跳过时，其关联记录只能一并跳过。对已有产品，append_source 只能增加或更新明确来源下的来源/价格记录，不得改写产品主字段。

## 7. 产品详情与客户报价

### 7.1 产品详情

在现有产品库页面中扩展详情区，不另建导航或通用状态系统。建议分区：
- 基础信息
- 技术参数与卖点
- 规格款式
- 价格明细
- 包装/配件/认证/售后（以参数分组和原文保存，不建立每个品类专属字段）
- 资料来源
- 附件（后续阶段）

列表显示型号/名称、来源公司摘要、默认批发价状态和更新时间。公司筛选应按关联来源记录查询，旧 manufacturer_name 仅作为没有来源记录时的兼容回退。价格状态区分“有默认批发价”“多价格/需选规格”“无报价”，不能把控价算作已有采购价。

### 7.2 客户报价兼容

- 现有只有一个批发价的产品迁移后应继续可报价，原有金额与客户导出白名单不变。
- 只有一个明确的 CNY 默认批发价时可沿用旧流程。
- 多规格或多价格产品必须在报价预览中明确选择规格与基准价格记录；不自动取最低价。
- 默认自动报价来源只允许唯一、明确的默认批发价。用户也可以显式选择出厂价、批发价或代发价作为本次基准价，但必须在预览中显示来源、规格和价格类型；平台控价、建议零售价及零售价不能作为自动采购成本来源。
- 缺少明确采购价时显示待报价并阻止自动计算；用户可以按现有机制人工填写本次客户报价，但不得修改厂家原始价格。
- 客户 Excel 只导出原有白名单字段和本次确认的客户报价；来源公司、原始报价、平台控价、价格备注、税费/运费内部条件、内部 ID 和来源摘录均不得自动导出。
- 延续文本风险检查、用户确认、版本快照、金额 Decimal 计算和安全测试。

## 8. 图片与原始文件

V2 第一阶段必须保存来源公司、原始文件名、页码/区域、日期和原文摘录；这属于资料追溯元数据，不等于保存文件本体。

实际产品图片、证书/检测报告及原始报价文件的二进制存储安排在独立附件阶段：
- 附件必须通过受控上传保存到工作台管理的目录，不允许把任意本机绝对路径写进数据库后当作可用附件。
- 附件关联产品或规格，并记录文件名、类型、来源页、大小、哈希和上传时间。
- 文件路径不得允许目录穿越；限制类型、大小和数量；删除产品时按明确规则处理附件，不误删共享来源。
- 不在当前阶段将图片 OCR、AI 识别、自动背景处理或外部云存储引入产品库。
- 附件导入方案需在实施附件阶段另做短 Spec，比较单独上传与 ZIP 资料包的操作成本后再定，不在本 Spec 中擅自增加 ZIP 上传契约。

## 9. 迁移和兼容

- 新增 Alembic revision，父版本必须取实现时实际脚本 head；禁止修改历史 revision。
- 新迁移将当前 (manufacturer_name, model, name) 唯一索引替换为目标身份索引：(model, name) WHERE model IS NOT NULL，以及 (name) WHERE model IS NULL。不得只改索引而遗漏服务层、schema gate、手动 CRUD、V1/V2 导入与并发校验。
- 新表使用外键和必要索引；启用/验证 SQLite 外键约束。
- 回填旧 wholesale_price_cents 为价格明细时，逐条验证旧金额与新记录一致；旧产品 ID、version、厂家、型号、名称、参数、卖点、价格备注、创建/更新时间和导入回执必须保留。
- 迁移前必须检查不同厂家之间的同型号同名称冲突，以及无型号同名冲突；不得自动合并。每个冲突须提供产品 ID 和字段差异供人工决策，冲突未解决前禁止迁移。
- 回填来源记录时，将旧 manufacturer_name 作为历史资料归属/来源标签保存，不把它自动认定为真实生产厂家。已有产品的主字段、ID、version 和导入回执保持不变。来源记录可保存 claimed_manufacturer_name；只有原件明确标注时才填写。
- 不自动解析旧 price_note，不把备注中的“控价/代发/运费/面议”转换成结构化金额。
- 数据迁移在隔离 SQLite 副本执行；迁移前后比较产品行、价格、身份索引、版本、导入回执、报价结果和外键完整性。任何不符合预期都阻止升级。
- 正式工作库不作为开发/验收数据库；不启动可能自动迁移正式库的服务来做试验。
- 旧产品查询、编辑、删除、搜索、批量导入、报价预览/导出必须回归验证。

## 10. 分阶段实施

### Phase A — 独立 Spec Review（当前阶段）
审查目标身份键从旧索引迁移到 (model, name) 的碰撞预检、V1 来源追加行为、字段/价格镜像、Excel 表头、合并规则、迁移和报价兼容；审查通过前不实现。

### Phase B — 数据与导入核心
增加规格、价格、来源表和必要字段；实现 V2 模板/解析/预览/关联校验/事务保存；旧模板保持可用。图片/原始文件二进制暂不纳入。

### Phase C — 详情与报价适配
展示和编辑参数、规格、来源、价格；报价支持明确选择价格记录/规格；保留现有客户导出安全合同。

### Phase D — 附件
单独评审并实现产品图片、证书、报告、原始报价文件的受控保存和展示。

暂不实现：内置 AI/OCR、供应商 CRM、库存/订单、复杂 SKU 组合器、全量报价历史分析看板、自动换汇、自动推断厂家/认证/报价。

## 12. 测试门禁

- pytest：模型/服务/迁移/导入解析/关系引用/重复与更新/回滚/幂等/报价兼容/文件安全。
- Vitest：模板版本识别、预览分类、默认操作、价格类型与规格选择、报价风险状态。
- TypeScript typecheck、frontend build。
- 按需人工浏览器验收产品详情、V1/V2 导入与报价关键路径；不新增前端 Playwright E2E。
- 迁移只在隔离 SQLite 副本运行；不得以正式工作库作为测试夹具。

实现前必须通过独立 Spec Review，至少确认：
1. 目标身份键 (model, name) 与现有索引的差异已处理；迁移碰撞预检、手动 CRUD、V1/V2 导入及来源追加行为一致。
2. V1/V2 模板识别与所有列名固定。
3. 价格镜像规则不会造成新旧字段双向漂移。
4. 规格/价格/来源的匹配和重复策略可确定、可预览、可幂等。
5. 多价格报价选择不会误用控价或其他非采购价格。
6. 迁移可在隔离副本完整回滚，且不丢旧产品或回执。

本 Spec 只定义目标与契约；未实现、未迁移、未对正式数据执行任何写入。
