# 组内竞争情报与竞争位置 V1

> 状态：正式 Spec 草案，待 ChatGPT 独立 Spec Review；未冻结、未实施。
> 日期：2026-10-09。第一期交付已有事实的位置分析与目标 UI；不授权本轮业务实现。
> 本文使用 to-spec 的结构化业务与测试合同，不执行 Issue Tracker 发布流程。

## Problem Statement

运营者在选定商品组内需要快速回答：我方在某个真实指标下处于什么位置，具体哪些 Offer 有差异，最近发生了哪些值得检查的变化，证据在哪里。当前组详情提供真实差距计数与事件动作，但我方固定第一行、没有指标排序，经营指标与综合评分尚不可用。逐个打开详情自行拼接结论效率低，也容易把库存变化、展示低价或精选样本误读为销量、同规格优势或市场结论。

## Solution

把现有 Group Detail 升级为 PC Web 优先、兼容窄浏览器窗口的组内竞争情报工作台，继续使用 React + FastAPI、现有导航与浅色蓝紫 UI。以 Offer 横向比较主表为核心，配合真实竞争动态、右侧事实快检和证据缺口。第一期真实启用店铺名、链接展示报价、MOQ、SKU、完整库存、变化历史、Offer 比较和单指标组内位置。

四项分析摘要、经营判断与综合竞争力区域保留确认的目标布局；真实能力未接入时明确显示“待接入 / 证据不足”。成交、增长、上架时间、口碑履约、收藏和标签须逐字段 POC 与后续 Spec 才能启用。V0.3 模拟分数、权重、增长率、情景和结论均不得进入生产。

成功条件：以真实 A19 组验收，用户约 5～10 秒内找到我方 MOQ 位置、两条 MOQ=1 的竞品及其证据；按真实指标排序后我方处于真实位置；能找到重要变化的前后值与检测时间。失败条件：硬编码 A19、假数值、伪排名、将样本称作全市场、让库存微动淹没真实价格/MOQ/SKU 变化。

## User Stories

1. 作为运营者，我希望看到组名、我方数、直接竞品数与样本口径，以便知道分析覆盖范围。
2. 作为运营者，我希望看到最近采集与各字段覆盖，以便判断证据是否完整。
3. 作为运营者，我希望同时看到主表和辅助判断，以便减少纵向翻找。
4. 作为运营者，我希望以真实店铺名识别 Offer，以便找到具体对手而不误合并同店商品。
5. 作为运营者，我希望切换四种字段视图，以便按任务观察而不一次塞满所有列。
6. 作为运营者，我希望直接点击列标题排序并再次反转，以便快速找我方位置。
7. 作为运营者，我希望看到当前排序方向、参与数、并列和未知原因，以便正确理解名次。
8. 作为运营者，我希望我方参与排序且能快速定位，以便避免虚假的第一行。
9. 作为运营者，我希望搜索店铺、商品或 Offer 并筛选真实条件，以便缩小检查对象。
10. 作为运营者，我希望筛选不暗改全组名次，以便不误读当前结果。
11. 作为运营者，我希望区间报价保持原文与语义，以便不误判同规格价格。
12. 作为运营者，我希望看到停止监控、下架、未知及无快照状态，以便区分历史与当前事实。
13. 作为运营者，我希望重要动态先出现且普通库存变化可查，以便降噪而不丢事实。
14. 作为运营者，我希望从动态与字段进入现有单品证据，以便核验来源。
15. 作为运营者，我希望右侧快检展示选中 Offer 的真实事实，以便检查单品。
16. 作为运营者，我希望未接入的成交、增长和评分明确标记，以便不被演示结论误导。
17. 作为运营者，我希望局部加载失败保留上一份事实并提供重试，以便继续检查而不把失败视作零值。
18. 作为运营者，我希望窄窗口可读、表格局部滚动、键盘可操作，以便持续使用 Web 工作台。

## Implementation Decisions

### 1. 文档效力与分期

- 本轮仅编写 Spec 与直接索引；自检后的纯 Spec Commit / Push 已获授权。
- 本文经独立 Review 并冻结后，才作为实现合同。第 8 节待确认项不得在实现阶段自行决定；评分与新数据独立后续 Gate 不阻塞已有事实能力。
- 冻结后明确替代旧 Group Detail 的“我方固定第一行”、旧大基准/差距首屏、动作数排行作为主要动态区及仅纵向页面结构；其余快照、比较、时区、成员关系、错误与查询规则继承。旧 Spec 原文保留。
- UI System 中“排名尚未实施”是当前事实；本 Spec 不宣称其已经上线。导航融合与全局视觉重构仍不在范围内。
- 重构计划与研究中的公司主体优先、独立指标选择控件、仅已接入视图等建议，按本轮明确要求收敛为店铺主显示、表头排序、四种目标视图及未接入状态；不得直接搬用研究草案。

### 2. 当前实现核验与最小变更边界

当前实现已核验：组详情单一聚合读取，返回 own、直接竞品、最新快照、Backend comparison、summary、今日事件和 7/30 天动作统计；Frontend 用内部 Page state 和请求序号防止过期响应覆盖。当前表固定我方首行；今日提供事件明细，7/30 天仅动作计数，不足以直接展示窗口内前后值；当前我方详情按钮缺失，需要复用单品入口补齐。

现有身份以 ownership 为准、group_id 表示当前归组、group_role 表示兼容角色。每组至多绑定一个 self/own；当前直接竞品为当前组内 ownership=competitor 的 Offer，不凭店铺名或标题猜身份。

后续实现仅扩展现有组详情只读聚合、response contract、对应页面及 scoped 样式和直接测试。复用 Snapshot、SkuSnapshot、ChangeEvent、单品详情、业务日期工具、已有 UI 组件与浏览器 API Mock。不得新增数据库表/字段/迁移、采集器、评分服务、调度器、依赖、Router、状态框架或持久化用户偏好。批量查询避免 N+1；不按行请求单品详情来拼主表。

### 3. 数据事实与就绪状态

Offer 是比较与排序单位，以 platform + offer_id 识别，行关联现有商品 id。同店铺多个 Offer 分别保留，不累计、合并或去重。店铺名仅为来源展示名，不认证企业主体；缺失显示“店铺未采集”，辅以商品名和 Offer ID。

最新快照沿用 captured_at DESC、id DESC。last_collected_at 与有效快照时间分开解释；失败不能生成新事实或覆盖历史。商品级价格字符串按十进制数值比较，不按字符串字典序排序。SKU 数是最新快照的实际 SKU 行数，有快照的 0 有效；无快照不可补 0。库存仅当存在 SKU 且全部 stock 非负且非 null 时求和，未知不补零。

| 状态 | 页面语义 | 排序/评分 |
| --- | --- | --- |
| READY | 已接入且该 Offer 有有效、同口径事实 | 只允许本期就绪指标排序；本期均不评分 |
| UNKNOWN | 已接入但该字段缺失或无法确定 | 无名次，末尾显示未知原因 |
| NO_SNAPSHOT | 从未获得有效快照 | 显示未采集，不能补零 |
| NOT_INTEGRATED | 数据能力尚未正式接入 | 显示待接入；表头不可排序 |
| INSUFFICIENT_EVIDENCE | 分析所需来源/历史/规则不足 | 显示证据不足；无分数或结论 |
| 历史事实 | 已停止、已下架或当前在线状态未知的最后有效值 | 展示时间与排除原因，不计当前名次（建议规则 R2） |

以上是显示与只读派生语义，不要求增加通用状态引擎或数据库枚举。NOT_INTEGRATED 不得伪装成全部商品恰好 null；标签未接入不表示“无标签”。成交档位如 `<10`、`100+` 保留原文，不能强转成 10 或 100 排序、求均值、增长或计分；本期不接入此数据。

### 4. 目标 UI 与第一期落地边界

#### 4.1 页面区域、层级和信息密度

A. 顶部沿用 AppShell、面包屑和 PageHeader，展示组名、我方 Offer 数（0/1）、直接竞品数（不含我方，含停止/下架成员）、最近真实采集时间及数据覆盖提示。明确“选定监控样本，非全市场统计”。最近采集时间取当前成员非空 last_collected_at 最大值；没有则“尚未采集”，不能代替每行快照时间。显示本期各指标可排名数/全组 Offer 数；未接入指标用文字状态。

B. 四项摘要依次为：组内经营景气信号；我方综合竞争力及组内位置；竞品成交与增长数据覆盖；当前经营决策提示。第一期景气“证据不足”；综合竞争力“待接入：评分规则未冻结”，下方可独立显示真实单指标位置；成交/增长“待接入”，不能展示模拟覆盖分子；经营提示“证据不足”，提供核查入口，不能给加码/放弃/调价结论。摘要紧凑排列，窄屏可折行，不用大块空白撑高页面。

C. 核心区在足够宽的桌面内容区为双栏，左栏较宽，包含主表和真实动态；右栏包含经营判断/关键证据/建议，以及综合竞争力/评分拆解/单品快检。前两类分析及评分拆解本期显示未就绪理由与缺口，不生成进度条、雷达图或虚构权重。快检显示选中 Offer 的报价、MOQ、SKU、完整库存、状态、时间、当前事实差异及详情入口，默认选择我方；无我方时显示“未建立我方基准”，可选择竞品检查其事实。

D. 桌面不能把所有模块简单纵向堆叠。窄窗口可折为单栏，主表优先，右侧辅助在后；宽表局部横向滚动，不产生整个 shell 横向溢出，不靠缩小字体硬塞。使用既有字号、spacing、卡片、浅色蓝紫语义及主滚动容器；表头与身份应易找，滚动不能遮挡按钮或末行。A19 九条 Offer 应能紧凑扫描，不强制一次铺开四视图所有字段，也不新增分页系统。

#### 4.2 四种视图与字段状态

四个 Tab 均可进入。未接入视图保留字段标题与明确的区域提示，行中按状态显示“待接入”；不创建数据库空列或假数据。

| 视图 | 字段 | 第一期状态及默认排序方向 |
| --- | --- | --- |
| 竞争总览 | 店铺/Offer | 真实身份展示，本期不设身份排名 |
| 竞争总览 | 竞争力 | NOT_INTEGRATED，不可排序 |
| 竞争总览 | 链接展示报价 | 已有 price_min/price_max；建议按完整区间下限升序 R1 |
| 竞争总览 | MOQ | 已有 min_order_quantity，升序 |
| 竞争总览 | SKU | 已有 sku_count，降序；数量不代表质量优势 |
| 竞争总览 | 月成交、增长 | NOT_INTEGRATED，不可排序 |
| 经营表现 | 上架时间、月成交、月代销、年成交件数、年成交笔数、增长 | 全部 NOT_INTEGRATED，不可排序；时间窗口、单位和粒度待 POC |
| 口碑履约 | 评论数、好评率、揽收率、收藏数 | 全部 NOT_INTEGRATED，不可排序；店铺级字段须标归属 |
| 平台标签 | 新品、人气新品、首发新品、超级新品、跨境、严选、哇偶定制等 | 全部 NOT_INTEGRATED，不可筛选/评分；列按该视图显示 |

本期竞争总览另保留紧凑“库存”事实列及详情操作，库存可按完整值降序做事实排序，不能称库存竞争力。状态、快照时间、最近变化与 Backend comparison 可放身份次级信息、快检和证据提示，避免额外堆满主表。每个视图保留店铺/Offer、我方标识及详情入口。

#### 4.3 表头排序与我方位置

- 删除独立“排序指标”下拉框和“升序/降序”按钮。仅就绪的数值列标题提供可点击按钮；第一次点击使用上表默认方向，再次点击同列反转，切换新列恢复该列默认方向。
- 当前排序列高亮并显示 ↑ / ↓；语义分别为升序/降序。使用表头 aria-sort、键盘 Enter/Space 与可见 focus；未接入列没有可操作排序按钮并解释原因。
- 首次进入竞争总览建议默认 MOQ ↑，在 R1 未确认时也可完成真实位置验收。切换视图保留搜索与筛选及已选 Offer；当前排序列在新视图不存在/未就绪时，新视图按稳定身份顺序显示、无活动排序箭头与指标位置，返回总览恢复最后合法排序。无本地持久化。
- 我方和竞品参加同一真实排序；不得 pin 我方第一行。相等主值按现有 id 升序稳定展示，但名次保持并列；反转方向不反转缺失区，也不制造并列中的先后竞争名次。
- 未知、无快照、停止、下架等无当前名次行始终在已参与排序行之后，末尾按 id 升序；保留历史事实和排除理由，不能依历史值冒充当前排名。
- “定位我方”滚动到我方行并短暂强调，不改变排序。若被搜索/筛选隐藏，明确提示并提供“清除筛选并定位我方”；不能悄悄绕过过滤。无绑定时显示原因而不定位竞品。

#### 4.4 搜索、必要筛选、详情与证据路径

搜索匹配店铺名、商品标题和 Offer ID，trim 后大小写不敏感子串匹配，不搜企业身份。条件组合为 AND。本期仅提供监控状态（全部/监控中/已停止）、商品状态（全部/在线/下架/未知）及“仅看重要变化”；不添加未接入的成交、标签筛选与复杂保存查询。

“仅看重要变化”针对当前今日/7/30 天窗口中有价格、MOQ 或 SKU 事件的 Offer；与动态区的“重点/全部”使用同一定义。默认关闭，动态默认重点。时间切换成功后才更新这一过滤，失败保留原窗口和提示。搜索/行状态筛选只过滤主表，不隐式改变全组动态和覆盖统计；动态保留全组范围标识。

点击商品/详情打开现有单品 Detail，我方与竞品都支持；点击行的快检入口更新右侧选中 Offer。字段说明展示来源快照 id、captured_at、原始区间/值、指标口径与排除原因，并提供现有详情入口，不要求新增第二份单品详情页。变化证据使用 event id、snapshot_id、collection_run_id 与检测时间定位事实：详情页没有事件锚点时也必须保留所选事件的前后值和关联标识，不能声称跳转已精确定位历史。

#### 4.5 状态合同

| 状态 | 必须呈现的行为 |
| --- | --- |
| Loading | 首次加载真实 loading，不能先显示假数值；范围更新局部 loading，保留上份事实 |
| Empty | 空组/无直接竞品/仅我方分开表达；搜索无结果提示清除条件；重点无事件提示可看全部，不等于完全无变化 |
| Partial | 已有事实照常显示，缺失字段明示；覆盖分母保持全组，不把缺失当零 |
| Error | 首次失败显示重试；404 显示组不存在与返回入口；刷新失败保留旧数据并注明失败/时间，不能更新成功时间或显示零事件 |
| 未接入/证据不足 | 四摘要、后续视图、右侧区域保留目标层级，但无模拟分数、增长、趋势或经营结论 |
| 未绑定/基准无资格 | 竞品事实可排序；我方位置不可计算；依赖基准的 comparison 不生成方向结论 |

异步请求继续使用现有过期响应保护；切组、离页、快速切换范围/排序不得让旧响应覆盖新页面或错误提示。

### 5. 排名与比较业务合同（R1/R2/R3 待确认建议）

本节是供 Review 的明确建议，未经第 8 节确认不得擅自冻结；没有统一“综合排名”。

1. 全组集合 G 为当前 self/own 加当前直接竞品，每条 Offer 一行。停止/下架成员仍计 G 的展示样本数并保留历史。移出组成员不在 G。
2. 指标合格集合 E：G 中 is_active=true、status=active、有最新有效快照且该指标值有效者。status=unknown 即使有旧值也展示排除原因；不把解析失败直接当下架。无快照/未知指标/停止/下架不计 E。MOQ 为正整数，SKU 为非负整数，库存为完整非负总和；报价资格见 R1。
3. N=|E|，包括合格我方；竞品覆盖另明确不含我方。名次采用竞赛排名：1 + 在当前排序方向严格排在其前面的 Offer 数，例如 1、1、3。显示“并列第 3 / 9 个可排名 Offer（MOQ 升序）”，不得显示截图里的 4/8 当真实结论。仅有我方时注明“仅我方 1 条，无直接竞品可对比”。
4. 显示顺序随方向反转；位置标签同步标注指标与方向，不称综合领先。筛选仅改变可见行，不重算 E/N/全组位置；显示“可见 X / 全组 Y”，隐藏我方时仍可展示原全组位置。首期不另建筛选内排名。
5. 无我方绑定或我方不在 E 时，rank=null 并显示具体原因；竞品仍可做单指标排序。相对我方的事实比较继续由 Backend 返回，已有历史 comparison 须标“历史快照比较”，不能当当前位置摘要。
6. 链接展示报价保留完整区间，建议仅在两端存在、非负、min<=max 时按 price_min 排序；仅有一端、倒置或无值为 unknown，不自动复制端点。相同下限并列，最大值不作竞争名次 tie-break。该位置只能称“链接展示报价下限位置”。区间重叠、混合 SKU、数量阶梯和包装运费差异均不能据此宣称同规格更便宜。原区间 lower/higher/overlap comparison 继续保留，排序与区间比较是两个口径。
7. 不设未经确认的过期天数阈值；显示快照时间与非同步采样提示，最近一次失败不改变旧事实。若需要时效排除，必须先确认阈值并修订合同，不能实现时临时猜测。

### 6. 竞争动态与变化证据

时间范围沿用今日、近 7 天、近 30 天，默认 7 天；Asia/Shanghai 业务日期转 UTC 半开区间，包含当天及此前 days-1 个日期。7/30 切换重新读取，不前端从 30 天切片。历史按当前组归属聚合，不宣称事件发生时已属该组；停止监控不删除历史。

第一期“重点”是展示优先级，不是新风险评分：价格 increase/decrease（Offer/SKU 均适用）、MOQ increase/decrease、SKU added/removed 均列为重点；不新增幅度阈值。SKU 库存售罄/恢复属于库存事实，不能等同 SKU 删除/新增。全部模式保留真实库存、生命周期、标题与主图变化；普通库存微动用更弱样式且排在重点区之后，同一类别按 detected_at DESC、id DESC，不用事件条数排序淹没重点。

每条动态显示店铺、商品/Offer、角色、变化类型、原始前值→后值、检测时间及证据入口。SKU 事件保留 entity_key、sku_name；数量增减不能伪造为商品级 SKU 总数变化，只有快照提供总数才可显示相应事实。缺失前后值显示未知而不补 0。视觉分组不能合并/篡改 ChangeEvent，也不从库存或事件数量推成交、增长与竞争力。当前动作计数保留兼容读取，降为次要事实，不作为评分。

### 7. API 合同与职责

继续使用既有只读入口 `GET /api/competitor-groups/{group_id}/detail?days=7|30`；默认 7，非法 days=422，不存在组=404/competitor_group_not_found，未绑定与空组=200。保留原有 group、own_product、summary、competitors、today、action_window 与原字段语义，不能把旧 matched/comparable 计数悄悄换成本期排名覆盖。

最小建议是同一聚合 response 增量增加以下内容，不拆多个模块接口、不逐行取详情；无需增加服务端搜索/筛选参数或未接入经营指标空字段：

| 增量字段 | 必要合同 |
| --- | --- |
| position | 指标键固定为 display_price_min / min_order_quantity / sku_count / total_stock。每指标包含默认方向、全组数、eligible_count、各 Offer 的 eligible、reason、sort_value、rank_asc、rank_desc。报价 sort_value 用十进制字符串，其余用整数；未知/排除时 sort_value 与 rank 为 null。包含我方，默认方向依字段表。 |
| action_window.events | 当前 7/30 天全部真实事件明细；复用 today.events 的 id、Offer 关联、角色、前后值、检测时间、snapshot/run/SKU 标识。不再只有事件计数。按检测时间倒序及 id 倒序，无静默 top-5 截断。 |

position 的指标名与默认方向冻结前由第 8 节确认；reason 至少能区分 not_monitored、offline、status_unknown、no_snapshot、unknown_value。所有 rank 来自同一 Backend 合格集，不由 UI 各自解释价格区间、null 或并列。Backend 返回双向名次与合法 sort_value，Frontend 仅据其进行展示排序、筛选与定位。稳定顺序以 id 升序收尾，资格/缺失优先于数值方向；不另建排名表或缓存持久化。

覆盖信息可由该聚合结果计数；未接入/评分不足文案是固定能力状态而非每个商品的假指标。事件店铺名可通过同响应的成员 id 查得，不能用历史事件去猜企业身份。复用已有快照与事件查询，读取不得写回数据库、采集、重分类或修改历史。新 response 是待实施合同，当前代码没有 position 或窗口事件明细，不能宣称 API 已具备。

### 8. 仍需用户确认的业务规则与 Gate

| 编号 | 建议与关键权衡 | Gate |
| --- | --- | --- |
| R1 | 链接展示报价按完整区间下限排序、同下限并列；仅一端不排名。易解释且复用现有报价，但不代表实际同规格采购价。 | 首期报价排名冻结前确认；不回退到偷偷选择均价/最高价 |
| R2 | 当前排名只含监控中且明确在线的有效事实；停止/下架/未知状态保留展示但不计分母；暂不设过期天数。 | 首期资格合同冻结前确认，避免悄悄扩大样本或临时设阈值 |
| R3 | N 含我方、竞赛排名 1/1/3、方向随表头反转、筛选不重排名；默认 MOQ ↑。 | 首期排名与展示合同冻结前确认；A19 条件满足时我方并列第 3/9 |
| R4 | 综合竞争力维度/权重、归一化、缺失与覆盖门槛、时间窗口、SKU 可比性、景气度与建议触发条件。 | 后续独立规则 Spec；本期始终未就绪，不使用 V0.3 权重 |
| R5 | 新字段真实来源、商品/店铺粒度、单位/窗口、精度、历史增长定义、上架含义、标签归属与消失语义。 | 逐字段 POC + 数据接入 Spec；本期不入库、不计算 |

R1～R3 为本草案建议，不冒充用户已经确认。R4～R5 不阻塞本期未就绪布局及已有事实功能，但禁止绕过 Gate 启用结论。

## Testing Decisions

只测用户可观察行为与合同，优先现有最高 seam，不建立新测试框架。本轮只写检查要求，不增改或执行业务测试；正式实现时执行相应 targeted pytest、Vitest、类型检查/构建及隔离浏览器 QA。复用现有 Backend TestClient + 临时 SQLite 的组详情测试，Frontend 组详情静态/交互测试与 fail-closed Chromium API Mock；受控 Mock 不得访问正式数据库或真实外部采集。

### 1. Backend 合同检查

- 原 404/422、未绑定、空组、成员身份、最新快照、SKU 有效零、完整库存/未知、区间 comparison、业务日边界、当前成员历史语义及 N+1 回归保持。
- position 覆盖默认方向、反转、并列 1/1/3、我方参与且分母含我方、相同店铺两个 Offer、未知/无快照/停止/下架/状态未知原因、仅我方、无我方、我方不合格、全部字段未知。
- 报价覆盖相同下限不同上限、区间重叠、仅一端、倒置、零值、字符串 9 与 100 的数值排序、Decimal 精度；不生成同规格价格名次。
- action_window.events 覆盖 7/30 范围、今日边界、我方与竞品事件、停止成员历史、移出成员排除、前后值/SKU/snapshot/run 关联与原事件计数一致；超过五条仍可追溯全部，不按单品循环请求。
- 读取前后持久化事实一致，不出现评分、成交/增长或标签伪造字段。

### 2. Frontend / 浏览器关键路径

- 进入组分析：双栏桌面、四摘要、四 Tab、店铺主身份与我方标识、未接入状态；无演示切换、独立排序下拉/方向按钮、虚构分数条。
- 同一就绪表头连续点击默认/反向；切换其他列及四视图；箭头、高亮、aria-sort 与真实行序一致；未知始终末尾，并列不因稳定顺序变成不同名次。我方不固定首行。
- 搜索 + 状态过滤 + 重要变化组合，名次与全组分母不变；定位我方、被隐藏时清除条件后定位、无我方提示；同店铺多 Offer 不合并。
- 真实商品入口/快检/字段依据/事件证据均对应所选 Offer，我方也可进入详情；缺失锚点如实显示事件标识，不冒称精确定位。
- 动态重点优先、库存微动弱化但全部可见；重点为空与全部为空区分；7/30 请求与失败保留正确窗口；切组/离页旧请求不能覆盖新结果。
- Loading、Empty、Partial、首次错误、404、刷新失败及全未接入视图；不出现零成交、伪覆盖率与旧请求成功时间。
- 浏览器采用现有默认拒绝 `/api/**` 的隔离策略，显式声明组详情/单品详情响应，未声明请求即失败。关键排序/定位/证据路径在真实挂载 UI 验证，不只断言 helper 返回值。

### 3. A19 真实业务验收与视觉检查

输入仅使用用户确认事实：我方 1 条 Offer、直接竞品 8 条；我方 MOQ=2，两个竞品 MOQ=1。其他 MOQ、价格、SKU、库存、状态与时间须从实际 API/详情核实，不把截图中的示例商家、分数、报价、月成交、增长或日期当事实。自动测试可用明确标注的受控边界 fixture，不能替代真实验收。

| 验收操作 | 预期 |
| --- | --- |
| 打开 A19，核对成员与详情 | 我方 1、竞品 8，全组 9；不将 8 当含我方分母 |
| 点击 MOQ ↑ | 两条 MOQ=1 Offer 在我方之前；若九条均符合 R2 且其余无更低 MOQ，则我方并列第 3/9；不猜其余事实 |
| 再点 MOQ ↓，定位我方 | 真实反向序列，缺失末尾，我方身份与定位保留 |

| 按展示报价并检查混合 SKU/重叠 | 展示下限口径与完整区间，不给同规格价格排名 |
| 打开真实价格/MOQ/SKU 变化 | 前后值、检测时间与单品证据一致；未发生事件时正确空状态，不造事件 |
| 切换经营/口碑/标签 | 明确待接入，没有精确成交排序、增长或生产评分 |

人工检查宽桌面（如 1440px viewport）在现有 Sidebar 下仍为主辅双栏，常见桌面（如 1280px）信息可读，窄窗口（如 800px）可重排且仅宽表横向滚动；不要求完整移动客户端。检查末行、focus、长店铺名/Offer、未知提示与证据入口不被裁切。像素尺寸为验证样例，不是新增全局断点合同。
