# 组内竞争情报与竞争位置 V1

> 状态：已通过 ChatGPT Final Spec Review / 已 Freeze；本轮已实施，最新 UI 已由用户验收。完整验证结果见最终收尾报告。
> 冻结基准：`7bd49355df7ca19a1de2835c0280d140a76b624f`（2026-10-09）。
> 日期：2026-10-09。第一期交付已有事实的位置分析与目标 UI；本轮业务实现及满足收尾门槛后的 Commit / Push 已获用户授权。
> 本文使用 to-spec 的结构化业务与测试合同，不执行 Issue Tracker 发布流程。

## Problem Statement

运营者在选定商品组内需要快速回答：我方在某个真实指标下处于什么位置，具体哪些 Offer 有差异，最近发生了哪些值得检查的变化，证据在哪里。冻结时的组详情提供真实差距计数与事件动作，但我方固定第一行、没有指标排序，经营指标与综合评分尚不可用。逐个打开详情自行拼接结论效率低，也容易把库存变化、展示低价或精选样本误读为销量、同规格优势或市场结论。

## Solution

把现有 Group Detail 升级为 PC Web 优先、兼容窄浏览器窗口的组内竞争情报工作台，继续使用 React + FastAPI、现有导航与浅色蓝紫 UI。以 Offer 横向比较主表为核心，配合真实竞争动态、右侧事实快检和证据缺口。第一期真实启用店铺名、链接展示报价、MOQ、SKU、完整库存、变化历史、Offer 比较和单指标组内位置。

四项分析摘要、经营判断与综合竞争力区域保留确认的目标布局；真实能力未接入时明确显示“待接入 / 证据不足”。成交、增长、上架时间、口碑履约、收藏和标签须逐字段 POC 与后续 Spec 才能启用。V0.3 模拟分数、权重、增长率、情景和结论均不得进入生产。

成功条件：以真实 A19 组验收，用户约 5～10 秒内找到我方 MOQ 位置、两条 MOQ=1 的竞品及其证据；按真实指标排序后我方处于真实位置；能找到重要变化的前后值与检测时间。失败条件：硬编码 A19、假数值、伪排名、将样本称作全市场、让库存微动淹没真实价格/MOQ/SKU 变化。

## User Stories

1. 作为运营者，我希望看到组名、我方数、直接竞品数与样本口径，以便知道分析覆盖范围。
2. 作为运营者，我希望看到最近采集与各字段覆盖，以便判断证据是否完整。
3. 作为运营者，我希望同时看到主表和辅助判断，以便减少纵向翻找。
4. 作为运营者，我希望以真实店铺名识别 Offer，以便找到具体对手而不误合并同店商品。
5. 作为运营者，我希望切换三种字段视图，以便按任务观察而不一次塞满所有列。
6. 作为运营者，我希望直接点击列标题排序并再次反转，以便快速找我方位置。
7. 作为运营者，我希望看到当前排序方向、参与数、并列和未知原因，以便正确理解名次。
8. 作为运营者，我希望我方参与排序且能快速定位，以便避免虚假的第一行。
9. 作为运营者，我希望搜索店铺、商品或 Offer 并筛选真实条件，以便缩小检查对象。
10. 作为运营者，我希望筛选不暗改全组名次，以便不误读当前结果。
11. 作为运营者，我希望区间报价保持原文与语义，以便不误判同规格价格。
12. 作为运营者，我希望看到停止监控、下架、未知及无快照状态，以便区分历史与当前事实。
13. 作为运营者，我希望重要动态先出现且普通库存变化可查，以便降噪而不丢事实。
14. 作为运营者，我希望从动态与字段进入现有单品证据，以便核验来源。
15. 作为运营者，我希望右侧快检展示选中 Offer 的真实事实，以便检查单品。
16. 作为运营者，我希望未接入的成交、增长和评分明确标记，以便不被演示结论误导。
17. 作为运营者，我希望局部加载失败保留上一份事实并提供重试，以便继续检查而不把失败视作零值。
18. 作为运营者，我希望窄窗口可读、表格局部滚动、键盘可操作，以便持续使用 Web 工作台。

## Implementation Decisions

### 1. 文档效力与分期

- 冻结时的文档阶段仅修订 Spec、直接索引与原始原型参考图片，纯 Spec Commit / Push 当时已获授权；本轮实现与收尾授权以本文开头状态为准。
- 本文经独立 Review 并冻结后，才作为实现合同。第 8 节 R4～R5 后续 Gate 不得在实现阶段自行绕过；评分与新数据独立后续 Gate 不阻塞已有事实能力。
- 冻结后明确替代旧 Group Detail 的“我方固定第一行”、旧大基准/差距首屏、动作数排行作为主要动态区及仅纵向页面结构；其余快照、比较、时区、成员关系、错误与查询规则继承。旧 Spec 原文保留。
- 冻结时 UI System 中“排名尚未实施”描述当时基线；本轮已有事实的单指标位置分析已实施。导航融合与全局视觉重构仍不在范围内。
- 重构计划与研究中的公司主体优先、独立指标选择控件、仅已接入视图等建议，按本轮明确要求收敛为店铺主显示、表头排序、三种目标视图及未接入状态；不得直接搬用研究草案。

### 2. 冻结时实现基线与最小变更边界

冻结时已核验的实现基线：组详情单一聚合读取，返回 own、直接竞品、最新快照、Backend comparison、summary、今日事件和 7/30 天动作统计；Frontend 用内部 Page state 和请求序号防止过期响应覆盖。当时表固定我方首行；今日提供事件明细，7/30 天仅动作计数，不足以直接展示窗口内前后值；当时我方详情按钮缺失，需要复用单品入口补齐。

现有身份以 ownership 为准、group_id 表示当前归组、group_role 表示兼容角色。每组至多绑定一个 self/own；当前直接竞品为当前组内 ownership=competitor 的 Offer，不凭店铺名或标题猜身份。

后续实现仅扩展现有组详情只读聚合、response contract、对应页面及 scoped 样式和直接测试。复用 Snapshot、SkuSnapshot、ChangeEvent、单品详情、业务日期工具、已有 UI 组件与浏览器 API Mock。不得新增数据库表/字段/迁移、采集器、评分服务、调度器、依赖、Router 框架或独立服务、状态框架或持久化用户偏好。批量查询避免 N+1；不按行请求单品详情来拼主表。

### 3. 数据事实与就绪状态

Offer 是比较与排序单位，以 platform + offer_id 识别，行关联现有商品 id。同店铺多个 Offer 分别保留，不累计、合并或去重。店铺名仅为来源展示名，不认证企业主体；缺失显示“店铺未采集”，辅以商品名和 Offer ID。

排名与事实展示均基于每条商品最近一次有效快照，沿用 captured_at DESC、id DESC；各商品采集时刻可能不同，不是实时同步报价。last_collected_at 与有效快照时间分开解释；失败不能生成新事实或覆盖历史。商品级价格字符串按十进制数值比较，不按字符串字典序排序。SKU 数是最新快照的实际 SKU 行数，有快照的 0 有效；无快照不可补 0。库存仅当存在 SKU 且全部 stock 非负且非 null 时求和，未知不补零。

| 状态 | 页面语义 | 排序/评分 |
| --- | --- | --- |
| READY | 已接入且该 Offer 有有效、同口径事实 | 只允许本期就绪指标排序；本期均不评分 |
| UNKNOWN | 已接入但该字段缺失或无法确定 | 无名次，末尾显示未知原因 |
| NO_SNAPSHOT | 从未获得有效快照 | 显示未采集，不能补零 |
| NOT_INTEGRATED | 数据能力尚未正式接入 | 显示待接入；表头不可排序 |
| INSUFFICIENT_EVIDENCE | 分析所需来源/历史/规则不足 | 显示证据不足；无分数或结论 |
| 历史事实 | 已停止、已下架或当前在线状态未知的最后有效值 | 展示时间与排除原因，不计当前名次（已确认 R2） |

以上是显示与只读派生语义，不要求增加通用状态引擎或数据库枚举。NOT_INTEGRATED 不得伪装成全部商品恰好 null；标签未接入不表示“无标签”。成交档位如 `<10`、`100+` 保留原文，不能强转成 10 或 100 排序、求均值、增长或计分；本期不接入此数据。

### 4. 目标 UI 与第一期落地边界

#### 4.1 页面区域、层级和信息密度

A. 顶部沿用 AppShell、面包屑和 PageHeader，保留组名主标题及唯一一行副信息“1 条我方商品 · 8 条竞品 · 仅监控样本，非实时报价”（数量动态生成，我方为 0/1，竞品不含我方、含停止/下架成员）。不再展示顶部独立的最近采集时间、报价口径及各指标可排名数说明行；具体有效快照时间和各指标可排名数/全组 Offer 数在商品速览查看，相关表格区域保留排序与全组分母说明。

B. 四项摘要依次为：组内经营景气信号；我方综合竞争力及组内位置；竞品成交与增长数据覆盖；当前经营决策提示。第一期景气“证据不足”；综合竞争力“待接入：评分规则未冻结”，下方可独立显示真实单指标位置；成交/增长“待接入”，不能展示模拟覆盖分子；经营提示“证据不足”，提供核查入口，不能给加码/放弃/调价结论。摘要紧凑排列，窄屏可折行，不用大块空白撑高页面。

C. 核心区在足够宽的桌面内容区为双栏，左栏较宽，包含主表和真实动态；右栏包含经营判断/关键证据/建议，以及综合竞争力/评分拆解/单品快检。前两类分析及评分拆解本期显示未就绪理由与缺口，不生成进度条、雷达图或虚构权重。快检显示选中 Offer 的报价、MOQ、SKU、完整库存、状态、时间、当前事实差异及详情入口，默认选择我方；无我方时显示“未建立我方基准”，可选择竞品检查其事实。

D. 桌面不能把所有模块简单纵向堆叠。窄窗口可折为单栏，主表优先，右侧辅助在后；宽表局部横向滚动，不产生整个 shell 横向溢出，不靠缩小字体硬塞。使用既有字号、spacing、卡片、浅色蓝紫语义及主滚动容器；表头与身份应易找，滚动不能遮挡按钮或末行。A19 九条 Offer 应能紧凑扫描，不强制一次铺开三个视图所有字段，主对比表不新增分页系统；历史事件使用第 7 节的有界继续加载。

#### 4.2 三种视图与字段状态

仅保留“竞争总览 / 经营表现 / 口碑履约”三个视图。平台标签不单独占用视图，在竞争总览“店铺”列后以紧凑列展示，标题标注“待接入”，未接入时各行显示“—”，不显示“无标签”。未来真实数据接入后每行最多显示两个紧凑标签，其余显示 `+N`；本期不新增标签采集或数据逻辑。未接入字段不可排序，保留明确状态；不创建数据库空列或假数据。

| 视图 | 字段 | 第一期状态及默认排序方向 |
| --- | --- | --- |
| 竞争总览 | 店铺、平台标签（标题注明待接入） | 店铺列单行展示；完整 Offer 身份见选中后的商品速览，本期不设身份排名；标签当前各行显示“—”，不可排序，不代表无标签；真实接入后最多显示两个标签，其余显示 `+N` |
| 竞争总览 | 竞争力 | NOT_INTEGRATED，不可排序 |
| 竞争总览 | 链接展示报价 | 已有 price_min/price_max；按有效完整区间下限升序（已确认 R1） |
| 竞争总览 | MOQ | 已有 min_order_quantity，升序 |
| 竞争总览 | SKU | 已有 sku_count，降序；数量不代表质量优势 |
| 竞争总览 | 月成交、增长 | NOT_INTEGRATED，不可排序 |
| 经营表现 | 上架时间、月成交、月代销、年成交件数、年成交笔数、增长 | 全部 NOT_INTEGRATED，不可排序；时间窗口、单位和粒度待 POC |
| 口碑履约 | 评论数、好评率、揽收率、收藏数 | 全部 NOT_INTEGRATED，不可排序；店铺级字段须标归属 |

本期竞争总览另保留紧凑“库存”事实列及详情操作，库存可按完整值降序做事实排序，不能称库存竞争力。按用户已确认的视觉设计调整，三个视图的店铺列只显示单行店铺名称、保持 54px 行高；我方仅以店铺名称加粗、加深颜色区分，不使用特殊整行背景、蓝色边框或左侧身份标识，其他字段保持正常样式，不恢复多行标题、Offer ID、时间或我方 Badge。行悬停仅有轻微背景反馈，键盘聚焦保留清晰焦点样式，不显示详细信息弹窗或原生 title 替代提示；点击或 Enter/Space 选中后，右侧商品速览展示该 Offer 的完整身份、快照时间、状态与事实依据。同店不同 Offer 独立选中，不按店铺合并。此调整仅改变展示位置，不改变 R1～R3 或 Backend 数据合同。平台标签仅在竞争总览列展示，不参与排序、筛选或评分。

#### 4.3 表头排序与我方位置

- 删除独立“排序指标”下拉框和“升序/降序”按钮。仅就绪的数值列标题提供可点击按钮；第一次点击使用上表默认方向，再次点击同列反转，切换新列恢复该列默认方向。
- 当前排序列高亮并显示 ↑ / ↓；语义分别为升序/降序。使用表头 aria-sort、键盘 Enter/Space 与可见 focus；未接入列没有可操作排序按钮并解释原因。
- 首次进入竞争总览默认 MOQ ↑（已确认 R3）。切换视图保留搜索与筛选及已选 Offer；当前排序列在新视图不存在/未就绪时，新视图按稳定身份顺序显示、无活动排序箭头与指标位置，返回总览恢复最后合法排序。无本地持久化。
- 我方和竞品参加同一真实排序；不得 pin 我方第一行。相等主值按现有 id 升序稳定展示，但名次保持并列；反转方向不反转缺失区，也不制造并列中的先后竞争名次。
- 未知、无快照、停止、下架等无当前名次行始终在已参与排序行之后，末尾按 id 升序；保留历史事实和排除理由，不能依历史值冒充当前排名。
- “定位我方”选中我方 Offer，让现有主滚动容器将目标行滚入可视区域，不改变排序、表格横向位置或浏览器窗口滚动。表格无内部纵向滚动，不使用 `.table-scroll.scrollTop` 定位。仅在我方确实被搜索/筛选隐藏时显示紧凑行内状态“当前筛选未显示我方商品”，采用浅蓝灰背景、轻量信息图标及右侧文字操作“清除筛选并定位”；点击后清除筛选、选中我方并滚动定位，正常表格不预留提示空间；不能悄悄绕过过滤。无绑定时显示原因而不定位竞品。矮视口及我方末尾场景须断言目标行边界进入主容器与视口可视范围。

#### 4.4 搜索、必要筛选、详情与证据路径

搜索匹配店铺名、商品标题和 Offer ID，trim 后大小写不敏感子串匹配，不搜企业身份。条件组合为 AND。本期仅提供监控状态（全部/监控中/已停止）、商品状态（全部/在线/下架/未知）及“仅看重要变化”；不添加未接入的成交、标签筛选与复杂保存查询。

“仅看重要变化”针对当前今日/7/30 天窗口中有价格、MOQ 或 SKU 事件的 Offer；与动态区的“重点/全部”使用同一定义。默认关闭，动态默认重点。该过滤使用 Backend 对完整窗口派生的 important_offer_ids，不能从事件首屏或已加载页推断。时间切换成功后才更新这一过滤，失败保留原窗口和提示。搜索/行状态筛选只过滤主表，不隐式改变全组动态和覆盖统计；动态保留全组范围标识。

点击商品行选中对应 Offer 并更新右侧商品速览；行可通过 Tab 聚焦，Enter/Space 选中。操作列仅保留“查看详情”，点击或键盘激活该按钮直接打开现有单品 Detail，不触发行选中，我方与竞品都支持。选中态独立于我方身份，以统一极浅高亮覆盖全部单元格及 sticky 操作列，不使用深色整行背景、整行描边或左侧标识；普通悬停轻微变色，我方身份仅通过店铺名称加粗、加深颜色区分。操作列收窄，保持 54px 行高及现有排序、筛选、横向滚动和滚轮行为。字段说明展示来源快照 id、captured_at、原始区间/值、指标口径与排除原因，并提供现有详情入口，不要求新增第二份单品详情页。变化证据使用 event id、snapshot_id、collection_run_id 与检测时间定位事实：详情页没有事件锚点时也必须保留所选事件的前后值和关联标识，不能声称跳转已精确定位历史。

#### 4.5 状态合同

| 状态 | 必须呈现的行为 |
| --- | --- |
| Loading | 首次加载真实 loading，不能先显示假数值；范围更新局部 loading，保留上份事实 |
| Empty | 空组/无直接竞品/仅我方分开表达；搜索无结果提示清除条件；重点无事件提示可看全部，不等于完全无变化 |
| Partial | 已有事实照常显示，缺失字段明示；覆盖分母保持全组，不把缺失当零 |
| Error | 首次失败显示重试；404 显示组不存在与返回入口；刷新失败保留旧数据并注明失败/时间，不能更新成功时间或显示零事件 |
| 未接入/证据不足 | 四摘要、后续视图、右侧区域保留目标层级，但无模拟分数、增长、趋势或经营结论 |
| 未绑定/基准无资格 | 竞品事实可排序；我方位置不可计算；依赖基准的 comparison 不生成方向结论 |

异步请求继续使用现有过期响应保护；切组、离页、快速切换范围/排序不得让旧响应覆盖新页面或错误提示。

### 5. 排名与比较业务合同（R1/R2/R3 已确认）

R1～R3 已由产品负责人正式确认，以下为确定业务合同；整份 Spec 仍待 Final Review 后冻结。没有统一“综合排名”。

1. 全组集合 G 为当前 self/own 加当前直接竞品，每条 Offer 一行。停止/下架成员仍计 G 的展示样本数并保留历史。移出组成员不在 G。
2. 指标合格集合 E：G 中 is_active=true、status=active、有最新有效快照且该指标值有效者。status=unknown 即使有旧值也展示排除原因；不把解析失败直接当下架。无快照/未知指标/停止/下架不计 E。MOQ 为正整数，SKU 为非负整数，库存为完整非负总和；报价资格见 R1。
3. N=|E|，包括合格我方；竞品覆盖另明确不含我方。名次采用竞赛排名：1 + 在当前排序方向严格排在其前面的 Offer 数，例如 1、1、3。显示“并列第 3 / 9 个可排名 Offer（MOQ 升序）”，不得显示截图里的 4/8 当真实结论。仅有我方时注明“仅我方 1 条，无直接竞品可对比”。
4. 显示顺序随方向反转；位置标签同步标注指标与方向，不称综合领先。筛选仅改变可见行，不重算 E/N/全组位置；显示“可见 X / 全组 Y”，隐藏我方时仍可展示原全组位置。首期不另建筛选内排名。
5. 无我方绑定或我方不在 E 时，rank=null 并显示具体原因；竞品仍可做单指标排序。相对我方的事实比较继续由 Backend 返回，已有历史 comparison 须标“历史快照比较”，不能当当前位置摘要。
6. 链接展示报价保留完整区间，仅在两端存在、非负、min<=max 时按 price_min 排序；仅有一端、倒置或无值为 unknown，不自动复制端点。相同下限并列，最大值不作竞争名次 tie-break。该位置只能称“链接展示报价下限位置”。区间重叠、混合 SKU、数量阶梯和包装运费差异均不能据此宣称同规格更便宜。原区间 lower/higher/overlap comparison 继续保留，排序与区间比较是两个口径。
7. 排名基于每条商品最近一次有效快照，而非实时同步报价。选中行后，字段依据和商品速览保留 snapshot id 与该快照 captured_at；不同商品可能采集于不同时刻，页头唯一副信息常驻说明“仅监控样本，非实时报价”，不额外占用顶部说明行。采集失败不覆盖历史，也不刷新有效快照时间。本期不设置 3 天、7 天等强制过期阈值；快照较旧本身不改变 R2 资格，资格仍依监控状态、明确在售状态及合法事实。若未来需要时效排除，先修订 Spec，不能实现时临时猜测。

### 6. 竞争动态与变化证据

时间范围沿用今日、近 7 天、近 30 天，默认 7 天；Asia/Shanghai 业务日期转 UTC 半开区间，包含当天及此前 days-1 个日期。7/30 切换重新读取，不前端从 30 天切片。历史按当前组归属聚合，不宣称事件发生时已属该组；停止监控不删除历史。

第一期“重点”是展示优先级，不是新风险评分：价格 increase/decrease（Offer/SKU 均适用）、MOQ increase/decrease、SKU added/removed 均列为重点；不新增幅度阈值。SKU 库存售罄/恢复属于库存事实，不能等同 SKU 删除/新增。默认重点模式只查询重点事件，防止库存微动淹没首屏。全部模式保留真实库存、生命周期、标题与主图变化，统一按 detected_at DESC、id DESC 排序；普通库存微动用更弱样式，重点事件保留明确标识，不按事件条数排序。全部模式不按类别重排跨页记录，以保证稳定的时间序列。

每条动态显示店铺、商品/Offer、角色、变化类型、原始前值→后值、检测时间及证据入口。SKU 事件保留 entity_key、sku_name；数量增减不能伪造为商品级 SKU 总数变化，只有快照提供总数才可显示相应事实。缺失前后值显示未知而不补 0。视觉分组不能合并/篡改 ChangeEvent，也不从库存或事件数量推成交、增长与竞争力。当前动作计数保留兼容读取，降为次要事实，不作为评分。

### 7. API 合同与职责

#### 7.1 组事实聚合与有界首屏

继续使用 `GET /api/competitor-groups/{group_id}/detail?days=7|30`；默认 7，非法 days=422，不存在组=404/competitor_group_not_found，未绑定与空组=200。保留 group、own_product、summary、competitors、today、action_window 的事实与计数语义，不把旧 matched/comparable 计数换成本期排名覆盖。明确替代旧今日明细无界返回合同：today.events 只返回今日全部模式第一批 20 条，并附 today.event_pagination（与下述 event_page 的 has_more、next_cursor、range=today、mode=all、limit=20 及窗口/筛选上下文同义），旧今日计数仍是完整今日计数，不能改成首批条数。主 UI 统一消费 event_page，不依赖 today.events 判断历史是否完整。

组详情增加以下最小只读派生字段，不增加经营指标空列：

| 增量字段 | 必要合同 |
| --- | --- |
| position | 指标键固定为 display_price_min / min_order_quantity / sku_count / total_stock。每指标含默认方向、全组数、eligible_count、每 Offer 的 eligible、reason、sort_value、rank_asc、rank_desc。报价为十进制字符串，其余为整数；排除时 sort_value、rank 为 null。N 包括合格我方，默认 MOQ 升序；双向名次按 R3 分别计算，不能简单用 N+1-rank 反转并列。 |
| event_page | 与 7.2 完全一致的有界首批响应；默认当前 days 窗口、mode=important、limit=20。不得增加无界 action_window.events。 |
| action_window.important_offer_ids | 完整 7/30 天窗口内有重点事件的 distinct 当前成员 id，包含我方；与明细是否已加载无关，供表格“仅看重要变化”使用。今日模式对应 today.important_offer_ids。 |

reason 至少区分 not_monitored、offline、status_unknown、no_snapshot、unknown_value。Backend 权威给出资格、合法排序值与双向名次，Frontend 只展示排序/筛选/定位。每行快照时间继续取 latest_snapshot.captured_at，position 不创建新的“实时报价时间”；双向排序按 id 稳定收尾，未知始终末尾，不建排名表。

#### 7.2 按需历史事件继续加载

新增一个必要的只读路由，挂在现有组详情 router 内：`GET /api/competitor-groups/{group_id}/events?range=today|7|30&mode=important|all&limit=20&cursor=...`。这是现有组事件查询的分页边界，不是独立模块服务；不重复获取整组事实，不新增数据库结构、依赖或持久化游标会话。

- range 默认 7，mode 默认 important，limit 默认 20、允许 1～100。非法枚举/limit/游标返回 422；不存在组返回同一 404。省略 cursor 为首批；继续加载须原样带回 cursor，并保持 group、range、mode、limit 一致，参数不匹配为 422，不静默重置。
- range=today 使用今日业务日，7/30 含今天及前 days-1 个日期，均用 Asia/Shanghai 日期转换 UTC 半开区间。mode=important 仅第 6 节价格/MOQ/SKU 类型，mode=all 保留所有原始事件。组成员按当前归属，不受 R2 排名资格过滤，停止/下架历史仍可检查；主表搜索/状态条件不传入此接口，动态明确标“全组”。本期不新增事件类型、店铺或关键词高级筛选。
- 返回 `items, has_more, next_cursor, range, mode, limit, window_start, window_end, through_event_id, important_offer_ids`；每批最多 limit 条，has_more=true 必有非空 next_cursor，末批 has_more=false 且 next_cursor=null。important_offer_ids 是同一固定窗口/事件上界内全部重点事件的成员集合，独立于 mode 与当前页；今日切换成功后用此响应同步主表重要变化过滤，不能沿用昨日的聚合集合。空窗口 items=[]、important_offer_ids=[]、through_event_id=0（若无已有事件），不得以空值伪造事件。UI 明示“已加载 X 条，仍有更多”并给“继续加载”；末批显示“已加载当前窗口全部符合条件的事件”，切到 all 才能声称查看窗口完整历史，无全量响应或静默 top-5 截断。
- 每条 item 复用现有事件 payload：id、competitor_id、role、title、offer_id、snapshot_id、collection_run_id、change_type、entity_key、sku_name、old_value、new_value、delta_value、delta_rate、detected_at，并带真实 shop_name 供此独立响应身份展示。保留一条原始事件一条记录及证据，不合并或改写。值缺失不补零。
- 稳定顺序是 detected_at DESC、id DESC，使用同一 UTC 时间精度比较，游标不得舍入检测时间。游标续查严格小于上一批末条 `(detected_at, id)`，不是 offset；用 limit+1 判定是否还有更多。首批固定 window_start/window_end 和 through_event_id（首批查询开始时的已有事件 id 上界），后续带回同一上下文并限定 id<=through_event_id，跨午夜或并发插入不移动窗口、不让新事件插入本轮历史；刷新/重新选条件重新开始才能纳入新事件。
- 游标仅编码必要的窗口、事件上界、末条键、group/range/mode/limit 与成员身份上下文，必须验证结构、时间/数值合法性及条件一致，不能作为任意 SQL 条件。组成员/角色变化导致上下文失效时返回 409/group_event_context_changed，UI 提示重新加载当前历史；不创建成员历史表或保存分页会话。永久删除的事实无法由分页复原，不宣称事务快照；原始历史不因该读取路径改变。
- detail 的 event_page 和 events 接口共用同一查询/组装逻辑及游标合同。今日兼容明细也必须有边界，不能一边分页 7/30 明细、一边无界返回今日。同一首批上下文的计数与 important_offer_ids 使用相同窗口/事件上界；既有今日/窗口计数与 important_offer_ids 按完整窗口由数据库聚合，不加载所有事件到 Python 后再切页；SKU 名称/证据恢复仅批量读取本批所需事实，避免 N+1。

#### 7.3 页面加载与兼容边界

首次组详情直接携带默认 7/30 天重点首批，不预取全部历史；今日兼容首批也有界，不由主 UI 另行预取其后续页；选择今日、切换重点/全部按需请求 events 首批，7/30 切换继续重读对应 detail 并使用其重点首批。范围切换成功后重置明细模式为重点并清空旧游标，保持页面明确展示实际范围/模式；重要变化过滤的定义不随事件 mode 改变；每次成功获得新首批后，使用该响应的固定窗口/上界与 important_offer_ids 同步过滤，避免并发新增时混用两份上下文。继续加载只追加同一上下文，按 event id 去重防止重复提交响应追加；加载失败保留已显示事件与游标，提供原批重试，不显示“全部加载完成”。快速切换/离页旧响应不得追加到新列表。

本期页面不请求未分页的全部历史。today.events 的有界化为本文明确覆盖的旧局部合同，现有调用与相关测试在正式实现时同步更新；今日/窗口总计数和动作统计语义仍保留。事件 paging 上下文与最近有效商品快照是不同概念，不能把 through_event_id 当报价刷新证据。读取不写库、不触发采集、不修改历史；冻结时基线代码没有 position、event_page 或分页 events 路由；本轮已按此合同实施。

## Testing Decisions

### 1. Backend 合同检查

- 原 404/422、未绑定、空组、成员身份、最新快照、SKU 有效零、完整库存/未知、区间 comparison、业务日边界、当前成员历史语义及 N+1 回归保持；今日明细按本期明确覆盖的有界合同更新断言，今日总计数不变。

- 店铺列单行、54px 行高、我方仅店铺名称加粗、加深颜色区分，选中态独立使用极浅高亮；悬停和聚焦不显示弹窗，选中后商品速览保留完整身份、有效快照 captured_at、状态、适用的排名排除原因和事实依据，同店不同 Offer 可独立选中。跨商品不同时间可核验，非实时同步说明常驻；失败后不伪造更新时间，表头降序选择 Backend 对应方向名次而非算术反转并列。
- Loading、Empty、Partial、首次错误、404、刷新失败及全未接入视图；不出现零成交、伪覆盖率与旧请求成功时间。
- 浏览器采用现有默认拒绝 `/api/**` 的隔离策略，显式声明组详情/分页事件/单品详情响应，未声明请求即失败。关键排序/定位/证据路径在真实挂载 UI 验证，不只断言 helper 返回值。

### 3. A19 真实业务验收与视觉检查

输入仅使用用户确认事实：我方 1 条 Offer、直接竞品 8 条；我方 MOQ=2，两个竞品 MOQ=1。其他 MOQ、价格、SKU、库存、状态与时间须从实际 API/详情核实，不把截图中的示例商家、分数、报价、月成交、增长或日期当事实。自动测试可用明确标注的受控边界 fixture，不能替代真实验收。

| 验收操作 | 预期 |
| --- | --- |
| 打开 A19，核对成员与详情 | 我方 1、竞品 8，全组 9；不将 8 当含我方分母 |
| 点击 MOQ ↑ | 两条 MOQ=1 Offer 符合 R2 时在我方之前；若九条均符合 R2 且其余无更低 MOQ，则我方并列第 3/9；不猜其余事实 |
| 再点 MOQ ↓，定位我方 | 按严格更大 MOQ 数重新得到降序竞赛名次，不能用 N+1-rank 反转并列；缺失末尾，我方身份与定位保留 |
| 搜索其中一店铺/开启重要变化 | 可见数变，全组资格/名次不变；能清除条件定位我方 |
| 按展示报价并检查混合 SKU/重叠 | 展示下限口径与完整区间，不给同规格价格排名 |
| 打开真实价格/MOQ/SKU 变化 | 前后值、检测时间与单品证据一致；未发生事件时正确空状态，不造事件 |
| 查看快照时间与历史继续加载 | 每 Offer 有最近有效快照时间及非实时说明；重点首批有界、全部可继续加载至末批，前后值/证据保留；真实数据不足以产生多页时用隔离 fixture 验证分页，不造正式事件 |
| 切换经营/口碑/标签 | 明确待接入，没有精确成交排序、增长或生产评分 |

人工检查宽桌面（如 1440px viewport）在现有 Sidebar 下仍为主辅双栏，常见桌面（如 1280px）信息可读，窄窗口（如 800px）可重排且仅宽表横向滚动；不要求完整移动客户端。检查末行、focus、长店铺名/Offer、未知提示与证据入口不被裁切。像素尺寸为验证样例，不是新增全局断点合同。
