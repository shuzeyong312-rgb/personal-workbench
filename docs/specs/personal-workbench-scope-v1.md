### 升级与外键事务

- 在 `20261030_22` 后追加向前迁移。现有 `21` 库在一次升级中执行 `22` 和退役 revision，现有 `22` 库只执行退役 revision。两条路径均使用同一 SQLite 连接，在发出 `BEGIN IMMEDIATE` 前启用 `PRAGMA foreign_keys=ON` 并读回 `1`，取得写锁后复核版本及结构。退役 revision 在第一条删除 DDL 前再次断言当前连接处于活动写事务且外键为 `1`。外键或事务状态不符时拒绝执行。
- 对现有 `21`/`22` 库，从写事务开始到退役 DDL、完整性检查和 Alembic 版本更新全部成功，仅提交一次。不得切换外键、使用 `autocommit_block()` 或提早提交。按外键顺序先删除依赖表，例如证据与审计先于报价版本，价格先于旧商品及来源。发现未知结构、保留对象引用退出表、历史升级失败或完整性异常时回滚全部变更。`21` 路径回滚时也撤销 `22` 产生的快照和版本变更。
- 首次安装从不存在或无应用对象的 SQLite 数据库重放历史迁移。旧 revision 使用 `autocommit_block()`，因此整段历史重放允许有提交边界。完成历史重放后，在进入退役阶段前确保前段事务已经结束，重新在事务外启用并确认外键，再以独立写事务执行退役 DDL、完整性检查和版本更新。若首次安装中断并留下部分结构，下次普通运行将其视为已存在的库，拒绝自动继续退役。保留旧 revision 的校验和重放能力，禁止手工标记 revision 或清洗旧价格数据以绕过校验。

### 显式切换与拒绝条件

- 普通 `alembic upgrade head` 遇到已存在且尚未退役的工作库时，在执行任何 revision 前拒绝运行，返回非零退出码和操作提示。`dev.ps1` 传播该失败并停止启动。直接启动后端时，同样在采集恢复、调度启动和 API 对外服务前拒绝旧版库或缺少有效 revision 的库。普通首次安装由 Alembic 初始化，新库成功到达退役 revision 后才启动应用。已切换库可正常执行普通升级与启动。
- 通过 Alembic 显式切换入口开启本次操作，建议使用 `alembic -x retire_legacy_modules=1 upgrade head`。放行仅适用于在线 SQLite 升级，且已识别目标库和已验证的 `21`/`22` 起点。启动脚本不传入该参数，其他命令或常驻配置不能隐式放行。未知 revision、无版本但已有应用对象的库，以及无法执行连接检查的离线 SQL 模式均不允许退役。放行和拒绝规则由 Alembic 层执行，覆盖手工调用。

### 停写验收与恢复边界

1. 先用临时库及工作库副本演练。正式切换时停止应用、调度器和其他写入方，确认目标路径和版本。使用 SQLite 在线备份接口制作临时恢复点，并在另一文件中验证恢复后的版本、结构和完整性。
2. 执行显式切换后保持停写，用只读连接逐项确认退役 revision、21 张目标表及相关对象均已清除、`integrity_check` 为 `ok`、`foreign_key_check` 为空，并将保留表的数据、键和约束与恢复点比对。需要启动应用的冒烟验收在隔离副本上完成。正式工作库的停写验收不启动后端，单独禁用调度器仍会执行启动恢复。
3. 任一检查失败且保留业务尚未恢复写入时，可使用临时恢复点与匹配版本的旧代码恢复。所有停写检查通过后，先结束可整库恢复的窗口，再放行后端启动或其他写入。之后清理本次创建的临时恢复点与演练副本。自放行写入起，即使恢复点文件尚在，也不得直接覆盖当前库。如需回退，先再次停写并保全当前库及保留业务增量，再据实决定恢复和补回方式。退役迁移不提供空表 downgrade。

| 场景 | 通过条件 |
| --- | --- |
| 现有库显式升级 | 分别对含数据的 `21` 和 `22` 库执行显式切换。断言 `BEGIN IMMEDIATE` 前已读回外键为 `1`，退役 DDL 执行时同一连接上外键为 `1` 且写事务仍活动。覆盖产品、导入回执、报价证据、历史副本、触达任务及活动。 |
| 普通命令拒绝与启动 | 含数据的 `21`/`22` 库分别用普通 Alembic 命令与常规启动触发拒绝。对比原 schema、数据和 revision，确认完全一致。直接启动后端时恢复函数与调度均未执行。空库能经普通启动流程初始化，已切换库能正常启动。未知 revision、无版本但已有应用对象的库和离线 SQL 模式均无法通过显式参数放行。 |
| 空库历史重放 | 从空库走完整历史链，验证退役阶段在前段事务结束后重新启用外键，之后以独立写事务完成退役与版本更新。完成库无退役对象，完整性和外键检查通过。注入历史重放中断并保留部分结构，确认下一次普通运行拒绝自动继续退役。 |
| 保留数据与停写验收 | 保持正式工作库停写；通过只读方式核验退役 revision、清除结果、保留表内容及结构、完整性和外键。用副本验证应用可启动，并确认正式库放行写入前的验收路径不会调用采集恢复或调度。 |
| 失败与恢复 | 在两条显式升级路径中注入中途 DDL 失败，比对原始 schema、全部业务表数据和 revision。另测旧价格冲突、外键未启用、未知跨范围依赖时拒绝。验证只在停写窗口允许用恢复点整库恢复，放行写入后的回退流程先保全新增监控记录。 |
| 页面与 API | 桌面和窄屏打开即进入监控大屏，侧栏、设置和搜索只暴露保留入口。搜索不请求退役 API。OpenAPI 无退役路由，已知旧端点返回 404，应用启动不恢复触达任务。 |
| 监控和采集回归 | 在 fixture 与 mock 中验证添加链接、分组与组内比较、手动和定时调度、任务恢复与记录、通知跳转、工作浏览器设置。保留历史有效数据及未知状态的现有处理。 |
