# 产品库商品身份规则 — 实施 Spec

2026-10-20；按用户后续要求修订审核与身份规则。仅开发和隔离迁移授权，不自动迁移正式库，不Commit/Push。

## 最终规则

厂家为边界，产品id为主键、version为并发令牌。保留原规范化（厂家折叠空白，所有文本去首尾空白、统一换行）；比较大小写/全半角敏感，不去规格、不做模糊合并。产品身份为(厂家,型号,名称)：三项完全相同才重复；任一项不同均可新增，不再把同型号异名、同名异型号归为冲突或疑似重复。空型号按空值参与应用层精确匹配。不同厂家独立。

导入预览只有新增、重复、异常三类。重复默认跳过；与已存在产品精确匹配且字段有变化时，可明确目标、核对差异后更新。异常行只能跳过。所有空上传字段更新时保留旧值。

文件内完全相同身份的第一行按库内情况分类，之后重复行标记为重复并默认跳过；相同型号但不同名称、相同名称但不同型号均按新增处理。校验失败仍为异常。文件行仅用于说明重复来源，不作为持久更新目标。

## 导入合同

新preview JSON绑定identity_rule_version=3（复用现有JSON，不新增列），回执也记录版本。旧ready读取/确认返回409 preview_rule_changed要求重传，绝不删除；已committed历史回执照常查询，并按旧摘要验证同import_id同决策幂等。新预览保持30分钟过期和厂家集合baseline。

预览仅为精确身份候选返回id/version、六字段diff及can_update；任何部分匹配不作为候选。前端必须先选择目标，查看对应diff，再二次确认update；无明确目标不能执行。新update决策必须提交target_id/target_version，服务端验证其属于服务端预览的可更新候选且版本匹配；纳入幂等摘要。insert/skip不得带目标。重复行不得新增。

批次拒绝两行更新同一产品；拒绝插入或更新后与已有精确身份冲突（含同批计划）；不能靠先后次序覆盖。全部写入与回执同事务，BEGIN IMMEDIATE串行化；唯一约束异常返回明确409 identity_conflict并全部回滚。没有实际变化不允许更新。

## Schema与上线隔离

新Alembic revision 20261020_17（父20261018_16）：在真实SQLite事务中先检查integrity/foreign_keys和旧数据规范化/精确重复，再创建uq_library_products_manufacturer_model_name(厂家,型号,名称) WHERE model IS NOT NULL，最后删除旧索引。不改表、不改产品字段/ID/version、不清回执。原数据不规范则只报错阻止升级，不自动修复。

新身份代码在create/update/preview/confirm ready写入前检查新索引结构及旧索引不存在；未迁移正式库返回503 identity_schema_required，不按新规则写入。已提交回执查询/幂等重放不受此写门禁阻断；只读查询/报价/复制继续可用。已有删除功能不涉及新身份写入，继续原版本校验。

降级先检查旧(厂家,型号)重复；不兼容直接拒绝且索引/版本不变，禁止删/合并/重命名。兼容时事务内先建旧唯一索引再删新索引。正式恢复必须停写，使用升级前一致性备份；新数据先导出，恢复会丢失备份后写入，不自动执行。
