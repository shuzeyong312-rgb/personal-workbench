# 产品库商品身份规则（简化 V2 冻结实施合同）

本合同随 [产品库 V2 简化设计](product-library-v2.md) 冻结并由用户授权实施。旧 V1 和 VNext 文件的厂家参与身份、旧索引和旧默认价条款是历史合同，适用关系见 V2 第 8 节；不是当前实现指令。此前 Issue #8 的五表设计与已验证历史事实不构成新设计通过。

## 目标身份

- 产品 ID 稳定，版本用于并发校验。唯一身份为规范化后的 **型号 + 名称**，供应商/厂家不参与；空型号只与空型号同名精确匹配。型号和名称统一 CRLF、CR 为 LF 并去首尾空白，空型号为 NULL、名称必填；内部空格、大小写、全半角、标点及 Unicode 不改写，BINARY 精确比较。不作模糊合并。
- 同型号异名、同名异型号可独立存在；同身份跨供应商复用同一产品并新增来源。导入文件内相同身份重复时阻止该身份组、标示行号。手动 CRUD、两类 Excel 导入及并发写入均使用相同合同。
- 型号列预设文本格式，数字、日期、布尔和公式单元格不能推断前导零；按行报错并要求以文本重新输入，详见 V2 第 1 节。旧六列兼容导入映射为同一内部字段，但旧批发价须待确认。
- 为空型号产品补型号须先检查目标精确身份；未占用时用户确认后更新原产品并保留 ID、来源、报价历史，已占用则拒绝并展示冲突，人工处理。输入有型号且已有空型号同名（或反向）提示潜在重复，用户选择独立新增或取消先修正，不自动合并或指向候选。

## 厂家字段与来源

历史 `manufacturer_name` 保留原值及首录资料公司语义，映射为历史供应商来源标签，不能推定为真实生产厂家。迁移将旧主表该列改为可 NULL 并验证全部历史行不变；新产品写 NULL，不得填空字符串、虚构厂家或首个供应商。新建和编辑 API 不要求填写该字段，不能用它维护新供应商。新系统的供应商归属来源及报价，上传时填写一次；它不是新主资料身份字段。主资料为分类、型号、名称、参数、独立的可空 `control_price` 文本、卖点，供应商来源保存批发价原文及独立备注；历史 `price_note` 仅作来源备注，不映射控价。兼容旧字段不得在新写入中作为第二套权威数据或自动覆盖其他供应商来源。

## 归档、并发、迁移与恢复

产品删除采用软删除，保留产品 ID、来源、报价版本、证据及回执；归档产品不参与普通搜索/报价，但继续占用型号+名称身份。导入或手动新增遇到同身份时，提示恢复原产品或跳过/取消，不自动新建或恢复；恢复必须重验版本、重新预览。来源和报价只能停用或归档，普通操作不物理删除历史。

- 数据库保证非空型号 `(model, name)` 和空型号 `name` 各自唯一；迁移前在写锁内检查规范化、完整性和全部身份碰撞，列出产品 ID、历史公司及差异，未解决即拒绝，不删除或自动合并。
- 新预览绑定规则版本、所有精确身份及潜在重复候选、产品及相关报价/来源版本；确认在写锁内重验，任何变化重新预览。旧 ready 失效，历史 committed 回执按原摘要查询和幂等重放。产品及关联写入和回执同事务成功或回滚。
- 不修改已发布 revision。`20261029_20/21` 为 PR #7 未发布链的历史实现；已应用的环境先备份并按 V2 第 6 节只读归档全部数据及关系，经可验证前向迁移处理，不能直接降级或丢弃。未应用环境从实际已发布 head 建简化路径。
- 迁移失败事务内完整回滚；新写入后恢复须停写、导出增量、恢复已验证的一致性备份并人工协调增量。不得借旧 `manufacturer_name`、默认价或 `is_default_wholesale` 自动选价；只有经资格校验的当前出厂报价、由用户明确选择供应商与规格并确认实际来源及条件后才能用于客户报价；人工最终售价不得绕过成本及条件门禁。
