# V1.2 采集记录 UI 增量说明

日期：2026-10-14。依据：用户确认的采集记录首页、批次详情两张原型及本轮 UI 合同。本文只补充展示与查询，不改写冻结 `collection-reliability-records-v1.2.md`。

## 信息架构差异

- 首页是筛选区 → 一张任务记录表 → 分页，不再分成批次和单次历史两张表。
- 默认只查真实批次，按真实开始时间倒序。记录类型切换为“历史未归属单次采集”时，同一表展示独立 CollectionRun。旧记录和新单商品立即采集都可查；不推断触发方式，不归并、不回填 Batch ID、不建立虚构批次。
- 日期默认最近 30 天、结束日期不限（避免未来/最新任务被结束界限误挡）；清除筛选恢复默认最近 30 天条件；可清空日期访问全部历史。日期按浏览器本地日边界转 UTC 查询。
- 首页只在点击查看详情后进入详情。批次详情展示七项紧凑汇总、商品过滤与分页；默认每个计划商品一行，每页十个商品。展开商品后显示完整逐轮历史，进一步展开字段表。
- 商品图片/身份来自真实关联商品；已删除商品只展示匿名汇总与删除说明。字段明细只来自本轮 Observation，完全不读 latest_valid。

## 查询与统计

- 批次搜索 API 保留按标识及关联商品标题/店铺/Offer ID 查询；默认批次首页不常驻关键词控件，触发方式支持全部、手动、定时与历史未知。异常筛选区分当前未恢复与曾异常后恢复；页面 `-` 不算技术故障。基础失败和需要验证也可定位。
- 详情过滤在服务端先筛商品、排序再分页。搜索、最终结果、当前/历史异常、尝试类型和原因可组合；历史条件选择商品后仍返回该商品全部真实尝试。批次汇总始终基于全批次，不随分页/过滤改变。
- 成功数是互斥最终结果 first_pass_success + verification_resume_success + retry_success；异常数是 final_failed + verification_required。pending/未执行单独表达，不伪装成功或异常。
- 计划商品与尝试次数分离。页面确认访问、未知访问、经营补采与验证恢复独立表达；历史无访问证据的单次记录显示未知而非编造一次。
- 同源字段错误先按状态聚合为一条摘要，展开字段表显示原始页面值、状态、实际原因。正常 placeholder 明确无需补采。

## 耗时口径

- 批次：可信 started_at 到 finished_at，包括真实等待、休息、冷却和补采。运行中显示“进行中”；未提供可信开始/结束时间显示缺失。created_at 不替代 started_at。
- 商品：本批次首次真实尝试到最终结果确定的历时，含跨队列等待，不是连续页面加载耗时。缺少可信终态时间时显示 —。
- 单轮：CollectionRun.started_at 到 finished_at。缺失、无效、逆序时间显示 —/时间信息不足，不造零秒。
- 无后台计时器、无第二轮询、无第二队列。本页面只按查询/翻页/进入详情加载记录；实时控制仍由大屏既有权威请求路径负责。

## 约束与验收

复用 shell、ProductImage、分页及现有控件风格；无新增依赖。保留 Collector、Scheduler、来源熔断、经营补采预算、验证恢复、设置、Observation 和删除合同。本轮不迁移正式数据库，不采集真实平台，不修改 Chrome Profile，不 Commit/Push。

自动检查使用隔离 SQLite 和 fail-closed 模拟 API；实际页面截图是隔离夹具的实现运行效果，不能当作真实采集成功证据。交付后等待用户实际 UI 验收。

## 最终人工验收反馈修复（2026-10-14）

- 首页和详情移除查询按钮，受控下拉/合法单侧日期立即触发服务器查询。条件变化回到第一页，服务器总数缩减时自动跳到有效页。清除恢复默认首页，详情重置保留当前批次。
- 首页仅历史未归属单次记录显示商品/Offer 搜索；详情保留商品/Offer/店铺搜索。两个关键词控件均采用 350ms 防抖，输入法组合结束后再应用。
- 数据渲染与完整请求地址绑定：切换类型或条件后不使用旧 payload 渲染，过期请求取消且无效响应显示错误与重试；不强制刷新、不新建轮询。
- 七指标保持既有统计口径，以浅色图标、数字层级与准确状态色增强视觉；异常为零保持中性。两个分页区使用同一记录页面局部样式，带内边距、每页数量和窄屏换行。
- 每轮八字段明细展开在本轮下方的整行 colspan 内容中，长原因正常换行，开始时间保持单行并允许表格容器横向滚动；不挤成竖向文字。
- 首页底部仅显示简短业务提示，完整耗时与未归属规则放在轻量帮助提示。字段值、placeholder、来源技术异常与真实历史规则均保持不变。
