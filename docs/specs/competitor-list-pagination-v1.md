# 竞品列表分页 V1 Feature Spec

## 1. 目标与范围

在现有竞品列表中启用固定每页 10 条的前端本地分页。分页只改变当前表格渲染范围和导航，不改变竞品数据来源、既有搜索筛选含义、列表统计口径或批量采集目标。

本 Spec 是 `competitor-list.md` 的独立增量契约。原 Spec 中“Pagination 暂不开放”描述的是当时的实现状态，继续作为历史记录保留；分页 V1 的行为以本文为准。

## 2. 数据与分页规则

- `GET /api/competitors` 继续一次返回全部竞品；不增加 `page`、`page_size`、`search`、`status`、`group_id`、`sort` 等服务端分页或筛选参数。
- 不修改 Backend API Contract、数据库 Schema 或 migration。
- 前端数据流固定为：

  ```text
  competitors
  → filteredCompetitors
  → pagedCompetitors
  → Table
  ```

- 搜索与商品状态、采集状态、竞品组筛选先对完整 `competitors` 在前端本地执行。页数、分页总数和当前页数据均基于完整 `filteredCompetitors` 计算。禁止先切页再搜索或筛选。
- V1 固定 `pageSize = 10`。页码从 1 开始；当前页切片为从 `(currentPage - 1) * pageSize` 开始的最多 10 条记录，并保持筛选结果原有顺序。
- 总页数为筛选结果数量除以 10 后向上取整；没有结果时按 1 页显示，避免出现第 0 页。空结果时 Table 仍由现有筛选空状态替代。
- 上一页、下一页只在目标页有效时可操作。首页上一页 disabled；最后一页下一页 disabled；总数不超过 10 时两个翻页按钮均 disabled。
- 数据或筛选结果变化使当前页大于新总页数时，将当前页收敛到最后一个有效页。不得保留不存在的页码或显示空白页。若筛选结果为空，空状态优先，页码回到第 1 页。
- 当前页以外的数据仍保留在内存中的 `competitors` / `filteredCompetitors`，不得因分页丢弃。

## 3. 页码重置与数据变化

下列变化后将当前页设为第 1 页：

- 搜索词变化；
- 商品状态、采集状态或竞品组筛选变化；
- 重置筛选；
- 从其他页面带竞品组条件进入列表；
- 新增竞品成功且列表重新加载完成。

筛选条件变化立即影响完整筛选结果，并回到第一页。进入列表时应用的竞品组条件与用户手动更改竞品组筛选遵循同一规则。

成功新增竞品并完成列表刷新后，明确回到第 1 页，以便用户看到按最新创建优先展示的新竞品。

普通数据刷新不因 `competitors` 发生变化而统一回到第 1 页。批量采集完成后刷新列表、单纯重新加载、生命周期状态更新、竞品重新采集及其他正常数据刷新，如果当前页仍有效则保持当前页；如果数据减少导致当前页超过新的总页数，则只回退到最后一个有效页。

## 4. 统计与空状态

现有列表统计（竞品数、已采集数、未采集数）和列表总数继续基于完整 `filteredCompetitors`，不受当前页限制。分页区域显示当前筛选结果总数，不能以当前页条数冒充总数。

空状态保持现有判断：

- 系统没有任何竞品（完整 `competitors` 为空）：显示原“还没有添加竞品” Empty State；
- 系统有竞品但筛选结果为 0：显示“没有找到符合条件的竞品”及现有重置筛选入口。

分页不得改变两种状态的判定。空状态下不渲染数据行。

## 5. 选择与批量采集

### 5.1 行选择和跨页保留

- 行复选框只为 `is_active = true` 的竞品启用；inactive 竞品不可选。
- 在筛选条件不变时，`selectedIds` 可跨分页累计：例如第 1 页选 3 个、第 2 页选 2 个，翻页后仍保留 5 个；单纯翻页不得清除其他页的有效选择。
- 搜索词、商品状态、采集状态、竞品组或重置筛选发生变化，以及从其他页面带新的竞品组筛选进入列表时，`selectedIds` 必须与新的 `filteredCompetitors.filter(item => item.is_active)` 求交集。只保留新筛选结果中仍可见且 active 的已选竞品，清除被新条件隐藏的选择。
- 竞品数据刷新后，已不存在、`is_active = false` 或不再属于当前 `filteredCompetitors` 的 ID 必须从 `selectedIds` 清除。无论筛选控件是否变化，选择有效范围始终是当前筛选结果中的 active 竞品；数据刷新使竞品不再匹配当前筛选时，同样清除其选择。
- 页面顶部“采集选中（X）”中的 `X` 是当前筛选结果中跨所有分页累计已选 active 竞品数，等价于 `filteredCompetitors` 中 `is_active` 且 ID 存在于 `selectedIds` 的数量。它不是当前页选中数，也不包含当前筛选结果外的隐藏选择。
- “采集选中”的实际请求 ID 集合必须与上述显示数量采用同一范围：仅提交当前 `filteredCompetitors` 中 active 且已选中的 ID，避免数量与提交目标不一致。

### 5.2 表头全选

表头复选框的作用域仅为当前页 `pagedCompetitors` 中 `is_active = true` 的竞品：

- 当前页 active 竞品全部已选：checked；
- 当前页 active 竞品有选有未选：indeterminate；
- 当前页 active 竞品一个未选：unchecked；
- 当前页没有 active 竞品：disabled。

点击全选只添加当前页 active ID；取消全选只移除当前页 active ID。其他页的选择必须保留。其他页已选 ID 不参与当前页 checked / indeterminate 判断。inactive 行不参与表头状态和全选操作。

### 5.3 采集全部监控中

“采集全部监控中”继续针对完整 `competitors` 中所有 `is_active = true` 的竞品，不受分页、搜索或筛选影响。其数量与批量请求语义均不得改成当前页或筛选结果。

## 6. Pagination UI

将当前“显示全部竞品 / 分页暂未开放”的占位 Pagination 升级为正式分页区域，放在列表底部，至少显示：

- 当前筛选结果总数；
- 上一页按钮；
- 可识别当前页的页码；
- 下一页按钮；
- `第 X / Y 页` 信息。

第一页上一页 disabled，最后一页下一页 disabled。结果不超过 10 条时允许保留分页区域，但前后翻页按钮均 disabled。页码呈现应足以识别当前页；不要求实现页码输入跳转。

V1 不包含：每页 10/20/50 切换、自定义 page size、输入页码跳转、无限滚动、URL `page` 参数、记忆上次页码或分页库。

## 7. 非目标

本 Feature 不修改 Backend、SQLite Schema、Alembic、添加竞品 API、生命周期业务规则、竞品组、我方商品角色、单条采集、Batch Runner、Dashboard、Detail、Group Detail、ChangeEvent 或 Scheduler。

不拆分 `App.tsx`，不重构页面架构，不引入 React Router、分页库、新状态管理或性能优化，也不调整无关 UI。

## 8. 实现验收场景

验收应观察用户可见行为，不为测试增加不必要抽象或接口：

1. 筛选结果不超过 10 条时只显示一页，前后翻页按钮 disabled。
2. 筛选结果为 11 条时产生第二页，页数及总数正确。
3. 各页表格只显示正确切片，顺序与完整筛选结果一致。
4. 上一页 / 下一页的首页、末页边界正确，且不会进入无效页。
5. 搜索词或任一筛选变化后回到第 1 页。
6. 重置筛选后回到第 1 页。
7. 删除最后一页最后一条数据后，自动回退到最后一个有效页。
8. 列表统计数量基于全部筛选结果，而不是当前页最多 10 条。
9. 表头全选只选择当前页 active 竞品。
10. inactive 竞品不参与行选择或表头全选。
11. 筛选条件不变时跨页选择能够保留；“采集选中”数量和请求 ID 均覆盖当前筛选结果中跨页累计选中的 active 竞品。
12. 搜索或任一筛选条件变化后，只保留新筛选结果中 active 的已选项，并同步更新“采集选中（X）”数量和请求 ID；被隐藏的选择不保留、不提交。
13. 其他页已选项不影响当前页表头 checked / indeterminate 状态；筛选变化后被隐藏的已选项已清理。
14. “采集全部监控中”覆盖完整列表中所有 active 竞品，不受页码和筛选影响。
15. 筛选结果为空时显示既有筛选 Empty State；系统无竞品时仍显示原 Empty State。
16. 新增竞品成功且列表刷新完成后回到第 1 页。
17. 普通数据刷新后当前页仍有效时保持当前页；数据减少导致越界时回退到最后一个有效页。
18. 分页、搜索和筛选不产生分页 API 请求；竞品列表继续通过现有一次性列表请求取得数据。

## 9. 当前仓库基线与实现提示

冻结实现时应遵循上述 Feature Contract，并复用当前列表本地筛选与现有表格、分页区域。当前已提交实现中分页仍是占位；此外，表头全选会整体替换 `selectedIds`，选择协调按筛选后的 active 列表清理 ID。实现时需保证同一筛选条件下翻页保留选择、筛选变化时清理隐藏选择、普通刷新清理已删除或 inactive ID，并让表头操作只增删当前页 active ID。“采集选中”的计数与提交范围均限于当前筛选结果中的已选 active 竞品。本文不追溯修改原 `competitor-list.md`。
