# 竞品监控大屏：日常运营优化

本轮用户已授权直接实现及 Chromium QA，不 Commit/Push。仅调整大屏前端及相关测试；继承 Group-first Dashboard 的数据、排序、导航和采集合同。此文仅覆盖本轮 UI 决策，不回写历史 Spec。

## 场景与成功标准

- 打开首页先识别今日有哪些组值得看，读取 Backend 原因并进入既有组分析；关注等级仅表示查看顺序。
- 同屏判断采集是否进行、失败或需要处理，使用原有暂停/继续/结束操作；可进入采集记录排查。
- 今日无关注项时，不能将未采集、全部失败、部分成功、请求失败说成全部无变化。

## 数据边界

- Attention API：日期、三项组级 KPI、已排序的关注组及原因。不得前端补算等级、排序或竞品数量。
- Dashboard today：今日成功/失败采集次数、最近采集时间、平均耗时、趋势及 active_monitored_products。次数不是商品覆盖数；有成功记录不等于所有竞品已采集。
- batchState：复用现有权威状态与动作。完成批次不等于全部成功；暂停/休息/冷却/验证不等于空闲。
- 不新增请求、指标或后台逻辑。不访问真实平台或写正式数据库。

## 页面组织

- Header 保留店铺和原有添加/采集能力，立即采集是主要操作。
- 四项真实 KPI 形成紧凑摘要带。增加说明：变化仅来自已检测事件，零值不保证采集覆盖。
- 主工作区以今日关注为宽主体、采集状态为侧栏；窄屏按 DOM 顺序自然堆叠。
- 默认展示前 5 个关注组，保留展开/收起；Backend 顺序不变。每组复用身份、等级、变化竞品数、最多三条原因、最近变化时间、组分析入口。补充查看全部商品组入口。
- 7 天趋势降为默认折叠的原生 details，保留真实数据、图表交互和键盘操作，不添加替代图表。
- 复用现有工作台字体/浅灰/白/石墨/蓝色及语义色；样式限定 dashboard。只给交互反馈，不加页面入场动效，尊重 reduced-motion。

## 空状态及可信度

- Attention loading/error 独立保留；错误重试仅重试 Attention。
- 今日无关注项且采集统计不可用：明确采集状态未知，不能判断是否无变化。
- 批次进行/暂停/休息/冷却/验证：显示实际批次阶段，说明结果未齐，继续保留已检测关注项。
- success=0 且 failed=0：今日尚无已完成采集记录，提示立即采集；不宣称从未发起采集。
- success=0 且 failed>0：今日采集未成功，提示查看采集记录。
- success>0 且 failed>0：部分采集失败，暂无已检测的组级关注事件不等于无变化。
- success>0 且 failed=0：今日暂无需要关注的竞争变化；说明只基于已成功采集及符合组条件的数据，不能证明全部竞品无变化。
- monitored groups=0：说明需绑定我方商品及直接竞品，入口进入既有分组管理；若已有失败也保留失败提醒。
- 最近采集无值、加载、失败分别表达；历史最近时间不标成今日。统计注明 Asia/Shanghai 和采集次数口径。
