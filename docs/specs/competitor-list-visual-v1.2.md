# 竞品列表视觉 POC V1.2

## 范围与成功标准

仅升级 `ListPage` 的 competitor 模式；self 模式、AppShell、商品资料库及所有既有未提交业务修改保持原样。保持 API、字段、筛选、排序、固定 10 条分页、跨页选择、批量操作、分组与详情行为。不恢复历史 Spec 中已被后续合同移除的添加/采集入口。

采用采购台账工作区：PageHeader → 一个连续工作区（筛选、统计、表格、分页）。使用现有中文字体栈与蓝色语义；商品标题 14px、正文 13px、辅助信息和状态至少 12px，数字等宽，金额右对齐。商品名允许两行并提供完整 title，避免仅看截断标题。

桌面保留所有列；窄屏将同一张语义表格重排为带字段标签的记录，不删除字段或操作，不复制另一套业务逻辑。长店铺名、标题、Offer ID 可换行。表格行选择有明确背景反馈，键盘焦点可见。

## 最小视觉例外

相对 `ui-system.md` 的轻毛玻璃、柔和阴影及 List Reference 容器表现，本 POC 仅允许 `.competitor-workspace` 内采用实白表面、单层边框、无模糊/阴影；保留已有 12/8px 圆角、间距刻度、字体栈与配色。不是全站换肤或第四类 Reference。历史 Spec 不改写；该例外仅在本次局部 Review 通过后生效。

## 动效

Emil 主导：仅对操作反馈使用 120–160ms 的颜色/边框过渡；批量菜单采用 160ms opacity 与 4px translate 入场，表达从触发器展开；禁用重复触发仍由原逻辑控制。无行入场、筛选 stagger、数值滚动或页面转场。reduced motion 下关闭位移与动画，状态立即可用。Hover 仅对精确指针启用。

## 验证与 Gate

实现前局部 Spec Review 检查范围、规范冲突和行为兼容性；本次用户已明确授权 Review 通过后直接实施，不提交/推送 Spec 或代码。完成后实施自检、只读 Code Review、修复、只读 Final Gate。保留真实 Chromium 在相同受控 API fixture 下的前后桌面/窄屏/选择菜单截图；标注为测试数据，不作为真实平台验证。运行相关单测、类型/构建、列表/分组/身份相关 E2E；检查减少动态效果、键盘焦点、空/错/加载态及无页面横向溢出。

## 设计比较

UI UX Pro Max 的 data-dense-dashboard：效率高，但多个独立容器保留模板感，维护多个密度和表面规则。minimalism-and-swiss-style 的网格、清晰字阶和少装饰更适合采购台账，但不采纳其纯黑白、零圆角或落地页建议。选择后者的结构方法，保留项目品牌。两次 design-system 查询出现 Hero/CTA、Glassmorphism 等不适配结果，已拒绝；未增加导出、排序、图表等建议功能。

Impeccable Operate 模式：精度与可扫描性优先，取消重复卡片表面；用字体、对齐、分隔和真实选中态表达层次。frontend-design 主导最终组合；不引入字体下载、组件库或动画依赖。
