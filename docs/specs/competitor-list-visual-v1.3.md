# 竞品列表视觉 V1.3

## Spec Review 结论

批准更新 `docs/ui-system.md` 中蓝紫雾感、渐变和轻毛玻璃的全局默认方向。V1.2 已完成的筛选—统计—表格—分页结构和全部业务交互继续有效；V1.3 更新色彩、字体层级、表面、边框及导航外观，不改业务合同。

本次适用范围：全局 App Shell（画布、侧栏、品牌标记、导航选中态、顶部工具条）和竞品列表的竞品模式。业务页内容样式仍按既有组件规则运行，后续按页面逐步迁移；不能把未触及页面描述为已换肤。

## 视觉方向对比

| 部位 | A. 石墨白底 + 品牌蓝（选定） | B. 暖石灰 + 墨绿账簿台 |
| --- | --- | --- |
| 核心颜色 | 画布 `#F3F4F6`、表面 `#FFFFFF`、主字 `#20242C`、次字 `#626B78`、边线 `#DDE1E6`、操作蓝 `#2563EB` | 画布 `#F3F1EC`、表面 `#FFFDF9`、主字 `#292B27`、次字 `#686B63`、边线 `#E2DED5`、墨绿 `#28695B`；状态色仍独立 |
| 字体 | 保留 Noto Sans SC / Microsoft YaHei 系统栈；28/16/14/13/12px 字级；数字 `tabular-nums` | 保留中文系统栈；字段标签 12px、行内容 13px、页标题 26px；Offer ID 可用系统等宽字体 |
| 导航 | 白侧栏、石墨正文、单色图标；当前项用浅灰底和窄蓝色边线；品牌标记用实色蓝 | 暖白侧栏、墨色正文；当前项用淡绿底与墨绿边线；减少图标层级 |
| 筛选区 | 白底连续工具行，标签加深，控件 36–40px，聚焦用清晰蓝环 | 暖灰底工具行、控件白底；减少独立边框，以组间距区分 |
| 表格 | 白表面、浅中性表头、水平分隔线、金额右对齐、行选择浅蓝底 | 暖白表面、灰褐分隔线、同样的列密度与数字对齐 |
| 状态标签 | 保留现有语义色，以低饱和底色、深色文字和细边线表达；蓝色只代表操作 | 同样保留语义色，墨绿仅用于品牌操作，需避免和“正常/成功”混淆 |

### 设计质量与维护成本比较

| 维度 | A. 石墨白底 + 品牌蓝 | B. 暖石灰 + 墨绿账簿台 |
| --- | --- | --- |
| 设计品质 | 高对比文字、稳定白面和行分隔强化商业工具的精确与扫描效率 | 暖白和灰褐线条带来纸面账簿质感，表面更柔和 |
| 辨识度 | 中等；操作蓝较常见，辨识度主要来自克制的品牌面积、石墨层次和密集表格节奏 | 较高；暖底和墨绿在同类工作台中更少见 |
| 可读性 | 高；中性底色和文字层级在长时间查看密集行时更稳定 | 高；但需要控制暖底与状态色之间的区分 |
| 实现成本 | 低；沿用已有蓝色操作语义和中文系统字体，只需一组表面与文字 Token | 中；要调整全局表面和交互色，并单独校准暖色状态标签 |
| 维护成本 | 低；品牌操作和成功状态继续分离，容易推广到其他列表 | 中高；墨绿与成功语义存在冲突风险，暖色表面还需在各类业务页统一 |

### 取舍

方向 A 符合已有操作蓝和状态语义，支持清晰的筛选焦点、选择反馈及批量操作；现有字体无需外链，规则数量较少，适合作为其它管理列表的长期基线。方向 B 能通过暖色账簿质感拉开辨识度，但墨绿容易与成功状态重叠，且需在 Dashboard、设置页和业务列表之间额外维护暖色语义。A 的辨识度来自石墨文字、近中性表面、稳定列线和明确选中态，不依赖大色块。

UI UX Pro Max 检索到 Shopify Polaris 商户后台的语义 Token / 焦点约束和 Data-Dense Dashboard 的中性底色、数据色、紧凑间距；同时返回暗色金融界面、营销页、在线字体组合等不适合本项目的候选，均不采纳。Impeccable 对现有列表的审查支持以字体、对齐和分隔替代重复卡片。Emil Design Engineering 的交互准则支持只保留输入焦点、行选择和菜单开合等用户触发反馈。frontend-design 审查强调中文系统字体、左对齐数据层级、一个清晰品牌动作和减少无意义装饰。

## 选定 Token

```css
--ui-canvas: #f3f4f6;
--ui-surface: #ffffff;
--ui-surface-subtle: #f6f7f8;
--ui-ink: #20242c;
--ui-muted: #626b78;
--ui-border: #dde1e6;
--ui-accent: #2563eb;
```

沿用现有中文系统字体，不加载网络字体；金额、数量、日期及 ID 使用等宽数字特性。正文和辅助文字维持不低于 12px。状态仍由文字和语义色共同表达。表面以白色和细边线区分，不使用背景光晕、毛玻璃、重复投影或相同圆角卡片堆叠。导航活动态和表格选择态各自明确，但不扩大品牌蓝的使用面积。

## 结构与交互约束

保留 V1.2 PageHeader、连续工作区、筛选、统计、表格、分页和窄屏同一语义表格重排。桌面列顺序、字段、排序、选择、分页、分组、详情、批量菜单、API 和状态行为不变。全局 App Shell 仅改表面与导航质感；不改导航信息架构、尺寸或路由。移除当前 `aria-hidden` 且没有操作行为的搜索、通知和账户占位装饰；以后只展示有实际功能的全局入口。

普通焦点、选中、按钮按压反馈维持 120–160ms；批量菜单沿用 160ms opacity + 4px 位移。精准指针才显示 hover；`prefers-reduced-motion` 时移除动画和位移。不得添加行入场、统计数字滚动或页面切换动画。

## 验收

- 使用 23 条固定受控竞品 fixture，桌面 1600×1100；菜单选择态及窄屏 390×844 对比同样数据和状态。
- 真实 Chromium 截图保存到 `docs/qa/competitor-visual-v1.3/`，标明测试数据。
- 验证业务/API 交互、320–1600px 响应式无页面横向溢出、键盘焦点、减少动态效果、状态页及窄屏可达性。
- 执行前端相关单测、类型/构建、列表与导航/分组 E2E、只读 Code Review 和 Final Gate。
- 不访问正式业务数据库或 1688；不 Commit/Push。

## 后续推广边界

本 Spec 确立新的全局视觉默认，但本次代码只迁移 App Shell 与竞品列表。Dashboard、详情、分组、产品库和设置内部表面可能暂时与新 Shell 并存。后续页面按其 Reference 和独立范围逐页迁移，先核验语义色、空/错/加载态和专属布局，不能对全站执行机械颜色替换。
