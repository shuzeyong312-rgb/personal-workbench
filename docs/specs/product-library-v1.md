## Problem Statement

厂家通过 PDF、PPT、Excel、Word 等不同格式提供资料，运营人员需要统一保存、查询和维护产品信息。目前工作台的产品库只有预留导航和占位页，已有我方商品、竞品和快照描述的是 1688 监控事实，不能承担厂家产品资料管理。

目标是让外部 Codex 根据原始资料整理标准 Excel，用户核对后导入轻量产品库。不在工作台内部开发 AI 或原文件解析能力，不以监控商品身份替代厂家产品身份。

## Solution

复用现有 `product-library` 导航入口，提供产品列表、详情、手动新增/编辑/确认删除、关键词搜索、厂家筛选、模板下载和三步 Excel 导入。

核心路径：上传 `.xlsx` 并填写厂家 → 预览、校验、识别重复并选择操作 → 确认后一次事务保存。确认前正式产品零写入；错误行可跳过，数据库写入失败必须整批回滚。

代表任务：

- 外部 Codex 将某厂家资料整理为 100 行 Excel，用户填写厂家后预览 100 条待新增，确认后新增 100 条。
- 第二次资料含旧型号：默认跳过，用户查看差异后逐条确认更新；空值保留旧资料。
- 资料缺型号或没有确定价格：保留为空，价格描述放备注，不编造型号或将未知价格变成 0。

## User Stories

1. 作为运营人员，我希望下载固定模板，以便外部整理资料时有统一格式。
2. 作为运营人员，我希望一次填写厂家，以便同一批产品无需重复输入。
3. 作为运营人员，我希望预览真实 Excel 行号和错误，以便定位并修正资料。
4. 作为运营人员，我希望跳过错误行，以便导入已经确认的合法数据。
5. 作为运营人员，我希望识别已有型号，以便不重复新增。
6. 作为运营人员，我希望查看每个字段的新旧差异，以便决定是否更新。
7. 作为运营人员，我希望保留旧资料中未被补充的字段，以便空白不会误删信息。
8. 作为运营人员，我希望不同厂家同型号能够共存，以便真实保留来源。
9. 作为运营人员，我希望无型号的同名产品先提示疑似重复，以便人工决定是否分别保存。
10. 作为运营人员，我希望按型号、名称、参数、卖点或厂家搜索，以便查找技术资料。
11. 作为运营人员，我希望按厂家筛选及按批发价排序，以便比较确定价格。
12. 作为运营人员，我希望手动新增和编辑，以便补充资料或明确清空字段。
13. 作为运营人员，我希望删除前确认具体产品，以便避免误删。
14. 作为运营人员，我希望提交失败不留下部分写入，以便可以安全重试。
15. 作为运营人员，我希望网络断开后能查询同一次提交结果，以便不重复创建产品。

### 2. 产品语义与存储

新增独立 `LibraryProduct`（表名 `library_products`），一行一款厂家产品，无 SKU、状态或监控身份。数据库 ID 为自增整数、不可变且删除后不复用。字段如下：

| API 字段 | Excel / 展示名 | 约束 |
| --- | --- | --- |
| id | 产品 ID | 系统生成，唯一 |
| manufacturer_name | 厂家名称 | 必填，规范化后 1～200 字符 |
| model | 产品型号 | 可空，最多 200 字符，文本 |
| name | 产品名称 | 必填，1～200 字符，非空文本 |
| parameters | 产品参数 | 可空，多行文本，最多 10000 字符 |
| selling_points | 产品卖点 | 可空，多行文本，最多 10000 字符 |
| wholesale_price | 批发价 | 可空，人民币元，0～999999999.99，最多两位小数 |
| price_note | 价格备注 | 可空，最多 2000 字符 |
| created_at / updated_at | 创建 / 更新时间 | 系统 UTC 时间，API 带时区，界面按本地时间展示 |
| version | 并发控制字段 | 内部单调整数，初值 1；实际修改才递增；不是历史版本系统 |

批发价 API 使用十进制字符串或 null，例如 `"12.30"`；数据库以整数分保存并设非负范围 CHECK，避免 SQLite 浮点金额误差。合法的 0 是明确零价，不表示未知。不得从备注推算价格；价格多于两位小数报错，不自动舍入。界面空价显示“未提供”，不显示 ¥0。

可空文本的空串/纯空白统一为 null；普通文本去首尾空白，换行 CRLF/CR 统一 LF，保留内部换行、单位、符号和关键技术信息，不拆参数、不拼接卖点。名称和型号不做大小写、全半角、标点或别名转换；文本长度按规范化后字符数校验，禁止静默截断。手动 API 与 Excel 共用字段规则。

厂家名称：去首尾 Unicode 空白，将内部连续 Unicode 空白（含换行）折叠为一个普通空格；其余字符保持原样，区分大小写，不做公司别名、标点、全半角归并。规范化后的值同时用于保存、展示、筛选和匹配；预览显式显示最终厂家名称。厂家不建独立表，不与店铺名称或我方店铺设置建立关系。

型号非空时，数据库部分唯一索引约束 `(manufacturer_name, model)`；型号为空不作唯一约束。同型号不同名称是待人工确认的同一产品更新候选，不能新增第二条绕过约束。没有任何 Competitor、ProductSnapshot、SkuSnapshot、CollectionRun、Group 外键或数据复制，也不修改这些实体语义、统计和调度。

### 3. Excel 模板合同

模板文件 `产品库导入模板.xlsx` 包含两个工作表：

- `产品数据`：第 1 行 A～F 严格依次为“产品型号、产品名称、产品参数、产品卖点、批发价、价格备注”，第 2 行起为空白可填写区。文本列设置文本格式，参数/卖点/备注自动换行，表头冻结。
- `填写说明`：字段要求、上述限制、单位保留、缺失值处理、确定价与阶梯价/起售价/面议规则。示例仅写在说明表，明确为示例，不混入产品数据。提供有型号、无型号、价格未知及备注价格的示例。

只导入 `产品数据`，不读取其他工作表的业务内容；上传时不要求说明表存在。其他工作表可保留但不导入。产品数据表隐藏、任一数据行/列隐藏或存在合并单元格时拒绝文件，避免不可见内容被静默导入。

| 检查 | 确定规则 |
| --- | --- |
| 格式 | 只接受扩展名 .xlsx（不区分大小写）且内容为有效 OOXML 工作簿；不凭 MIME 判断；.xls、.xlsm、加密/损坏工作簿或伪装格式拒绝 |
| 上传限制 | 原文件最多 5 MiB；ZIP 解压内容合计最多 50 MiB，最多 1000 个条目；读取时同样限额，不解压到文件系统 |
| 行数 | 产品数据最多 1000 个物理数据行，即第 2～1001 行；忽略只有样式的尾部空单元格，但任一非空单元格超界拒绝整文件；中间空行仍占行号和行数额度 |
| 表头 | A1:F1 必须严格匹配六个固定字符串，不 trim 修复；缺列、重复列、乱序、多列或多级表头拒绝；G 列以后任何非空值均视为结构错误 |
| 空文件 | 仅表头或所有数据行均为空，报 no_product_rows，不能确认空导入 |
| 空行 | 六列规范化后均为空的行忽略，不参加重复判定和结果总数；原始 Excel 行号不重排 |
| 文本列 | 只接受字符串/空值；数字、布尔、日期、错误类型报该行格式错误；不将数字型号转换成字符串，避免丢前导零后假装可信；说明表指导外部整理为文本 |
| 批发价 | 接受数值单元格或只含十进制非负金额的文本；不接受货币符号、千位分隔符、范围、科学计数法文本、NaN/Infinity、布尔、日期；按十进制检查范围和小数位；不接受负数 |
| 公式 | 产品数据中任何公式单元格（即使有缓存值）均为该行错误，不采用缓存结果；Excel 错误单元格同样报行错误 |
| 特殊内容 | 包内宏、嵌入对象、外部工作簿链接/外部关系或 DTD/实体声明拒绝整文件；不访问网络，不执行宏、公式或外部链接；其他表公式不求值、不作为产品输入 |

使用 openpyxl 读取时保留公式类型（不用 data_only 隐藏公式），禁用保留外链与 VBA；包结构/大小检查先于工作簿解析。不要依赖工作表虚假的 dimension 值漏读越界数据。原始文件不持久保存，不送给外部服务，解析完成释放资源。

选择依据：标准库 ZIP/XML 可以检查包边界，但完整 Excel 单元格类型和工作簿读写自行实现维护成本高；已有依赖不能覆盖，openpyxl 同时支持模板生成和读取。[官方教程](https://openpyxl.readthedocs.io/en/stable/tutorial.html) 说明了读取模式、公式缓存与外链保留选项。实现时锁定并验证依赖版本；本轮不安装。

### 4. 重复判定与更新

匹配使用规范化后厂家、型号、名称精确比较；不做 AI、模糊匹配或跨厂家合并。先校验单行，再检查文件内重复，再查正式产品。

| 输入与已有记录 | 分类 | 默认 / 可选操作 |
| --- | --- | --- |
| 同厂家，非空型号相同，名称相同 | existing 已有产品 | 默认 skip；有实际差异才可逐行确认 update |
| 同厂家，非空型号相同，名称不同 | conflict 冲突 | 默认 skip；展示名称及其余差异，明确确认后 update；禁止 insert |
| 不同厂家，型号相同 | new 正常待新增 | 默认 insert，允许 skip |
| 同厂家，输入型号为空，名称相同（不论已有型号是否为空） | suspected 疑似重复 | 默认 skip；查看候选后可明确“仍新增为独立产品”；不提供自动/人工指向候选的合并更新 |
| 同厂家，输入型号非空且无同型号，但已有同名产品 | suspected 疑似重复 | 默认 skip；可明确仍新增；不据名称更新已有产品 |
| 型号/名称均无匹配 | new | 默认 insert，允许 skip |
| 文件内非空型号重复（名称相同或不同） | invalid | 所有涉及行均报错，列出彼此行号；不能选择其中一行自动覆盖 |
| 文件内同名且至少一行型号为空 | invalid | 所有涉及行均报错；防止无型号重复绕过；不同非空型号同名允许存在 |

文件内重复组以单行合法的数据为输入；格式非法行已经禁止写入，不据其非法字段推断产品身份。文件内重复错误不使整个结构合法文件失效，其他无关合法行仍可导入。修正重复记录需重新上传预览。

差异针对六列展示 old、incoming、effective（实际保存值）和 changed；空值保留时明确标注“保留原值”，不能误显示为清空。用户不能编辑预览字段；改文件或厂家必须重新预览。

更新仅修改同型号匹配的既有产品：输入非空字段整体替换原字段，空字段保留旧值；参数、卖点不合并/拼接。价格 0 是非空值，可替换旧价；null 不能清除旧价。无需变化的 existing 行仅能 skip，不能制造更新时间。厂家和型号不通过本次导入更新改变身份。需要清空字段、改厂家或改型号，通过手动编辑并再次校验唯一性实现。

### 5. 导入状态、并发和事务边界

采用同步、有限大小的导入，不启动后台任务，不复用 CollectionBatch 或采集锁。UI 固定三个步骤，不增加独立导入历史页。

为保证“预览内容由后端保管、提交后网络重试不重复写入”，新增一个仅服务本功能的 `LibraryImport` 凭据表（`library_imports`），而非通用作业系统：

- 随机 UUID import_id、created_at、expires_at；规范化厂家、校验后的行/错误/候选/旧字段及该厂家产品集合基线摘要；状态 ready / committed；提交决策摘要和最终结果。
- ready 有效期 30 分钟；不保存原始 Excel。预览写入凭据允许，但正式产品表零写入。
- committed 与产品修改同事务持久化；精简为提交决策摘要、计数和逐行结果，不保留整份旧/新产品内容；V1 不自动删除 committed 回执，保证重启后仍可查询、重放同一提交。
- 过期 ready 不可确认，访问或创建预览时可机会式清理；不增加定时清理任务。仅对未提交凭据适用 expires_at，已提交结果不因 30 分钟到期失效。

状态和错误处理：

| 情况 | UI / API 行为 | 产品写入 |
| --- | --- | --- |
| 文件结构非法 / 超限 | 留在步骤 1，指出结构原因 | 无 |
| 预览成功，部分行错误 | 步骤 2 显示分类及行级错误，可跳过错误行 | 无 |
| 全部行错误 / 全部跳过 | 展示结果，确认按钮禁用；API 拒绝空操作 | 无 |
| 用户取消 / 离开 | 放弃当前预览，提示未保存；凭据自然过期 | 无 |
| 正在确认 | 步骤 3 禁止重复点击；仍使用原 import_id | 一次事务中 |
| 基线变化 / 预览过期 | 保留提示，必须重新上传预览并重新选择，不自动沿用确认 | 无 |
| 提交成功 | 结果显示新增、更新、跳过、错误及逐行结果，刷新列表 | 全部提交 |
| 数据库失败 | 显示“本次未保存，全部回滚”，保留原 import_id 供重试 | 全部回滚 |
| 超时 / 断网 / 结果不确定 | 显示“结果待确认”，先 GET 原 import_id；ready 才可按原决策重试，committed 显示原结果；禁止自动重新上传确认 | 以回执为准，不声称失败或零写入 |

并发与原子性：

1. 预览在一致的读取事务内取得该厂家所有产品（ID、全部业务字段、version）的稳定排序摘要和候选；避免同一次预览读到混合版本。
2. 确认先取得 SQLite 写事务（BEGIN IMMEDIATE 或等价的先锁后读语义），再读取凭据。已 committed 且决策摘要相同，直接返回原结果；不同摘要返回 409 idempotency_conflict。
3. ready 检查有效期、决策完整性和当前该厂家产品集合摘要。任一新增、编辑、删除导致摘要变化，整次 409 preview_stale。其他厂家变化不阻塞。无需引入全库 revision 表或通用锁。
4. 在同一写事务执行全部 insert/update、更新产品 version/时间、保存 committed 回执。任一步异常（包含约束、SQLite busy、磁盘/提交失败）整体 rollback，凭据仍为 ready；绝不能按行捕获后继续提交。
5. 相同凭据的并发确认最多一次成功，后到者读回原结果；SQLite 忙返回可重试错误，不把忙误报为提交成功。提交进程中断后以事务恢复和回执判断，不猜测已保存数量。

所有产品库手动写入也使用同样的短写事务与校验。手动编辑/删除携带读取时的 version，事务内不一致返回 409 product_stale，不覆盖其他标签页的修改。手动新增命中同厂家同型号返回 409 product_exists；同名疑似重复返回候选和 409 suspected_duplicate，用户明确“仍新增”后携带 allow_suspected_duplicate=true 重交；该参数不能绕过型号唯一约束。手动编辑若形成同名疑似重复采用同样确认规则，并排除自身匹配。

### 6. API 契约（未来实现）

统一前缀 `/api/product-library`，产品 payload 为第 2 节字段（不返回数据库的整数分）。所有请求在后端权威校验，拒绝未知字段；更新和确认不信任客户端传入的旧值或计算计数。

| 方法与相对路径 | 请求 | 成功响应 |
| --- | --- | --- |
| GET /products | q（可空，最多 200 字符）、manufacturer（规范化后精确匹配）、sort=updated_desc\|price_asc\|price_desc、page>=1、page_size=20（1～100） | 200 `{items,total,page,page_size}`，列表 items 为完整产品字段 |
| GET /manufacturers | 无 | 200 `{items: string[]}`，从现有产品 distinct 厂家派生，按名称稳定排序，不维护厂家档案 |
| GET /products/{id} | 正整数 ID | 200 产品 |
| POST /products | manufacturer_name、六列字段；可选 allow_suspected_duplicate，默认 false | 201 产品 |
| PUT /products/{id} | manufacturer_name、六列完整字段、version；可选 allow_suspected_duplicate | 200 产品；可空字段显式 null 清空，缺字段 422；无实际变更不递增 version |
| DELETE /products/{id} | JSON `{version}`，页面已明确确认 | 204；永久删除此产品，不影响竞品或回执 |
| GET /template | 无 | 200 xlsx 下载，正确文件名和 Content-Type |
| POST /imports/preview | 原始 xlsx 二进制 body，Content-Type 为 xlsx；manufacturer_name 使用 URL 编码查询参数 | 201 预览对象；避免仅为上传增加 multipart 依赖 |
| GET /imports/{import_id} | UUID | 200 ready 预览或 committed 原结果；ready 过期 410 |
| POST /imports/{import_id}/confirm | JSON `{decisions:[{row_number,action}]}` | 200 committed 结果；相同决策重放返回相同结果 |

预览对象包含 import_id、status=ready、expires_at、manufacturer_name、counts、rows。每行含 Excel row_number（从 2 开始）、规范化六字段、category、errors（field/code/message）、candidate（可多条的 ID/名称/型号）、existing_id/version（唯一型号匹配时）、diff、allowed_actions、default_action。

counts 中 `total_rows` 为非空数据行；new/existing/conflict/suspected/invalid 互斥且和等于 total_rows；ignored_blank_rows 单列。planned_insert/planned_update 由当前选择计算，初始仅 new 默认 insert，其余默认 skip。前端展示选择后的计数；后端确认时重算，不能信任前端计数。

confirm 必须对每个非空数据行恰好提供一个决策，不能重复/遗漏/添加行号。action 只能是 insert/update/skip，须属于该行 allowed_actions；invalid 仅 skip。suspected 选择 insert、conflict/existing 选择 update 均须在 UI 逐行明确确认，不提供默认批量覆盖。diff 无变化不能 update。只排序 row_number 后规范化决策做摘要，请求数组顺序差异不造成幂等冲突。

最终结果含 import_id、status=committed、inserted、updated、skipped、invalid、rows（row_number、outcome=inserted/updated/skipped/invalid、product_id 可空、reason_code）。四个数量互斥且和等于 total_rows；invalid 是因校验错误未写入，skipped 是合法行用户跳过。回执中的 product_id 是提交时的结果标识，产品后来删除不重建、不重放写入。

错误响应沿用顶层 `{code,message}`，可附 field、row_number、errors、candidates。常用 HTTP/code：400 invalid_workbook / invalid_structure / no_product_rows；413 file_too_large / workbook_limit_exceeded；415 unsupported_excel_format；422 invalid_product / invalid_decisions / no_changes_selected；404 product_not_found / import_not_found；409 product_exists / suspected_duplicate / product_stale / preview_stale / idempotency_conflict；410 preview_expired；503 database_busy；500 product_save_failed / import_save_failed。文件中的行级格式错误是正常预览响应中的 invalid 行，不返回整文件 422。未列明的解析异常安全映射 invalid_workbook，数据库异常不泄露 SQL/路径。

### 7. 页面交互与查询

- 列表沿用 PageHeader、工具栏、Table、Dialog、Notice。标题“产品库”，简述“厂家产品资料”；操作为手动新增、批量导入、下载模板。列表显示厂家、型号、名称、批发价、更新时间及查看/编辑/删除；长参数/卖点在详情完整换行展示，不建统计大屏。
- 搜索为一个普通关键词，经 trim 后，在型号/名称/参数/卖点/厂家中任一字段匹配即命中；空查询返回全部。SQLite LIKE 采用参数化并转义 `%`、`_`、反斜线，使它们按字面字符搜索；沿用 SQLite 默认大小写行为（ASCII 不区分大小写，其余不另做语言折叠），不分词、不按词拆分，不搜索价格备注。
- 搜索与厂家筛选使用 AND，厂家选项来自全部现有产品。分页采用后端分页；变更搜索/筛选/排序时回第 1 页，默认 20 条。updated_desc 按更新时间降序、ID 降序；价格排序未知价格始终最后，相同价格按 ID 降序。price_asc/desc 纳入核心 V1，不添加其他排序系统。
- 详情/新增/编辑采用现有弹窗或面板习惯，不增加导航入口。必填厂家和名称，其他字段允许留空；手动清空明确保存 null。保存失败保留表单；成功刷新列表/厂家选项。已有同型号引导查看/编辑现有记录，不静默新增或更新。
- 删除确认显示厂家、型号（空时“未提供”）和名称，提示永久删除，不默认确认；删除失败保留内容并报错。分页最后一条删除后回退到有效页。列表刷新失败明确提示“操作已完成，列表刷新失败”，不引导重复提交。
- 导入步骤 1 展示限制、厂家必填及模板入口；步骤 2 显示五类数量、实际计划新增/更新数、逐行错误和字段差异，可分页查看但确认覆盖全部决策。错误行固定跳过，不让用户勾选导入；确认按钮旁说明错误/跳过数。
- 步骤 3 显示实际结果和逐行反馈；允许关闭或返回列表。用户选择 update/疑似重复 insert 时明确提示实际覆盖/新增内容。取消、返回改文件或改厂家都会废弃当前选择并重新预览；确认前不写产品数据。
- 列表、详情、上传、预览、确认分别处理 loading/empty/error/ready；网络错误不能显示为零数据。弹窗支持键盘、焦点返回、标签和文字错误，不仅靠颜色表达。桌面优先，基础窄屏不溢出；不复制设置页的局部换肤为全局新风格。

## Testing Decisions

测试外部可观察行为及数据结果，不为内部辅助函数逐个镜像测试。主要边界为后端 API + 隔离 SQLite；pytest 用程序生成最小 xlsx 样本。金额、规范化、解析和重复边界必要时补少量服务测试；Vitest 保护表单/选择/计数；Playwright 只覆盖关键真实浏览器路径。

已有先例：后端 TestClient/get_db 覆盖和内存 SQLite fixture；现有迁移测试在临时数据库验证；前端 Vitest 页面测试；E2E 的 installApiMock 和未声明 API 拒绝机制。不可运行正式 lifespan 调度或访问正式 SQLite，测试用专用 fixture 禁用外部采集与调度副作用。迁移测试使用临时数据库，核对新增表及唯一/CHECK 约束，升级不更改现有监控表记录；降级会删除产品库与回执，必须明确数据损失，不对正式库试跑。

实现阶段先完成单一闭环（模板→预览→确认→查询）和上述关键 API 验收，再覆盖手动维护及关键 E2E；不机械把全部 pytest 场景重写为浏览器测试。最终运行相关 pytest、Vitest、类型检查、构建和产品库 Playwright，按影响面决定既有回归范围。人工验收检查真实经外部整理的少量厂家 Excel、价格与参数保真、差异确认和删除交互；没有真实资料时记录待人工核验，不能用模拟样本代替真实业务证据。

- 独立导入历史管理大屏、后台导入队列、分布式任务、通用导入平台、多用户权限系统。
- 为上述未来能力预建空表、接口、适配层或配置。

### 优先级与默认值

- 核心 V1（必须）：本 Spec 定义的产品管理、查询、模板、三步导入、重复确认、事务与重试保护，含低成本批发价排序。
- 建议后续（P3 / 非验收阻塞）：错误报告下载、完整产品库 Excel 导出。本轮不设计专用接口、存储、通用导出框架；若以后实施，另明确公式注入防护与导出合同，不推迟核心交付。
- 5 MiB、1000 行、30 分钟有效期、字段长度、两位小数和分页为本 Spec 的简单默认限制；变更需集中修订对应合同与测试，不由实现无声放宽。
- 本 Spec 新增一张业务产品表及一张必要导入凭据表；后者仅解决跨请求确认和持久幂等，不是用户可管理的历史业务。未要求统一导入/采集架构，禁止复用监控任务模型。
