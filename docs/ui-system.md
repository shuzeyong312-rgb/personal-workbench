# UI System

## 1. 目标

本文件定义 Personal Workbench 的长期 UI 规则。

它负责约束：

- 全局视觉风格；
- 页面骨架；
- 导航层级；
- 基础组件；
- 状态与语义色；
- 三类 Reference Page 的结构基线。

它不负责逐页业务需求。具体页面展示什么字段、按钮执行什么业务行为，由对应 Feature Spec 定义。

当前页面业务状态与合同更新关系见 [Spec 索引](specs/README.md)。Reference 图保留视觉基线，不代表当前按钮、导航或业务内容。

系统设置已按 [视觉改版 V1](specs/system-settings-visual-refresh-v1.md) 完成局部试点：浅灰底、低装饰内容区、Row、二级设置导航及原生 Radio / Switch。该例外仅属于设置页，不代表其他页面已换肤，不推翻以下全局规范。

核心原则：

> 新页面应延续现有设计体系，而不是重新设计一套 UI。

## 2. 已确认的视觉方向

竞品列表视觉升级以 [V1.3 Spec](specs/competitor-list-visual-v1.3.md) 覆盖旧有蓝紫雾感、渐变和轻毛玻璃默认值。当前代码已迁移 App Shell、首页、竞品列表与产品库；其它页面按各自 Reference 逐页迁移前，不视为已换肤。V1.2 的列表结构和业务行为继续有效。

关键词：

> 中性浅灰 / 稳定白色表面 / 石墨文字 / 克制品牌蓝 / 高密度可扫描 / 精致但克制

### 2.1 背景

- 工作区使用中性浅灰背景，内容表面使用清晰白色；
- 背景和导航不使用渐变、光晕、毛玻璃或装饰纹样；
- 白色表面、细边线、留白、文字层级和对齐负责建立空间关系；
- 禁止将蓝紫色雾感背景恢复为默认，禁止高饱和大面积渐变、赛博朋克和纯深色大底。

### 2.2 卡片

- 主体内容使用白色不透明表面；
- 以清晰细边线区分工作区和内容，不默认使用投影或模糊；
- 数据密集区域优先可读性，表头与行分隔使用中性灰阶；
- 统计项优先使用数字层级和分隔带，不默认增加独立卡片。
- 同一视口避免连续嵌套卡片；优先用留白、分隔线和标题层级区分内容。

### 2.3 色彩

主色：

- 品牌蓝作为主要操作、链接、焦点和选中态；
- 不再使用蓝紫作为装饰性科技色。

辅助语义色：

- 绿色：成功、正常、下降类正向状态；
- 紫色：SKU / 分类类状态；
- 橙色：提醒、价格变化等辅助状态；
- 红色：失败、异常、风险；
- 浅蓝：一般信息、采集中等中性状态。

要求：

- 色彩丰富但克制；
- 不同状态必须同时配合文字或图标，不能只依赖颜色；
- 页面不得自行发明新的主色体系。

### 2.4 字体与数字

- 中文必须清晰易读；
- 页面标题有明显层级；
- 关键数字可以加大加粗；
- 表格正文保持可快速扫描；
- 不使用装饰性字体。

沿用全局 `Noto Sans SC`、`Microsoft YaHei` 和系统无衬线回退，不从 CDN 加载字体。字号按 12 / 13 / 14 / 16 / 20 / 28 / 32px 建立层级，正文行高约 1.5，标题行高 1.2–1.35；中英文混排使用同一字体栈。金额、计数、库存、百分比和日期使用 `font-variant-numeric: tabular-nums`。未知值显示 `—`，不得格式化成 0。

当前迁移页面采用 Token：画布 `#f3f4f6`、白色表面 `#ffffff`、浅表面 `#f6f7f8`、石墨文字 `#20242c`、次级文字 `#626b78`、边线 `#dde1e6`、操作蓝 `#2563eb`。成功绿 `#19805c`、提醒橙 `#d88332`、错误红 `#b04e5d` 作为语义色延续。尚未迁移的页面可能仍引用旧局部色值，迁移前核对该页 CSS；状态色必须配合文字或图标。

## 3. 全局页面骨架

桌面端优先。

所有主要页面保持：

```text
左侧分级导航
+
顶部全局区域 / 面包屑 / PageHeader
+
主内容区
```

主内容区使用统一留白和细边线。迁移页面采用白色表面与中性灰画布；圆角只区分控件和对话框，不以卡片重复制造层级。

V1 不单独设计完整移动端系统，只保证基础响应式不崩坏。

复用 `.main-content` 的最大宽度与流式内边距，不为单页叠加固定宽度容器。沿用 4 / 8 / 12 / 16 / 24 / 32px 间距刻度。按任务选结构：总览先呈现待处理信息，列表突出筛选和表格，详情按事实层次组织；不要让每个信息组都变成相同卡片。窄屏优先重排和换行，关键文案、状态及操作不得被裁切。

## 4. 左侧导航：Personal Workbench 信息架构

整个产品是“个人工作台”，竞品监控只是其中一个工具模块。

导航基线：

```text
个人工作台

首页

工作工具
产品库
竞品监控
  ├─ 竞品监控大屏
  ├─ 我方商品
  ├─ 竞品列表
  ├─ 竞品分组
  └─ 采集记录

规划工具（规划中）
  ├─ AI智能助手
  ├─ 全网比价
  ├─ 自动询价
  └─ 自动上架

系统设置
```

规则：

- 一级导航代表工具 / 系统模块；
- 二级导航代表模块内部页面；
- 竞品监控支持折叠/展开，当前二级页保持可识别；
- 当前二级页面明显高亮；
- 二级导航通过缩进、字号、背景和图标层级体现父子关系；
- 不把竞品监控表现成整个产品本身；
- 首页为任务入口工作台，产品库、竞品监控与系统设置已启用；四项规划工具保留占位路由并明确标记“规划中”，不将占位页解释为业务已实现；
- 组分析从大屏/分组入口进入，未新增独立竞争分析导航；导航融合仍是后续规划；
- 后续新增工具时继续沿用相同一级模块结构。

左上角品牌区固定表达：

```text
个人工作台
工作提效工具集
```

或语义等价文案。

### 4.1 首页与 Shell（2026-10-20）

按 [整体体验升级 V1](specs/workbench-experience-v1.md) 实现：桌面侧栏 232px；760px 以下使用文档流中的非模态折叠导航，选择页面后收起，Escape 收起并返回触发按钮，关闭时隐藏导航不可聚焦。提供跳至主内容链接与返回首页 / 竞品模块总览的面包屑。高频导航无入场动画，焦点可见且尊重 reduced-motion。

首页使用引导标题、职责不同的竞品监控 / 产品库区域、监控任务行、设置入口和安静的规划清单；不展示 KPI，不发数据请求，不代替竞品大屏。双列工作区在 760px 以下单列；相关样式限定 `Workspace.css` 的首页与 Shell 范围，不改变业务页面内部组件合同。首页是任务选择入口，不新增第四种业务数据 Reference Page。

2026-10-21 按用户授权的[首页精密工作舱升级](specs/home-command-center.md)，首页内容区局部允许静态分层几何构型、细连接线和模块边线识别；保留浅灰/白色/石墨/品牌蓝，不扩展到导航或业务页面，不引入光晕、霓虹、背景纹样、外部字体或依赖。保留七项真实任务入口与四项静态规划工具，只有用户触发的短反馈；减弱动效时移除首页过渡和位移。这里的“不发数据请求”指 HomePage 不自行取数；App 启动原有监控摘要预加载仍然存在，本次未改动。

## 5. 顶部区域

统一包含：

- 面包屑；
- 页面标题；
- 一句简短页面说明；
- 右侧主要操作；
- 只在全局搜索、通知或用户入口已有实际功能时显示；不展示无行为的占位装饰。

面包屑用于表达：

```text
个人工作台 / 一级模块 / 当前页面
```

详情页可进一步增加上级页面：

```text
个人工作台 / 竞品监控 / 竞品列表 / 竞品详情
```

不要每页重新设计顶部结构。

## 6. 基础组件

V1 优先统一：

- Button
- Input
- SearchInput
- Select
- Card
- StatCard
- Table
- Dialog
- Badge
- Toast
- EmptyState
- PageHeader
- Breadcrumb
- FormField
- LoadingState
- ErrorState
- Pagination
- TrendChart

新页面优先组合现有组件。

不要因为单个页面需求重新创建一套 Button / Card / Table / Badge 风格。

主要、次要、危险按钮的视觉层级保持一致；Input / Select 保留可见标签、禁用态和焦点态；表格数字按列对齐，行高适合连续扫描；Badge 的文字说明与颜色并存。Dialog / Drawer 必须保持键盘可达并将焦点放在合理位置；Loading / Empty / Error 状态应给出真实状态或可执行的下一步。先复用原生控件和现有 CSS，不为单页引入组件库。

延用现有尺寸基线：紧凑控件约 32px、常规控件 36–40px；输入框和按钮使用约 8px 圆角，内容卡片约 12px，Dialog 约 16px，状态 Badge 保持胶囊形。表格正文约 13px、辅助字段约 11–12px，垂直内边距通常 10–12px。只在新控件无法对应这些基线时才扩展尺寸。

## 7. 状态规范

所有数据页面至少考虑：

```text
Loading
Empty
Error
Normal
```

提交操作至少考虑：

```text
Submitting
Success
Failure
```

采集业务至少考虑：

```text
采集成功
采集中
采集失败
未知
```

空状态必须告诉用户下一步可以做什么。

# 8. Reference Page 01：竞品监控大屏

定位：

> 数据总览型页面。

它回答：

> 今天发生了什么？

这是竞品监控模块的总览入口，也是 Dashboard 类页面的视觉基线。

### 8.1 当前结构（Group-first）

```text
PageHeader + 我方店铺 + 立即采集 / 添加监控商品
↓
组级 KPI 与异常采集
↓
今日需要关注的商品组（宽主体） + 采集状态概览（操作侧栏）
↓
默认折叠的近 7 天历史趋势
```

四项 KPI：监控商品组、今日有变化商品组、今日涉及变化竞品、异常采集。前三项来自 Backend Group Attention；异常采集沿用 Dashboard 数据。

### 8.2 当前规则

- 主体是“今天先看哪些商品组”，旧竞品级今日变化大表不再作为核心；单品事件进入 Group Detail / Competitor Detail。
- 每个关注项展示组名、我方商品身份、关注等级、变化竞品数、最多三条 Backend 原因、检测时间和“进入组分析”；保持 Backend 顺序，不展示内部评分。
- 当前绑定 own 且至少一个直接竞品的组计入监控组；还须有今日可纳入 Attention 的直接竞品事件才进入关注列表。不把无变化或未绑定组伪装为关注项。
- 关注等级只表示查看优先级，不是风险、销量或竞争力。未知、空数据与加载失败分开；局部失败不掩盖采集状态和趋势。
- 大屏 Header 提供添加监控商品与全量手动批量采集入口；统一添加先验证真实店铺，立即采集覆盖全部 active self + competitor。未配置店铺时提示前往系统设置。
- 采集概览保留数据库摘要及当前批次，展示休息/冷却/验证等权威状态；不得由本地 timer 伪造状态或剩余时间。
- [日常运营优化](specs/dashboard-operations-ux.md) 将关注列表默认展示调整为前 5 组，保留展开和 Backend 顺序；列表尾部提供全部商品组入口，采集侧栏提供采集记录入口。趋势通过原生折叠区按需查看，不新增图表。
- 零关注事件不能证明全部无变化。未完成采集、今日失败、部分失败、采集统计未知和成功空结果分别表达；成功/失败是采集次数，包含我方与竞品，不能当作去重商品覆盖率。加载或失败不展示“暂无采集记录”。
- 延续紧凑布局、克制 KPI、轻辅助色和可读图表，不做 BI 大屏；Reference 图的旧竞品表、快捷添加入口和旧 KPI 仅作历史视觉参考。

### 8.3 Group Detail V1：分析型详情

组分析复用现有卡片、表格、Badge 与 Detail 基线，展示我方概览、事实差距、当前直接竞品横向比较、今日事件和 7 / 30 天动作。未绑定、字段未知、区间重叠和不可比较须明确表达；进入单品证据检查来源。

现有比较是价格区间 / MOQ / SKU / 完整库存的事实关系，不是排名表或竞争力分数。Group Detail V2、公司主标识排序、经营指标和导航融合未实施；不能借视觉治理提前引入。

# 9. Reference Page 02：竞品列表

定位：

> 列表 / 筛选 / 管理型页面。

它回答：

> 我现在监控了哪些商品？

也是未来“采集记录”“自动上架列表”“选品列表”等管理型页面的主要参考。

### 9.1 固定结构

```text
PageHeader + 主要操作
↓
搜索 / 筛选卡片
↓
列表统计信息
↓
主数据表格
↓
Pagination
```

顶部操作：

- 通用批量操作菜单：直接竞品支持设置分组、停止/恢复及永久删除；我方商品批量操作仅停止/恢复。
- 添加与采集入口已集中到大屏，两个列表都不再提供这些按钮。

表格首列支持通用选择，包括已停止监控的商品；表头全选仅影响当前页，同筛选下跨页保留。各批量操作独立判断资格，不按 active 清空 selection。分页固定每页 10 条，先筛选再分页；我方和竞品使用 ownership 分流，不从 group_role 推断身份。

筛选区参考：

- 商品名称 / offerId / 店铺搜索；
- 竞品组；
- 商品状态；
- 是否有变化；
- 采集状态；
- 重置 / 筛选。

表格信息架构参考：

- 商品信息；
- 店铺名称；
- 竞品组；
- 当前价格；
- SKU 数量；
- 最近变化；
- 最近采集时间；
- 商品状态；
- 采集状态；
- 操作。

### 9.2 List 规则

- 搜索和筛选集中在统一卡片中；
- 主操作放 PageHeader 右侧；
- 表格为主体，不使用大量卡片替代表格；
- 商品列可使用缩略图 + 主标题 + 次级描述；
- 状态统一使用 Badge；
- 价格变化可使用数值 + 趋势箭头；
- 已下架使用单行 Badge 显示；
- 操作列只保留“详情”，停止 / 恢复监控和删除竞品进入详情页处理；
- 次要信息进入详情页；
- 分页固定在列表底部。

以后所有管理型列表优先复用这一结构。

### 9.3 竞品分组页面

竞品分组已启用，页面定位为以我方商品型号为中心的管理与总览混合页，不使用传统 CRUD 表格。当前支持新建组、重命名、删除组并解除成员关系、未分组、Summary、分组卡片、组分析及列表筛选入口。商品单条归组在相应列表/详情操作；我方身份不再由分组页人工指定。

页面结构：

```text
PageHeader + 新增竞品组
↓
紧凑竞品组卡片 Grid（组名使用商品型号）
```

分组页面当前仍遵守其已实施布局；后续视觉迁移使用中性画布、白色表面和分隔线，不沿用蓝紫雾感背景或重复阴影。卡片展示竞品数量、监控中、竞品价格区间、今日变化和最近变化，提供组分析、查看竞品与更多操作，并展示我方基准的绑定/未绑定事实；未分组是 `group_id = NULL` 的虚拟分类，只在存在未分组竞品时显示，并只提供查看竞品。

# 10. Reference Page 03：竞品详情

定位：

> 详情 / 趋势 / 历史记录型页面。

它回答：

> 这个竞品现在是什么状态，最近发生了什么？

也是未来其他实体详情页的主要参考。

### 10.1 固定结构

```text
PageHeader + 操作
↓
商品概览卡片
↓
趋势卡片组
↓
SKU 信息
+
最近变化记录
+
最近采集记录
```

商品概览区参考：

- 主图；
- 主图下方展示当前最新 ProductSnapshot 的商品图库缩略图；缩略图条不超过大图宽度，点击只切换本地预览，首图始终可直接切回；
- 商品标题；
- 店铺；
- 商品链接；
- offerId；
- 所属竞品组；
- 详情页所属竞品组使用 Badge/Pill 展示，并提供轻量“修改”入口；该入口只负责选择已有竞品组或“未分组”；self 入组为 own，解除仍保留 self，目标已有 own 时冲突。它不承担新建、重命名、删除竞品组或人工识别商品身份；
- 当前价格；
- 最近一次真实价格变化；
- 商品状态；
- SKU 数量；
- 当前库存；
- 最近采集时间；
- 监控状态。

趋势区参考：

- 价格趋势卡；
- 库存趋势卡；
- 销量趋势占位卡，明确“销量数据待接入”，不展示 POC 或伪造数据；
- 统一时间范围切换 7 天 / 30 天，同时作用于价格和库存趋势；
- 缺失日期保留为空点，未知库存不绘制为 0；
- 价格和库存趋势支持真实数据 Tooltip。

下半区参考：

- SKU 信息表；
- SKU 信息表列为 SKU 规格、SKU ID、库存、SKU 价格；未知价格显示 `—`；
- 最近变化记录；
- 最近采集记录。

### 10.2 Detail 规则

- 顶部先回答“它现在是什么状态”；
- 中部回答“它最近怎么变化”；
- 底部回答“具体 SKU 和历史发生了什么”；
- 概览桌面端采用图片区、核心信息区、状态摘要区三列，窄屏自然折叠为单列；
- 列表只展示 `Competitor.main_image_url`，详情页才展示 Snapshot 商品图库；所有真实 CDN 图片使用 `no-referrer`，缺失或加载失败显示“暂无主图”；
- 详情页常驻删除操作使用弱化危险视觉，确认 Dialog 继续使用实心 danger；
- 图表视觉必须与 Dashboard 保持一致；
- 详情页允许信息密度略高，但仍保持清晰分区；
- 不要把所有字段塞进一个巨大表单。
- 工作台 shell 固定在 viewport 内，Sidebar 可独立滚动，main content 是右侧唯一主滚动容器；
- Detail Overview 保持自然高度，不使用固定高度、max-height 或内部纵向滚动；固定高度只属于底部三张历史卡；
- 底部 SKU、最近变化和最近采集记录三张卡桌面端等高，历史内容在卡片内部滚动，表格表头使用 Detail scoped sticky 样式；
- Sidebar 隐藏横向溢出但保留纵向滚动；竞品列表不设置固定高度，整页由 main content 滚动；
- 内嵌滚动区域使用 `overscroll-behavior-y: contain`，不使用 JS wheel 阻断。

以后实体详情页优先参考本页面。

### 10.3 采集任务与系统设置

采集任务沿用 List / 运行状态的轻量布局：当前批次、默认折叠的批次明细、持久化单商品采集历史。明细保持 Backend 顺序；运行、计划休息、风控冷却、人工验证、完成分清语义，ownership 不使用强状态色。历史搜索/筛选/分页与 Runtime 相互独立，页面不提供采集发起或重跑。

系统设置按业务分类组织；竞品监控分析下设店铺识别、采集策略和工作浏览器，各设置模块独立加载和保存。新外观仅限 settings scoped 样式，其他页面继续遵守全局视觉规范。

## 12. 表格原则

- 列名清晰；
- 行高舒适；
- 信息密度中等；
- 数字对齐统一；
- 商品信息优先采用“缩略图 + 标题 + 次级说明”；
- Badge 统一；
- 操作列简洁；
- 重要变化突出；
- 次要字段不强塞在表格里。

禁止为了展示所有字段造成横向信息过载。

---

## 13. 图表原则

V1 使用简单趋势图。

要求：

- 折线清晰；
- 网格线轻；
- 坐标轴弱化；
- Tooltip 简洁；
- 蓝 / 绿 / 紫 / 橙等色彩语义在同一产品内保持一致；
- 图表表面使用白底和细边线；不以阴影或渐变区分图表类型。

不使用复杂 3D 图表或装饰性图形。

---

## 14. 间距与圆角

统一使用 spacing scale：

```text
4 / 8 / 12 / 16 / 24 / 32
```

圆角只保留少量等级：

```text
small
medium
large
```

控件采用小圆角，内容表面以边线和留白建立层级；避免所有元素套用同一大圆角。

当前迁移 Token 以本文件第 2 节及已有 CSS 变量为准；根目录 `DESIGN.md` 与 `.impeccable/design.json` 记录首页 / Shell 的实际摘要，不创建第二套视觉权威。

---

## 15. 交互原则

- 主要操作明确；
- 危险操作需要确认；
- 加载中禁止重复提交；
- 保存 / 采集后必须有明确反馈；
- 错误说明发生了什么；
- 可恢复错误应给出下一步操作；
- 不为了“高级感”隐藏核心操作。

---

## 16. 动画原则

只使用轻量、有功能价值的动画：

- Dialog；
- Toast；
- Hover / Focus；
- Loading；
- 简单状态切换。

禁止：

- 大量页面转场；
- 弹跳；
- 复杂背景动画；
- 炫技型交互。

Hover / Focus / Active 过渡通常为 120–180ms，Dialog / Drawer 进出通常为 160–220ms，使用短促的 ease-out 进入与 ease-in 退出。只动画用户触发且能帮助理解的状态变化；结束后内容、语义状态和焦点必须正确。新增动效应提供 `prefers-reduced-motion: reduce` 回退，持续 Loading 在减少动态效果时显示静态状态。

- **反馈与退出**：新建/编辑仅在有未保存修改时确认放弃；保存结果未知时保持禁止重发，允许确认退出核对。字段错误关联输入并提供可聚焦摘要与字段跳转。所有关闭路径共用同一规则；Tab/Shift+Tab 在模态首尾循环，关闭后回到触发控件。
- **资料与风险**：详情把客户资料与内部价格分开组织，三种复制均使用既有按钮层级与状态反馈。导入显示上传、核对、结果三个真实阶段；报价阶段只反映配置、复核、下载条件，不新增状态机或隐藏风险条件。报价风险字段用中文业务名显示；全部原安全确认仍必须完成。
- **动效**：本轮采用按钮颜色 150ms 过渡；高频列表、编辑和抽屉不增加入场等待。reduced-motion 关闭过渡。2026-10-19 的只读动效建议未全部采用，不视为实现要求。
- **作用域**：样式限于 `.library-page`、`.library-dialog` 及专属子类；共享 PaginationBar、全局 Shell 和其他业务页面内部不修改。原生文件输入保留键盘/文件选择能力，以中文选文件区域和真实文件名呈现。
