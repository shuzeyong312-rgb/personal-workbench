### 结论与后续集成建议

- **稳定性部分通过：** 同一目标测试会话在初始、最大化、还原并位移后的状态下均可重新核验身份并完成草稿输入/清除；三轮无害输入验证均没有发送。
- **发送链路未通过验收，不能据此启用正式触达：** 尚未验证实际文案+商品链接的输入/预览、点击发送、发送结果识别及失败/未知区分。发送只能在用户指定单一测试对象、提供完整文案和 URL 并明确授权该次测试后进行。
- **后续最小集成边界：** 在 Windows 已登录交互桌面运行一个串行桌面执行器进程；FastAPI 只创建任务、校验授权及编排状态，不在 Web worker 中直接操控 UI。复用第三轮经验证的“重新搜索并唯一匹配客户 → 行身份复核 → 滚动按钮到视口 → 再核对行 → 打开会话 → UIA/截图双重核对对象”；输入区暂用窗口截图识别与相对定位，操作前强制验证窗口标题、会话身份及空草稿。
- 执行器向 FastAPI 回报 `queued / running / awaiting_confirmation / sending / succeeded / failed / unknown / cancelled` 状态，通过现有前端 API 轮询或 SSE/WebSocket 将任务事件展示到 React。人工确认必须发生在最终预览之后、实际发送之前；暂停在安全步骤边界生效，取消在当前 UI 操作完成后尽快生效，任何状态不明都不得自动重发。
- 以稳定客户业务标识、任务/活动标识及规范化内容摘要记录处理结果；已成功任务拒绝重复执行，`unknown` 转人工复核。只有存在明确触达授权且未撤回/退订的客户才能进入任务队列，授权证据应与任务绑定。上述仅为集成建议，本轮未创建执行器、API、数据库表或 React 代码。

### 本轮异常策略

任一窗口缺失、对象昵称不符、会话加载/响应超时、编辑区无法定位、输入回读与预期不同、内容预览不完整或发送结果无法确认时，立即停止当前客户任务并记录错误与最后一次确认状态；不沿用旧窗口索引/坐标，不自动切换到相邻客户，不自动重发。发送前异常归为 `failed`；发送动作已触发但无可靠结果证据归为 `unknown`，由人工检查。
