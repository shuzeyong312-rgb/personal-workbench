# 客户触达 V1：开发态使用说明

## 启动

1. 在 `backend` 下安装现有 requirements。只有隔离开发数据库才运行 `alembic upgrade head`；不要把迁移直接应用到正式工作库。
2. 默认模式 `PERSONAL_WORKBENCH_CUSTOMER_REACH_MODE=simulated` 只演练任务状态，不会操作 1688 或发送消息。
3. 启动 API：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8200`。
4. 在 `frontend` 下运行 `npm exec vite -- --host 127.0.0.1 --port 5173`，打开工作台左侧“客户触达”。

## 当前能力

- SQLite 持久化旧版单客户任务和新版推广任务；推广任务记录所选分类、消息内容指纹、客户稳定标识、列表顺序、授权依据、逐客户处理状态、发送结果及异常原因。
- 推广任务从“已成单客户”或“询盘客户”列表读取客户；仅处理同时具备稳定登录标识和明确营销授权标记的行，缺少任一项或重复身份的行会跳过。
- 每位客户分别打开旺旺、复核昵称与稳定登录标识、填写消息和链接、核对可见草稿，再等待用户确认。确认和跳过请求均绑定当前任务、客户标识及内容指纹；旧任务授权不能作用于新客户。
- 支持逐客户跳过、暂停、继续和取消。恢复时保留已完成客户；确认发送后不接受取消；结果不确定时停止队列且不重发。
- 模拟模式演练客户队列、逐客户确认、跳过及记录，不会操作 1688 或发送消息。
- 截图读取接口只返回执行器保存到该任务的图像。模拟模式没有桌面截图。

## 真实桌面执行边界

`desktop` 模式使用 WinApp UIA 实时查询窗口和控件，进入所选客户分类并读取分页列表。客户行中的昵称、稳定登录标识和明确授权文字必须可见；每次打开旺旺时执行器重新核对客户行，聊天侧同时核对昵称和稳定登录标识。POC 中的主发送按钮不是可调用 UIA 控件；执行器要求 UIA 可见“发送”文字位于聊天文档右下方，并要求新截图中的唯一按钮区域与该文字位置重合。缺少结构/文字或截图证据时会停止。点击前会再核对会话和草稿，并检查接待中心仍在前台。点击后无法判定结果时记为 `unknown`，不重试。

暂停和取消会在 UI 操作边界被检查；正在执行的一次 UIA 命令无法中断，命令结束后会停止后续操作。图片定位使用 Pillow，随 `backend/requirements.txt` 安装。

模式通过 API 进程环境变量选择：`PERSONAL_WORKBENCH_CUSTOMER_REACH_MODE=simulated|desktop`。桌面执行器必须和已登录的 1688 客户端运行在同一个可交互 Windows 会话中；模拟模式是默认值。

桌面执行器通过 `winapp ui ...` 调用 WinApp CLI。2026-10-25 本机交互会话实测 `winapp --version` 为 0.7.1，WindowsApps 下长度为 0 的 `winapp.exe` 是可正常分派的执行别名；`list-windows` 与 UIA 查询均能启动。搜索无匹配时 CLI 返回退出码 1 和 `matchCount: 0`，执行器只将这种明确空结果视为“未找到”，其他错误仍停止。API 必须和工作台处于同一已登录交互桌面会话。不要在密码框中自动登录；登录和验证码由用户处理。

## 多客户推广任务操作

1. 在“客户分类”选择已成单或询盘客户，填入完整文案和商品链接，创建任务。
2. 页面显示从列表读取的客户顺序。没有明确授权或稳定身份的客户标记为已跳过；不要把“已成单 / 询盘”本身当作营销授权。
3. 当前客户进入“发送前核对”后，复核识别身份、授权依据、文案和链接。选择“跳过此客户”会记录未发送并继续下一位；“暂停”后可恢复未完成客户。
4. 每位客户分别选择“确认向此客户发送一次”。确认后按钮请求只对这一客户和本次内容有效；系统发送一次并检查聊天记录回显及失败提示。
5. `unknown` 表示点击后无法确认结果。先由人工检查旺旺聊天记录，系统不会重发或继续队列。

当前 UIA 客户行与授权标记解析基于可见文本字段名称和文字模式。1688 客户管理页面的实际列名、授权标记和稳定登录标识必须在目标客户端实机验证；字段不匹配时执行器应停止或跳过，不会猜测授权。

当前桌面窗口选择优先采用唯一前台 `AliWorkbench` 窗口，只有没有唯一前台窗口时才按工作台/接待中心标题回退。这样可避免在前台接待中心、后台工作台并存时把 UIA 命令发给后台窗口。

## 首位客户非发送验收入口（2026-10-25）

- API 运行在 `desktop` 模式时，客户触达页面提供“首位客户非发送验收”。该按钮实际调用 FastAPI，执行器自动进入“全部客户明细 → 客户资产 → 已成单客户”，不要求预先进入客户页，也不要求手填昵称。
- 请求使用 `preview_only: true`；服务端固定为已成单客户第一页首位客户的非发送任务，固定测试字符 `X`，不需要商品链接。执行模式保存为 `desktop_preview`，复用既有任务表和 recipients JSON，不新增迁移。
- 身份列与操作列是客户端的独立固定表格。执行器按文档顺序选择首行，并核对首行旺旺按钮的位置；聊天侧同时核对可见昵称及 `air.1688.com` 服务面板的 `chatLoginId`。`preview:first:` 只表示该非发送任务的列表显示身份，不代表营销授权或正式营销客户标识。
- 当前客户端的可见编辑区不属于聊天记录 Document。非发送执行器复用本机已安装的 Tesseract（含 eng 数据）读取编辑区截图，追加 `X`，验证可见字符，再只退格一次；清理后核对原编辑区 OCR 摘要。`preview_state.cleanup_required` 记录是否仍需清理，`restored` 记录正常清理核验结果。只保存摘要，不保存原草稿明文。
- 页面隐藏非发送任务的发送按钮；即使直接请求确认接口，服务端也拒绝发送，桌面发送方法另有同样的禁止门槛。单字符输入使用窗口定向 PostMessage，避免中文输入法组合态；没有 Enter 或发送按钮操作。
- 截图保存的是清理前的预览证据；是否已经清理以任务步骤及 `preview_state` 为准。编辑区几何已按本次 Qt 客户端校准，客户端布局或 DPI 改变后须重新校准；不能据此宣称跨布局验收完成。
- 每条 WinApp 命令前检查暂停/取消。已在执行的一条命令可以结束；恢复非发送任务时重新核对同一客户，已清理且摘要一致时不重复输入。

此入口只验证真实非发送链路，不等于普通推广任务的授权字段、正式文案、商品链接及真实发送已经实机验收。详细实机结论见 `docs/qa/1688-client-automation-poc.md` 的本轮续验记录。
