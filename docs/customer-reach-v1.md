# 客户触达 V1：开发态使用说明

## 启动

1. 在 `backend` 下安装现有 requirements。只有隔离开发数据库才运行 `alembic upgrade head`；不要把迁移直接应用到正式工作库。
2. 默认模式 `PERSONAL_WORKBENCH_CUSTOMER_REACH_MODE=simulated` 只演练任务状态，不会操作 1688 或发送消息。
3. 启动 API：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8200`。
4. 在 `frontend` 下运行 `npm exec vite -- --host 127.0.0.1 --port 5173`，打开工作台左侧“客户触达”。

## 当前能力

- SQLite 持久化旧版单客户任务和新版推广任务；推广任务记录所选分类、消息内容指纹、客户稳定标识、列表顺序、授权依据、逐客户处理状态、发送结果及异常原因。
- 桌面连续任务固定为“已成单客户”第一页前五位，不翻页补人，不要求营销授权 UI 字段。单客指定昵称和非发送验收仍保留；模拟模式保留逐客确认行为。
- 五客名单全部锁定、首位草稿核对通过后，一次任务级确认绑定名单顺序、客户身份、店铺和内容指纹。后续每位仍分别核对身份、拒收记录及完整草稿，不能将授权用于名单之外的客户。
- 支持逐客户跳过、暂停、继续和取消。恢复时保留已完成客户；确认发送后不接受取消；结果不确定时停止队列且不重发。
- 模拟模式演练客户队列、逐客户确认、跳过及记录，不会操作 1688 或发送消息。
- 截图读取接口只返回执行器保存到该任务的图像。模拟模式没有桌面截图。

## 真实桌面执行边界

`desktop` 模式使用 WinApp UIA 实时查询窗口和控件。首先复用当前 AliWorkbench 原窗口：WinApp 枚举结合 Win32 隐藏窗口枚举，按进程实际 EXE、店铺标题和 HWND 核验；后台激活、最小化还原和保留 HWND 的托盘隐藏均不启动 EXE。激活后复核同一 PID、标题及实际前台。没有找到窗口只表示状态未知，不能推断为未登录。没有保留可识别窗口的托盘实现暂不能自动恢复。

当前标签没有客户入口时，在实时截图中 OCR 核验原生“工作台”按钮再返回首页；不关闭业务标签。该回退复用已安装的 Tesseract/chi_sim，工具栏布局变化时安全停止。随后读取第一页前五位并逐客重新绑定同行旺旺按钮；聊天侧复核可见昵称及会话身份，Qt 可见草稿回读一致后才允许发送。发送按钮沿用 UIA/截图及 OCR 核验，点击前持久化一次发送占用。点击后的任何不确定结果进入 `unknown`，不重发。

暂停和取消会在 UI 操作边界被检查；正在执行的一次 UIA 命令无法中断，命令结束后会停止后续操作。图片定位使用 Pillow，随 `backend/requirements.txt` 安装。

模式通过 API 进程环境变量选择：`PERSONAL_WORKBENCH_CUSTOMER_REACH_MODE=simulated|desktop`。桌面执行器必须和已登录的 1688 客户端运行在同一个可交互 Windows 会话中；模拟模式是默认值。

桌面执行器通过 `winapp ui ...` 调用 WinApp CLI。2026-10-25 本机交互会话实测 `winapp --version` 为 0.7.1，WindowsApps 下长度为 0 的 `winapp.exe` 是可正常分派的执行别名；`list-windows` 与 UIA 查询均能启动。搜索无匹配时 CLI 返回退出码 1 和 `matchCount: 0`，执行器只将这种明确空结果视为“未找到”，其他错误仍停止。API 必须和工作台处于同一已登录交互桌面会话。不要在密码框中自动登录；登录和验证码由用户处理。

## 多客户推广任务操作

1. 桌面模式选择已成单客户，填入完整文案和商品链接；单客昵称留空即为固定五客任务。创建只准备名单和首位草稿，不会直接发送。
2. 核对页面展示的完整五客名单、顺序、文案和链接，选择“确认按名单连续发送五位客户”。授权保存在现有 recipients JSON，无需新增数据库表或迁移。
3. 执行器串行处理五人，后续客户不再重复请求授权；明确拒收、身份或草稿不符时不发送该客户，不扩大范围。暂停和取消仍在命令边界生效，发送中不能取消。
4. `unknown` 停止队列。“只读复核结果”仅枚举及读取聊天记录，不聚焦、不截图、不输入、不点击；唯一正文和完整原链接核验成功后，只接续已授权任务中的其余未处理客户。复核失败保持 unknown；重复复核请求不能重复接续。
5. 每位客户的步骤耗时、执行耗时及前台占用保存在 recipients.timing。任务响应 statistics 汇总目标成功率、总耗时和平均执行耗时；总耗时含等待确认，平均执行耗时不含等待。前台占用按 25ms 周期采样原店铺窗口，属于近似值，不把等待确认全部算作占用。

五客任务按身份列文档顺序锁定展示身份，打开旺旺前重新核对该行与操作列的同行关系；不把展示昵称猜成登录标识，聊天侧独立核对会话身份。旧通用分页解析器保留授权标记规则，不作为五客任务的前提。

客户导航始终选原店铺商家工作台，聊天操作选同店铺接待中心。`foreground_not_target` 仅在明确拒绝执行后恢复并重试一次；只读查询超时可有界重试一次，输入、调用和点击超时不得重放。下方验收记录按历史时间保留，当前行为以本节为准。

## 首位客户非发送验收入口（2026-10-25）

- API 运行在 `desktop` 模式时，客户触达页面提供“首位客户非发送验收”。该按钮实际调用 FastAPI，执行器自动进入“全部客户明细 → 客户资产 → 已成单客户”，不要求预先进入客户页，也不要求手填昵称。
- 请求使用 `preview_only: true`；服务端固定为已成单客户第一页首位客户的非发送任务，固定测试字符 `X`，不需要商品链接。执行模式保存为 `desktop_preview`，复用既有任务表和 recipients JSON，不新增迁移。
- 身份列与操作列是客户端的独立固定表格。执行器按文档顺序选择首行，并核对首行旺旺按钮的位置；聊天侧同时核对可见昵称及 `air.1688.com` 服务面板的 `chatLoginId`。`preview:first:` 只表示该非发送任务的列表显示身份，不代表营销授权或正式营销客户标识。
- 当前客户端的可见编辑区不属于聊天记录 Document。非发送执行器复用本机已安装的 Tesseract（含 eng 数据）读取编辑区截图，追加 `X`，验证可见字符，再只退格一次；清理后核对原编辑区 OCR 摘要。`preview_state.cleanup_required` 记录是否仍需清理，`restored` 记录正常清理核验结果。只保存摘要，不保存原草稿明文。
- 页面隐藏非发送任务的发送按钮；即使直接请求确认接口，服务端也拒绝发送，桌面发送方法另有同样的禁止门槛。单字符输入使用窗口定向 PostMessage，避免中文输入法组合态；没有 Enter 或发送按钮操作。
- 截图保存的是清理前的预览证据；是否已经清理以任务步骤及 `preview_state` 为准。编辑区几何已按本次 Qt 客户端校准，客户端布局或 DPI 改变后须重新校准；不能据此宣称跨布局验收完成。
- 每条 WinApp 命令前检查暂停/取消。已在执行的一条命令可以结束；恢复非发送任务时重新核对同一客户，已清理且摘要一致时不重复输入。

此入口只验证真实非发送链路，不等于普通推广任务的授权字段、正式文案、商品链接及真实发送已经实机验收。详细实机结论见 `docs/qa/1688-client-automation-poc.md` 的本轮续验记录。

### 指定单客一次发送路径

用户明确指定“已成单客户第一页首位客户”的一次测试时，在 `desktop` 模式的创建表单填写“单客一次测试昵称”。该昵称必须与实时第一页首行完全一致；API 保存为 `desktop_single`，只纳入这一位客户，发送后立即结束，不遍历下一位。本次一次测试授权记录与客户营销同意分开保存；普通推广队列仍保持原有明确营销授权规则。

该路径复用 Qt 实际编辑区的运行时范围，用 Unicode 剪贴板粘贴正文、Emoji、换行和链接，再从已聚焦的可见编辑区复制回读，按原文校验（仅统一 Windows 换行）。若存在其他草稿则停止；相同完整草稿可在发送前技术故障恢复时复用。不会把隐藏 `AB_JSHiddenInput` 的值当作可见草稿。

发送前核对同店铺接待中心、当前会话身份、已加载记录中的明确拒收表达与重复消息。发送按钮优先使用实时 UIA 和新截图；Qt 未暴露发送文字时，以聊天区域和窗口实时范围约束蓝色按钮候选，再识别“发送”文字。此回退需要本机 Tesseract 的 `chi_sim` 模型；模型目录使用标准环境变量 `TESSDATA_PREFIX`，不会自动下载或替换系统配置。本轮本地模型来源为 `tesseract-ocr/tessdata_fast` 官方仓库。

点击前先在 SQLite 保存 `send_attempts=1` 和占用时间；本次任务的发送操作不能再次占用。点击后仅核对完整消息唯一回显、原始链接、Offer ID 与失败提示，任何点击后错误/超时均标记 `unknown` 并停止，不自动重发。已完成单客任务不进入下一位。
